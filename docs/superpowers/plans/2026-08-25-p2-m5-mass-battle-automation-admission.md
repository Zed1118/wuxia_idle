# Phase 2 M5 守城自动准入结果合同

- 单一目标：守城已首通关通过 typed request 进入真实 bot/headless/差遣 runner，保留阵型、实际参与者与共享结算。
- 固定验收门：`0/1 → 1/1`；typed admission、生产 runner、阵型输入与 settlement 必须同链成立。
- 重资格化基线：塔门证明既有 `Phase0aSweepHeadlessRunner` 可扩展模式专用 application 方法并复用同一内核；`Phase0aStageContentMapper.mapMassBattle` 已接 production 阵型输入，因此即时 headless 技术路径可行。
- 当前关键阻塞：固定分母同时要求前台 bot、快速 headless 与差遣。守城没有玩家可达自动入口，也没有 durable run/session；既有共享占用只覆盖闭关、百草岭和断魂庄，无法在不改 schema/共享真相源时表示守城差遣、锁装、阵型快照、离线推进和返程报告。
- 成本：90 分钟停止线；只读 owner 审计与守城域回归。
- 非目标：schema/saveVersion、YAML、TUNING、奖励、经济、解锁、叙事、战斗规则或 main。

## 结果

- 验收门保持 `0/1 BLOCKED`；只实现即时 headless 或 policy 不能关闭固定门，故不留下部分生产代码。
- 守城域 `13/13 PASS`，只证明现有进度、阵型、逐次选人与手动 stage seam 未回归。
- 解阻授权：需要指定并授权守城差遣的 durable owner（含阵型快照）及 schema/saveVersion/共享 occupancy 扩展，或明确取消本门差遣分母。
