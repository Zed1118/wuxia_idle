## 3. P0：实施前必须闭合的设计问题

### 3.1 强化 +10 底线与实际可达下限矛盾

当前规则同时声明：

- 只有冲击 +20～+49 时，未保护失败才掉级。
- +20～+29 一次随机掉 1～2 级。
- +10 是唯一永久底线，可以跨阶段连续下降。

按现有算法，装备从 +19 冲击 +20 失败后最低到 +17；此后冲击 +18／+19 失败不再掉级。因此真实可达下限是 +17，`+10 floor` 在合法状态流中不可达。

Claude 必须：

1. 写出完整状态演算，确认上述结论。
2. 在正式装备规格中选择并明确一种自洽语义：
   - 保持“冲击 +20 起才掉级”，将实际恢复底线订正为 +17；或
   - 为“曾进入高风险段”的装备增加可持久化状态，并完整设计其在 +11～+19 的失败掉级与结晶保护规则，使 +10 真正可达。
3. 不得用不可能的 `currentLevel/targetLevel` 组合编写测试来伪造 +10 floor 覆盖。
4. 如果选择新增持久化状态，必须并入 0.37 schema／迁移计划，旧档默认值从当前强化等级安全推导。

这是玩法数值决策，不允许只在代码中偷偷修正。

### 3.2 断魂庄补给的托管语义

原规格要求“实际使用时才扣库存，未使用不消耗”，但挑战期间普通背包、战后治疗等入口仍可能消费同一库存，造成已装载补给消失或重复使用。

推荐采用会话托管：

1. 入场事务将最多三份补给从普通库存移入 `BossGauntletRun` 托管栏。
2. 整备页使用时只减少托管数量，不再次扣普通库存。
3. 胜利、失败、认输和安全恢复关闭会话时，未使用数量原子返还。
4. 崩溃恢复以会话托管数为准，不复制、不丢失。
5. UI 文案区分“装入行囊”与“已经消耗”，维持“未使用不消耗”的玩家语义。

如果 Claude 选择库存预留而非托管，必须证明所有现有消费入口都会扣除 reserved quantity，且成本低于托管方案。

### 3.3 缺少永久玩法进度

两个 active run collection 无法独立承载以下永久信息：

- 任一角色首次达到 Lv100 后永久解锁江湖远行。
- 百草岭历史最深节点和稳定的远征序号。
- 断魂庄是否首通、首通时间和首次奖励防重。
- 问鼎江湖第 10／20／30 层断魂帖旧档补发防重。

推荐新增小型单例进度 collection，例如 `JianghuJourneyProgress`，而不是复用语义为装备 defId 的 `SaveData.grantedMilestoneEquipmentIds`。最低字段应覆盖 unlock、max depth、run serial、cleared gauntlet ids／time 和 granted ticket milestones。

Claude 需对比“新增单例 collection”与“继续给 SaveData 加字段”的迁移成本，选择更符合现有项目模式的一种，并把唯一真相源写清楚。

### 3.4 Boss 最终奖励三选一的崩溃恢复

最终 Boss 胜利与玩家从三件命名装备中选择一件不是同一个同步动作。若胜利后、选择前关闭游戏，当前规格没有可恢复状态。

必须增加等价于 `awaitingRewardChoice` 的会话阶段：

1. Boss 胜利先原子固化胜利、奖励候选、首通判定快照和待结算状态。
2. 重启后强制恢复奖励选择页，不能再次战斗或重抽候选。
3. 玩家选择后一次性发装备、经验、领悟点、秘籍与典故，并关闭会话。
4. 重复点击或窗口重入只能成功一次。
5. 如果非装备奖励先发，必须提供独立幂等账；推荐全部在选择完成时统一结算，降低状态数量。

### 3.5 活动占用不能只锁角色

百草岭与断魂庄会冻结角色、装备、心法和技能装配。只提供 `CharacterOccupancyService` 不足以阻止：

- 把会话中的装备换下、出售、分解、助炼、强化或开锋。
- 修改会话角色的心法／技能装配。
- 把同一装备或心法分配给其他角色。

Claude 应设计统一的活动保留上下文，至少能查询：

```text
occupiedCharacterIds
reservedEquipmentIds
reservedTechniqueIds
activityKind / runId
```

可以扩展 `CharacterOccupancyService` 的返回 DTO，也可以增加薄的 `ActivityReservationService`；不得让装备、心法和各战斗入口分别查询两套 session collection。

装备实施计划中的助炼资格、批量处置、强化目标校验和开锋服务应接收通用 `reservedEquipmentIds`，不能只检查当前装备槽和当前出战编成。

### 3.6 断魂庄命名装备与保护／助炼的冲突

如果所有 `obtainedFrom == 断魂庄` 的装备都按“特殊来源”永久保护，重复通关获得的命名装备将不能助炼或分解，两个系统无法形成预期联动。

推荐规则：

- 普通重复通关获得的未培养命名装备允许助炼、单件分解和批量整理。
- 默认“同 `defId` 至少保留一件”继续保护收藏底线。
- 带“断魂庄首破”个人典故、已经培养、正在装备、活动保留或玩家手动锁定的实例继续保护。
- 不要仅凭通用断魂庄来源标签保护全部重复件。

Claude 必须把该规则同时并入奖励发放、装备保护策略、助炼资格和批量处置测试。

## 4. P1：必须进入正式实施计划的配套任务

### 4.1 百草岭／断魂庄分阶段实施计划

当前 Phase A／B／C 仍是规格级切片，不能直接作为长任务执行清单。建议至少拆成以下可独立恢复的计划：

1. **Phase A1：** 永久进度、schema 0.37、迁移、活动占用／资产保留。
2. **Phase A2：** 发布上限 10→17、存量溢出探针、断魂帖、补给托管、配置加载与校验。
3. **Phase B1：** 百草岭纯规则、稳定随机、节点生成、奖励与 headless 战斗结算。
4. **Phase B2：** 百草岭持久化、分批离线结算、召回／战败事务、总览／行记 UI。
5. **Phase C1：** 断魂庄三关控制器、敌方真气扣减、关次边界战斗快照。
6. **Phase C2：** 整备页、补给托管、恢复、待选奖励、首通／失败结算与 UI。

每份计划必须使用 TDD 小步骤、明确文件路径、验证命令和小提交恢复点。Phase B/C 是否并行，只能在 Phase A 冻结共享 DTO 和服务接口后决定。

### 4.2 跨战状态白名单

三关之间建议只继承：

- 当前生命
- 当前真气
- 阵亡状态
- 技能冷却

行动条、临时 Buff、Debuff、控制、护盾、召唤物、临时目标和敌方状态全部清除。持久伤势仍属于角色外部状态，不由关次快照重复写入。

需要领域测试覆盖每一类“保留／清除”，不能依赖序列化整个 `BattleState`。

### 4.3 稳定随机协议

- 会话创建时生成并持久化稳定 seed。
- 节点／关次 seed 使用明确的稳定哈希或整数混合算法派生。
- 禁止使用可能受运行时影响的普通对象 `hashCode` 作为跨重启协议。
- 相同会话、节点／关次和检查点必须在重启后得到相同行为。
- 存档恢复、同槽删除重建和多存档不得串 seed。

### 4.4 百草岭长离线性能与幂等

禁止在一个超长 `writeTxn` 内模拟数十个节点和多场战斗。正式计划必须明确：

1. 从会话快照纯计算下一批节点。
2. 单批节点／战斗数量上限由配置或经过论证的常量边界控制。
3. 事务内校验 settlement cursor 未变化后再提交批结果。
4. 未消费的 elapsed time 留在会话中，下一批继续。
5. 每批提交后允许 UI 让出一帧并展示结算进度。
6. 崩溃重入不会重复发奖或重复伤势。

### 4.5 联合经济与时间吞吐探针

现有 Lv100→170 吞吐探针必须扩展为跨系统模型：

```text
百草岭每小时节点／断魂帖
→ 断魂庄入场频率与三档阵容胜率
→ 命名装备选择
→ 助炼或分解的机会成本
→ 心血结晶净流入／保护消耗
→ +30／+40／+49 的预期到达时间
```

至少输出快／中／慢三套 YAML 候选，并建立 ratchet 范围；不能只验证单次成功率公式正确。

重点检查：

- 固定选择同一命名装备是否成为压倒性的 +25 个百分点助炼来源。
- 重复装备分解产生的心血结晶是否形成无限或过快的自反馈。
- 助炼、分解和收藏是否存在真实取舍。
- 补给生产速度与断魂庄消耗是否造成强制等待。

### 4.6 道具来源、用途与资源总览

新内容实施时同步：

- 断魂帖在资源总览中的库存、来源和用途。
- 疗伤丹／行囊补给新增“断魂庄整备”用途。
- 药草、灵泉水、补给和命名装备的新增来源反查。
- 装备详情／图鉴显示断魂庄命名装备来源。
- 不新增每日刷新、过期时间或催上线提示。

### 4.7 存档、备份和恢复兼容

0.37 迁移与新增 collection／字段必须覆盖：

### 4.8 内容与视觉资产清单

## 5. 联合验收矩阵

Claude 应在修订后的计划中至少覆盖以下跨系统场景：

1. 角色远征中可从出战编成换下、不可换上；祖师仍可 solo 出战。
2. 远征／断魂庄保留的装备不能换装、强化、开锋、出售、分解或助炼。
3. 活动结束后角色、装备和心法占用全部释放。
4. 断魂庄补给装入、使用、返还、失败、认输和崩溃恢复数量守恒。
5. Boss 胜利后关闭游戏，重进仍停在同一奖励三选一且只能领取一次。
6. 重复命名装备可助炼／分解，首破典故装备受保护。
7. 百草岭在线分段与离线批处理得到相同节点、奖励、战斗和伤势。
8. 同一关重打随机一致，不能靠重启刷新敌方行为。
9. 旧档升级后永久解锁、最深记录、首通和里程碑补发均不重复。
10. 联合经济探针显示 Lv100→170、断魂帖、补给和 +49 强化没有无限收益或强制日课。
