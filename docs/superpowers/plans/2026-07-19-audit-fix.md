### 根因与修法判定

1. **前向版本降写**：`IsarSetup._ensureSaveData` 仅判不等，导致 `0.99.0`
   同样进入 `_migrateSaveData`；尾部无条件把 `saveVersion` 写成 `0.37.0`。
   修法是在唯一入口使用既有 `_compareVersion`：高于当前时抛专用异常，禁止进入
   migration transaction；`init` 捕获后关闭刚打开的实例并清空全局句柄，避免 caller
   捕获异常后误用。`listSlots/_readSummary` 同样拒绝未来版本，使存档选择屏既有
   `AsyncValue.error → ErrorFallback` 明确呈现失败。
2. **schema 打开前备份评估**：现有 `SaveManagementService.createBackup` 依赖已打开的
   `Isar` 与当前 `SaveData`，`SaveRestoreDatabaseOps` 也只负责候选校验/关闭，无法在
   未打开 schema 时读取版本；直接复用会形成循环。若要严格“识别未来版本前绝不
   打开原库”，只能为所有既有档先做 raw file preflight 副本，或新增外置版本 manifest，
   均超出本单点修并需恢复/清理 spec。目标 2 采用应用层零写 fail-closed；不自行扩架构。
3. **心跳旧对象回写**：`touchOnlineNow` 在事务外读完整 `SaveData`，等待事务期间其他
   写入可被 stale `put` 覆盖。修法：事务开始后重读，仅改 `lastOnlineAt` 再 put。
4. **主菜单四任务竞态**：并发本身是既有首帧行为；实际跨 collection 冲突点是
   `unlockJianghuJourneyOnOpen` 在事务外读旧 `SaveData` 后完整 put，可能覆盖离线结算
   刚写的累计字段。为避免串行 await 离线 recap dialog 改变启动体验，只把远行解锁
   改为 transaction 内重读并最小改 `jianghuJourneyUnlocked`；Isar 写事务串行化消除窗口，
   `main_menu_startup_gate.dart` 保持四任务对外时序不变并补安全注释。
5. **周目跨槽残留**：`SelectedChallengeCycle` 的 keepAlive family 仅以 chapterKey
   为 key，切槽 invalidate `isarProvider` 不会清它。修法将 family key 扩为
   `(slotId, chapterKey)`，生产 wrapper 统一绑定 `IsarSetup.currentSlotId`；导航往返仍
   keepAlive，同章不同槽天然隔离，不改战斗语义。
