# 批二图层稳定实施计划

## 结果合同

- 单一目标:角色纵向交叉时按实际渲染脚底坐标排序，同时用滞回带消除边界附近的来回翻层。
- 固定验收门:批二三门中的第 3 门；技能特效、破势反馈已关闭，本门完成后批二达到 3/3。
- 实时基线:`c2782c44`，工作分支 `codex/p2-b2-layer-hysteresis-20260827`。
- 当前阻塞:现有排序已与插值后的 render-y 同源，但每次越过零差值就立即换序，横向缠斗时会抖动。
- 预期增量:批二受控链从 2/3 提升到 3/3；不代表整个二阶段完成或已进入 main。
- 成本上限:只改表现层排序状态、表现 token 和对应 widget 测试；不改领域坐标、阵营规则、美术资产或禁区文件。

## 实施约束

1. 每处修改前按符号重新定位，不照抄交接单行号。
2. 排序输入必须是 `_actorRenderPosition` 经 `worldToScreen` 得到的实际脚底 y。
3. 使用 10px 对称滞回带:既有前后关系在脚底差未越过阈值时保持；两个方向越过阈值后都必须翻转。
4. 新增角色按当前脚底 y 与 id 确定初始顺序；移除角色不得残留排序状态。
5. controller 替换或战斗 tick 回退时清空历史顺序，避免新一局继承旧层级。
6. 不采用“玩家恒在最上层”或任何阵营偏置。

## 验证

1. widget 测试读取真实战斗 `Stack.children` 顺序和角色实际脚底位置。
2. 正向越过少量时顺序不变，超过 10px 后翻转；反向越过少量时仍保持，超过 10px 后翻回。
3. 做一次破坏证红:临时将滞回阈值短路为 0，新断言必须失败；恢复后全绿。
4. 跑相关表现层回归与 `flutter analyze --no-pub lib test`。
5. 检查禁区文件无 diff、工作区 clean，并以 `[READY]` tip 收口。
