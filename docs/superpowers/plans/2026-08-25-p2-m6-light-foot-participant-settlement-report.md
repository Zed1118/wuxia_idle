# P2-M6 轻功试炼实际参与者结算报告闭环计划

## 结果门与基线

- 固定验收门：轻功试炼“主菜单 → 江湖地图 → 地点详情 → 逐次选择实际参与者 → Phase 0A 亲战 → 共享结算 → 胜负身份报告”从 `WIP 0/1` 变为 `PASS/READY 1/1`。
- 基线：`84199646978851297a9b3981335b48f6b9dfbc8e`，继承断魂庄亲战结算报告 clean READY。
- 最大阻塞：轻功列表仍直接启动默认掌门；地点详情仍把掌门写成唯一参与者；共享胜负结算仍可能用旧 `activeCharacterIds` 过滤掉本次选中的当代门人。

## 完成定义

1. 候选只来自当前掌门与当代存活门人，并读取统一 `CharacterOccupancyService`；占用、疗养、死亡、无主修、悬空身份、重复占用和 provider 异常 fail closed。
2. 每次点击可挑战路线都重新选人，并在进入真实 `Phase0aMainlineBattleHost` 前复核及装配 exact snapshot；绝不回退掌门。
3. 胜负共享结算只接受该 exact participant，经验、伤势、装备战斗次数和心法使用归属实际参与者；错人或悬空资源不写入。
4. 既有胜利与失败报告明确显示实际参与者身份，不新增强制剧情文本。
5. 生产路由、两视口、定向与相邻域、scoped/root analyze、白名单、一次必要全量和 clean 状态通过。

## 非目标与成本上限

- 不做守城试炼、派遣/自动/headless 解锁，不重设计重试与失败政策。
- 不新增 reducer/session/事件/结算真相源，不改 schema/saveVersion、YAML、数值、奖励、经济、解锁、叙事或 main。
- 硬上限 90 分钟；22.5/45/72 分钟检查 gate 增量。周用量不可直接观测，不伪造百分比。
