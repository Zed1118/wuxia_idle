# 境界派生 490 级设计

> 日期：2026-07-13  
> 状态：用户已确认设计方向，进入书面规格复核  
> 所属批次：系统语义清理第一批（等级与经验统一）

## 1. 目标

把现有“境界经验”和“角色 Lv 经验”两套并行成长账统一为一套：

- 唯一真实经验为 `Character.experience`。
- 唯一真实层内经验门槛为 `Character.experienceToNextLayer`：非终局用于突破，终局用于登峰修为刻度。
- 玩家继续看到直观的数字等级和经验数字。
- 数字等级范围为 `Lv1～Lv490`，由 49 个境界层及当前层经验实时派生。
- 数字等级不再单独增加属性，不改变境界、装备阶、心法阶三系锁死。
- 旧存档中的 `level` / `levelExp` 字段保留用于 Isar schema 兼容，但退出生产读写路径。

本批不调整既有经验产量、前 48 次境界突破门槛、心魔门槛和战斗平衡。唯一新增数值是武圣·登峰的终局修为刻度，用来保证 Lv481～Lv490 连续可达；它不产生新境界或属性。

## 2. 核心模型

### 2.1 49 个境界层

现有 `RealmDef.absoluteLevel` 已把七个大境界、每境七个小层映射为 `1～49`。它继续作为境界层的单一真相源。

每个境界层在展示上细分为 10 个修为等级：

| 境界绝对层 | 展示等级区间 |
|---:|---:|
| 1 | Lv1～Lv10 |
| 2 | Lv11～Lv20 |
| … | … |
| 49 | Lv481～Lv490 |

### 2.2 展示等级公式

层内经验门槛 `experienceToNextLayer > 0` 时（包括武圣·登峰的终局刻度）：

```text
progressSegment = floor(experience × 10 / experienceToNextLayer)
progressSegment = clamp(progressSegment, 0, 9)
displayLevel = (absoluteLevel - 1) × 10 + progressSegment + 1
```

结果保证：

- 刚进入某个境界层时显示该区间第 1 级。
- 当前层经验接近满值时显示该区间第 10 级。
- 突破到下一境界层并扣除门槛经验后，等级从上一段第 10 级自然进入下一段第 1 级。
- 一次获得大量经验、连续跨越多个境界层时，最终等级直接按结算后的境界和余留经验派生。

`武圣·登峰` 继续使用同一公式，从 Lv481 随经验推进到 Lv490。其 `experienceToNextLayer` 从历史哨兵 `0` 改为终局修为刻度 `1,250,000`；达到或超过该值时显示 Lv490，但 `CharacterAdvancementService.nextLayer` 返回空，不会产生第 50 个境界层，也不会扣除这笔经验。

### 2.3 心魔锁表现

心魔锁会允许经验超过当前门槛但阻止境界突破。此时：

- 展示等级封在当前十级区间的第 10 级。
- 经验数字保留真实溢出值，不截断、不丢失。
- 进度条视觉值封顶为 100%。
- 状态文案显示“经验已满 · 待破心魔”。

例如当前层区间为 `Lv411～Lv420`、经验为 `1800 / 1200`，界面显示：

```text
Lv420 · 经验 1800 / 1200 · 待破心魔
```

## 3. 玩家界面

### 3.1 角色面板

原独立 Lv 卡改为统一修为卡，展示：

```text
修为等级  Lv187
二流·圆熟
经验 650 / 1200
```

境界名称、数字等级和经验进度位于同一信息块，不再出现两个互相竞争的经验条。

### 3.2 结算反馈

主线、爬塔、闭关、离线收益、扫荡和经验丹全部只调用境界经验推进服务。

结算前后分别通过纯派生函数计算展示等级：

- 数字等级变化但未跨境界层：显示 `修为等级 Lv186 → Lv187`。
- 跨越境界层：显示 `Lv190 → Lv191 · 境界精进至二流·精通`。
- 一次跨越多级：只显示起点与终点，不逐级弹出多个提示。
- 无等级变化：只展示获得的经验，不显示升级仪式。

### 3.3 满级表现

满级统一显示：

```text
Lv490 · 武圣·登峰
已臻巅峰
```

达到终局修为刻度后继续获得的经验可以保留在存档中，但不再生成数字等级变化。

## 4. 战力与解锁规则

数字等级是同一份修为进度的细分表达，不是第二套力量来源：

- 移除 `Character.level` 对最大生命、内力上限和速度的额外加成。
- 删除生产路径对 `LevelService.applyLevelExp` 的调用。
- 装备强化上限继续使用 `RealmDef.absoluteLevel`，保持最高 `+49`，不跟随展示 Lv490 放大。
- 装备阶、心法阶和玩法解锁继续只看真实境界。
- 经验丹只增加境界经验，不再复制写入另一经验账。

因此本批不会把强化上限误放大到 `+490`，也不会突破玩家血量、内力和装备数值红线。

## 5. 领域边界

新增一个无副作用的修为展示派生单元，职责只有：

- 根据 `RealmDef.absoluteLevel`、当前经验、层内经验门槛和满级状态计算 `displayLevel`。
- 计算当前层的展示进度。
- 判断普通、心魔封顶和最终满级三种展示状态。

该单元不写存档、不推进境界、不增加属性。经验推进仍由 `CharacterAdvancementService` 独占，避免新的双真相源。

## 6. 旧存档兼容

`Character.level` 和 `Character.levelExp` 暂不从 Isar collection 中删除，原因是直接删字段会扩大 schema 迁移风险。

兼容策略：

- 旧值不参与界面、结算、战力或解锁。
- 新版本不再更新这两个字段。
- 不把派生等级反写到旧字段，避免形成新的镜像漂移。
- 现有旧等级修复任务退出启动链；字段本身保留到未来统一 schema 清理批。

无论旧存档此前 `level` 是 1、49 或 100，升级后显示结果都只由真实境界和境界经验决定。

## 7. 配置清理

现有 `numbers.yaml level` 段服务于独立 Lv 曲线及每级属性加成。本批移除其生产消费，并删除对应配置和解析模型，避免留下另一套看似有效但实际休眠的等级配置。

境界经验需求继续来自 `numbers.yaml realms` / `RealmDef.experienceToNext`，不新增第二张经验曲线表。武圣·登峰的 `experience_to_next` 改为 `1,250,000`，语义为终局修为刻度而非“突破到下一层”；该值沿现有武圣后段 `870,000 → 1,040,000` 的增长节奏顺延。

“每个境界层拆 10 个展示等级”属于固定领域映射，不作为可调平衡数值；否则调整该值会改变整个 Lv1～Lv490 产品口径。

## 8. 测试策略

所有行为变化按 TDD 执行。

### 8.1 纯逻辑测试

覆盖：

- `absoluteLevel=1`、经验为 0 时是 Lv1。
- 当前层经验分别跨过 10%、50%、90% 时等级正确。
- 经验刚低于门槛时停在该区间第 10 级。
- 心魔锁导致经验等于或超过门槛时仍封在当前区间第 10 级。
- 突破后余留经验能得到下一段正确等级。
- `absoluteLevel=49` 从经验 0 的 Lv481 连续推进到经验满值的 Lv490。
- 武圣·登峰经验达到或超过 `1,250,000` 时固定 Lv490，且不会尝试进入不存在的第 50 层。
- 负经验或异常门槛使用防御性边界，不产生 Lv0 或 Lv491。

### 8.2 生产接线测试

覆盖主线、爬塔、闭关、离线收益和经验丹：

- 同一奖励只增加一次 `Character.experience`。
- 不再修改 `Character.level` / `levelExp`。
- 经验丹仍能触发境界连升和心魔锁。
- 战力派生不再读取旧 `level`。

### 8.3 界面测试

覆盖：

- 角色面板只出现一套修为等级和经验进度。
- 普通、心魔锁和 Lv490 三种状态文案。
- 常规桌面视口 1280×720、1440×900 无溢出。
- 升级反馈显示派生等级的起止值，且不会重复弹出旧 Lv 升级仪式。

## 9. 红线检查

- 数值硬红线：移除一套等级属性加成，只会降低派生战力，不会抬高极值。
- 三系锁死：继续使用境界，不使用 Lv490 作为装备或心法门槛。
- 在线等于离线：所有经验来源进入同一个推进服务，规则一致。
- 不硬编码数值：战斗平衡值仍在 YAML；固定的十级映射是产品等级制本身。
- 不硬编码中文：玩家文案继续归入 `UiStrings`。
- 反主流清单：不新增每日、体力、加速、奖励领取或焦虑提示。

## 10. 后续批次边界

用户已经确认继续处理排行榜、双声望、心法/招式成长、装备共鸣语义和祖师修炼加成。为遵守可恢复任务协议，这些独立子系统不混入本批代码：

1. 排行榜改为“问鼎战绩”。
2. 江湖声望改为“势力关系”，门派声望改为“门望”，并分别接入实际消费。
3. 心法修炼度与招式熟练度拆分收益职责。
4. `battleCount` 迁移为共鸣历练语义。
5. 祖师修炼度加成在修炼公式统一后接入。

每个后续批次单独设计、测试、提交和验收；第一批只建立统一、可信的等级与经验基础。
