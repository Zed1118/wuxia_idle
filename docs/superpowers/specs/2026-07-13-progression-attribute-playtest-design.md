# 成长路径与四属性体感体检设计

> 日期：2026-07-13  
> 状态：用户已确认设计，待实施计划  
> 范围：第一批只做诊断与真实 Bug 修复；数值调整另开第二批

## 1. 背景与目标

项目已完成两项成长底座收敛：

- 49 个真实境界层派生 Lv1～Lv490，`Character.experience` 成为唯一角色经验账；
- 根骨、悟性、身法、机缘四项属性职责重新统一，主线与通天塔也已复用公共成长结算。

现有测试已覆盖大量字段、入口和红线契约，但缺少从完整玩家路径观察这些规则是否连续、清楚、名副其实的统一诊断。第一批的目标不是继续堆功能或直接调数值，而是建立可复现的成长体检基线，修复被硬证据证明的 P0/P1 问题，并把主观或平衡类结论留给第二批单独决策。

## 2. 设计原则

1. **诊断先于调参**：没有跨配置、跨种子的复现证据，不改数值。
2. **真实生产入口**：测试直接调用生产服务和真实 YAML，不复制经验、属性或战斗公式。
3. **硬契约与软观察分离**：等级越界、双经验账等进入 CI；胜率、节奏等只形成绑定 commit 的观察报告。
4. **单变量对照**：属性诊断一次只改变一个属性，避免把装备、心法和境界差异误归因给属性。
5. **合法玩家样本**：所有配置继续遵守境界、装备阶、心法阶一一对应。
6. **最小修复**：第一批只改被硬契约证明错误的生产逻辑，不顺手扩大重构。

## 3. 范围

### 3.1 包含

- Lv1～Lv490 与 49 个境界层的完整连续性、心魔锁和终境封顶；
- 主线首通/重打、通天塔首通/重打、闭关、普通离线、经验丹七类经验入口；
- 根骨、悟性、身法、机缘在前中后期的单变量职责诊断；
- 主线、心魔和通天塔的固定种子成长路径汇总；
- P0/P1 真实 Bug 的最小修复、回归测试和 macOS 关键画面复验；
- 可复现的 Markdown 结论与 CSV 原始数据。

### 3.2 不包含

- Windows 构建、签名、安装包、升级安装或发布准备；
- `numbers.yaml` 平衡系数、敌人血攻、掉率、经验奖励或经济调整；
- 四属性收益倍率调整或职责扩展；
- 新玩法、新资源、新属性、大规模 UI 重设计；
- `docs/spec/rejected_task_registry.md` 中已否或暂缓方向；
- Isar schema 或 save version 变更。

## 4. 测试矩阵

### 4.1 成长阶段

| 阶段 | 代表内容 | 核心观察 |
|---|---|---|
| 前期 | Ch1～Ch2、低层塔 | 升级反馈、单人开荒、早期属性是否可感知 |
| 中期 | Ch3～Ch5、中层塔 | 三人队成长、属性分工、装备与心法差异 |
| 后期 | Ch6、心魔高层、塔 25～30 | Lv490 封顶、突破锁、终局机制与软门槛 |

### 4.2 队伍配置

- **标准配置**：符合当前境界的正常装备、心法和熟练度；
- **轻度欠配**：仍符合三系锁，只降低装备强化、熟练度或配置完整度；
- **接近满配**：当前境界内的高完成度配置，不使用越阶装备或心法。

诊断不做所有轴的笛卡尔积。主线使用三类配置，塔只抽取 5/10/15/20/25/30 层及其前驱层，心魔只重点复核 05/06/07；随机战斗沿用 20 个固定种子，确定性等级和经验测试不乘随机种子。

## 5. 诊断结构

### 5.1 共享场景夹具

新增 `test/support/progression_playtest_fixture.dart`，职责仅限：

- 从真实 `RealmDef` 创建前、中、后期角色；
- 构造标准、轻度欠配、接近满配队伍；
- 生成只提高一个属性的对照角色；
- 注入固定时间和固定随机种子；
- 校验装备、心法、技能和境界引用合法。

夹具不得计算经验、伤势、领悟、派生属性或战斗收益。所有结果必须由生产服务给出。

### 5.2 Lv490 与经验硬契约

新增：

- `test/features/cultivation/application/progression_full_path_contract_test.dart`
- `test/features/cultivation/application/experience_source_consistency_test.dart`

硬契约覆盖：

- 490 个展示等级严格单调，每个真实境界层映射 10 个展示等级；
- 升层不倒退、不重复，武圣登峰最终停在 Lv490；
- 继续增加经验不会产生 Lv491 或第 50 层；
- 心魔锁定时经验保留但真实境界不越过，解锁后溢出经验继续结算；
- 给旧兼容镜像写入错误值也不能改变生产计算；
- 七类经验入口最终只改变 `Character.experience`；
- 主线重打给经验，通天塔重打不给经验；
- 闭关与离线按真实结算时长处理，大额经验可连续升层；
- 重复结算幂等，事务失败不留下半条数据或事件。

主线和塔已有接线契约继续保留；新测试复用公共结算和真实持久化，不复制整套界面战斗流程。

### 5.3 四属性职责诊断

新增 `test/tools/attribute_role_sensitivity_diagnostic_test.dart`。在前、中、后三个阶段分别生成基准角色及四种单属性对照角色，调用真实生产入口：

- 根骨：新产生重伤的持续时间应单调缩短，但不替代疗伤系统；
- 悟性：心法修炼、招式熟练度、武学领悟均朝有利方向变化；
- 身法：行动相关收益生效，暴击率不能因身法重新变化；
- 机缘：普通奇遇概率和显式门槛生效，战斗伤害、装备掉率等非职责内容不得变化。

第一批只判断方向、接线和职责越界，不规定“每点必须提升多少”。效果存在但可能偏弱的情况归入 P2，不修改倍率。

### 5.4 成长路径汇总诊断

新增 `test/tools/progression_playtest_diagnostic_test.dart`，复用现有平衡模拟器、首通节奏、心魔和塔 Boss 诊断，不创建第二套战斗引擎。

统一记录：

- 场景 ID、成长阶段、队伍类型、随机种子；
- 胜负、战斗节拍、玩家结束剩余生命；
- 真气平均状态、溢出或枯竭情况；
- 普攻、招式、机制伤害占比；
- 心魔、护法结界、脆弱窗口等机制是否触发；
- 经验收益、最终境界和最终展示等级。

明确失衡候选必须同时满足：固定种子可复现、不止一个配置同向异常、不是单个临界种子翻盘、相对相邻内容形成明显断崖，并且不是既有设计明确要求的欠配惩罚。

## 6. 数据流与输出

```text
真实 YAML / GameRepository
            ↓
合法角色与队伍测试夹具
            ↓
经验、闭关、离线、伤势、领悟、战斗生产服务
            ↓
固定时钟与固定种子执行
            ↓
硬契约断言 + 软指标采集
            ↓
Markdown 结论 + CSV 原始数据
```

输出文件：

- `docs/audit/progression_attribute_playtest_2026-07-13.md`
- `test/tools/output/progression_attribute_playtest_2026-07-13.csv`

报告必须记录 Git commit、Flutter 版本、种子范围、数据版本、执行时间和是否修改生产代码。精确胜率或胜场观察值必须绑定 commit，不能脱离版本当作永久断言引用。

## 7. 硬断言与软观察

### 7.1 进入常规全量测试的硬契约

- Lv490 与 49 层连续性和封顶；
- 唯一经验账；
- 心魔锁不可绕过；
- 属性职责接线和非职责隔离；
- 三系锁合法；
- 重复结算幂等；
- 事务回滚不留部分数据。

### 7.2 只进入报告的软观察

- 单关胜率和平均战斗节拍；
- 满配、标准和欠配的差距；
- 属性收益幅度；
- 各经验来源的相对效率；
- 单个临界种子的胜负变化。

软观察只锁既有设计红线或语义区间，不新增“必须 17/20”一类精确永久断言。

## 8. 错误分类与处理

### 8.1 诊断执行错误

1. **样本非法**：装备越阶、心法缺失或角色配置不完整时直接失败，不输出平衡结论；
2. **执行异常**：战斗未结束、事务报错或数据加载失败时直接失败，报告场景 ID 和种子；
3. **结果异常**：流程正常但疑似失衡时继续完成诊断，归入 P2 候选。

### 8.2 产品问题等级

| 等级 | 定义 | 第一批处理 |
|---|---|---|
| P0 | 重复经验、绕过心魔、超过 Lv490、存档损坏 | 必须修复并补回归测试 |
| P1 | 属性接错、显示与落库不一致、确定性规则错误 | 必须修复并补回归测试 |
| P2 | 属性偏弱、关卡偏难、某经验来源存在感不足 | 只记录，进入第二批候选 |
| 观察项 | 单个临界种子或纯主观手感 | 保留原始数据，不建立修复任务 |

每个 P0/P1 必须说明玩家表现、根因、为何属于 Bug、最小修改、不修影响和防复发测试。允许第一批在没有 P0/P1 时以零生产代码修改结束。

## 9. 执行顺序

1. 冻结当前 `main` 基线，运行现有 Lv490、经验、主线、心魔、塔、闭关、全量测试和构建；
2. 建立合法玩家模板并验证确定性；
3. 用 TDD 建立 Lv490、心魔锁和经验来源硬契约；
4. 依次完成根骨、悟性、身法、机缘职责诊断；
5. 运行受控规模的玩家成长路径诊断；
6. 先形成问题表，再逐项修复 P0/P1；
7. 重跑专项、全量、format、analyze 和 macOS Debug 构建；
8. 复验前期档案、心魔锁、战后反馈、Lv490 档案四个关键画面；
9. 生成 Markdown/CSV 证据并更新 `PROGRESS.md`。

## 10. 强制停止条件

遇到以下任一情况，第一批停止扩张并请求用户决策：

- 需要修改 `numbers.yaml`、属性倍率、敌人、经验、掉率或经济；
- 需要修改 Isar schema 或 save version；
- 需要新增玩法、大幅 UI 重设计或改变三个以上系统规则；
- 结论依赖主观手感，自动证据无法判定；
- 结果只在单个临界种子出现。

停止项进入第二批设计，不在第一批自行处理。

## 11. 真机复验

macOS Debug 复验四个关键画面：

- 前期角色档案：等级、境界和四属性；
- 心魔锁定状态：经验溢出与等待突破说明；
- 战后结算：经验、Lv 变化和真实境界突破反馈；
- Lv490 角色档案：封顶文案且无虚假进度条。

沿用 1280×720 和 1440×900 两个桌面视口，只检查信息直观性、溢出和异常，不在第一批重设计 UI。

## 12. 验收标准

- 490 级与 49 层映射全路径通过；
- 七类经验入口没有第二经验账，心魔锁不可绕过；
- 四属性职责方向正确且无越界接线；
- 所有 P0/P1 已修复并有回归测试；
- P2 只形成候选，没有隐式调数值；
- 诊断报告可通过 commit、时钟和种子复现；
- format、analyze、定向测试、全量测试和 macOS Debug 构建通过；
- 四个关键画面双视口无异常；
- 工作区干净，报告只引用本轮真实执行数字。
