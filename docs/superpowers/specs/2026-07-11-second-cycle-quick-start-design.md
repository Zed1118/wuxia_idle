# 二周目快速开局设计

## 目标

让已经完成过首轮江湖的玩家在新建其他存档时，可选择跳过第一章的菜单引导限制，直接使用心法与闭关等基础功能；主线、奖励、角色塑形和数值成长仍从头开始。

## 玩家流程

1. 任一现存存档已完成首周目 `stage_06_05`。
2. 玩家在空槽新开江湖，空槽会提示“可选老江湖开局”。
3. 祖师创建页新增“循序入门 / 老江湖开局”分段选择，默认仍为“循序入门”。
4. 选择“老江湖开局”后，完成祖师塑形并进入主菜单；心法与闭关不再受第一章教程步数限制。
5. 主线仍从 `stage_01_01` 开始，不补关卡、不补奖励、不提高资源。

## 资格判定

- 在 `SlotSummary` 增加只读派生值 `completedFirstCycle`，不增加 Isar schema 字段。
- 优先检查 `MainlineProgress.clearedStageCycleKeys` 是否包含 `stage_06_05#1`。
- 兼容旧档：若 `clearedStageIds` 包含 `stage_06_05`，同样视为完成首周目。
- 存档选择页只要发现任一非空槽完成首周目，就给空槽开放快速模式。
- 删除所有满足条件的存档后资格随之消失。这一策略保守、可解释，也避免另建跨档全局存储。

## 持久化语义

- 复用既有 `SaveData.isOnboardingCompleted`，不升级 save version。
- “老江湖开局”创建时写入：
  - `isOnboardingCompleted = true`
  - `tutorialStep >= 5`
  - `tutorialHintsRead` 合并 `3` 与 `5`，避免出现已经失效的心法/闭关解锁提示。
- “循序入门”保持现有默认值。
- 正常玩家通关 `stage_01_05` 时同步写入 `isOnboardingCompleted = true`，让字段语义完整闭环。
- 不预读步骤 6/7/8：收徒、奇遇、开锋仍应在真实业务节点给出上下文提示。

## UI 约束

- 模式选择仅在符合资格的新档出现，默认选中“循序入门”。
- 使用分段控件和图标表达互斥选择，不新增教程弹窗。
- 文案明确快速模式只开放基础入口，主线和奖励仍从头开始。
- 视觉验收覆盖 `1280x720` 与 `1440x900`，检查创建页无溢出、遮挡和文本截断。

## 未采用方案

1. **SharedPreferences 全局解锁**：会引入存档目录之外的第二真相源，备份/迁移行为不清晰。
2. **快速模式直接通关第一章**：会跳过剧情、首通奖励和早期成长反馈，破坏买断制单机体验。
3. **新增 `tutorialSkipped` 字段**：既有 `isOnboardingCompleted` 已具备等价语义，新增 schema 只会增加迁移成本。

## 验收标准

- 未完成首周目的存档组合不显示快速开局。
- 任一槽完成首周目后，所有空槽显示快速开局提示。
- 快速模式写入正确引导状态，且不改变初始资源和主线进度。
- 循序模式行为与当前版本一致。
- 第一章正常通关会标记引导完成。
- 定向测试、静态分析、全量测试、macOS 构建和双视口视觉验收全部通过。
