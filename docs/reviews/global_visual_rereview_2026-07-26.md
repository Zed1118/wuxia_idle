## 1. 结论

第二阶段已完成原计划中的代码侧与可独立产出素材侧任务。macOS 可验证范围内，没有发现新的 P0/P1 视觉硬伤，也没有发现布局重排、信息层级丢失或风格转向。

本阶段的主要价值不是“换一套设计”，而是把上一轮仍显松散的四个连接点收紧：

1. 战斗人物与地面、状态牌与人物之间的归属关系更清楚；
2. 远征、断魂庄、门派谱等长尾深色页面开始共用同一套水墨档案语言；
3. 三件断魂庄装备不再重复使用普通图标充当详情图，并建立了详情资产不倒退门禁；
4. 离群场景和生产肖像有了用途级安全裁切，避免主体被桌面视口截断。

综合评分由上一阶段实施后复评的 **8.4 / 10** 提升至 **8.6 / 10**。距离 9 分的主要差距已不再是已知 macOS 页面硬伤，而是正式字体、候选角色透明站姿、Windows 实机缩放，以及一批历史资产与低风险视觉 token 债务。

## 3. 本阶段已闭环

### 3.1 战斗人物落地与状态归属

- 脚底墨影增加实心接触核与克制扩散，人物不再像浮在背景图上；
- 状态墨拓增加小型归属指针，仍沿用原状态牌位置和尺寸；
- 暴击反馈从页面硬编码色迁入战斗语义 token；
- 高、中风险美术色调问题升级为自动测试硬门禁。

复查判断：塔层、断崖场景的角色位置、阵位、底部 HUD 和操作区域均未移动；增强发生在视觉层，不构成 HUD 重设计。

### 3.2 长尾页面共享水墨语言

- 新增 `InkPageHeader`、`InkSectionLabel`、`InkListCard`；
- 远征总览、断魂庄装载、门派谱/人物纪事接入统一标题、分区、身份题头和选择态；
- 原最大宽度、卡片排列、滚动方式、顶部动作入口和内容顺序保持不变。

复查判断：原先最明显的“核心页像成品、长尾页像工具面板”落差已缩小。其余档案类页面不应为了统一而强制迁移；只有出现真实层级漂移时才接入共享组件。

### 3.3 装备详情资产与门禁

- 锁脉囊、镇岳铁衣、摄魂铃补齐独立详情构图；
- 三张图保留原装备身份和水墨材质，具备透明安全边、深浅底可见性和主体占比；
- 新增 1024 方图、透明角、主体占比、明暗层次、色键残边、精确重复和感知近似检测；
- 29 组历史感知近似图进入显式“只减不增”清单，新提交不能扩大债务。

复查判断：本阶段修复的三组精确重复已经清零。29 组历史近似图仍是资产债务，不是门禁误报，也不能因为已登记就视为完成。

### 3.4 场景与肖像安全裁切

- 四张尺寸/比例离群场景登记焦点与 0–1 安全区；
- 战斗背景和门派厅堂生产组件消费焦点；
- 十二张生产纵向肖像默认优先保留脸部和上半身；
- 调用方仍可覆盖焦点，透明战斗站姿和未登记素材继续居中。

复查判断：修复没有改变容器尺寸或页面排版，只改变图片在原容器中的取景方式。断崖瀑布、门派厅堂和成员肖像的主体完整性明显提高。

### 3.5 终验门禁修正

- 深色 `InkPageHeader` 的宣纸文字审计误报以精确、相邻注释登记，没有放宽全局规则；
- 调试装备 gallery 的 Material `redAccent` 回退改为项目危险色 token；
- 当前美术色调审计为 high 0、medium 0、low 230。

## 4. 仍需推进的视觉任务

### P1：发布前必须完成，但依赖外部输入或目标设备

#### P1-01 正式跨平台中文字体

**现状**

- 当前字形气质仍依赖系统字体，macOS 与 Windows 的字宽、字重和标点位置可能不同；
- 直接引入字体会涉及授权、包体和商业发布许可，不能由代码侧擅自拍板。

**执行**

1. 确认字体授权、是否可随游戏分发、包体预算和可用字重；
2. 先在独立视觉 route 对标题、正文、数字、长人名和中英文混排做 A/B；
3. 跑最长字符串、1280×720、1440×900 和 Windows 三档缩放；
4. 通过后再接入全局 typography token，不逐页散改 `fontFamily`。

**完成标准**

- macOS/Windows 字形一致性可接受；
- 无新增截断、换行抖动和按钮宽度漂移；
- 字体许可证与来源进入发布文档。

#### P1-02 九名候选角色透明战斗站姿

**现状**

- 当前纯墨身份剪影是安全降级，避免把普通肖像强塞进战场；
- 它能保证正式感不崩，但不能替代最终角色美术。

**执行**

1. 为三名招募候选、六名门派候选建立统一站姿规格；
2. 固定朝向、脚底基线、透明边、光源、透视和人物尺度；
3. 每名角色同时验收浅雾、深山、暖色厅堂三类背景；
4. 替换后删除对应 fallback 允许项，不保留永久双轨。

**完成标准**

- 正式战斗 route 的候选角色 fallback 计数为 0；
- 同帧敌我不出现无法解释的同脸、同向和同尺度错觉；
- 角色脚底、血条和状态牌归属稳定。

#### P1-03 Windows 实机三档缩放

**执行**

- 在真实 Windows 目标机验证 100%、125%、150%；
- 覆盖启动/存档/设置、主菜单、章节、战斗、仓库/详情、远征、断魂庄、门派谱；
- 重点检查字体宽度、鼠标 hover/focus、滚轮、窗口边缘、图片解码和 GPU 合成。

**完成标准**

- 三档缩放无 overflow、裁切、不可达操作或焦点丢失；
- 发现的问题有 route、视口、缩放、截图和复现步骤；
- Windows 结果进入发布验收记录，不能用 macOS 缩放模拟替代。

### P2：下一阶段可在独立工作树继续推进

#### P2-01 分批替换 29 组历史装备详情近似图

**建议顺序**

1. 神武、宝物、特殊装备：高价值、高曝光，先做 8 组；
2. 重器、利器：中后期常见，做 8 组；
3. 好家伙、襄阳：中期常见，做 7 组；
4. 寻常与剩余配饰：做 6 组。

每批都必须：

- 保留原装备身份，不重画成另一件武器或饰品；
- 使用独立详情构图，而不是把 icon 放大或加背景；
- 跑深/浅底 gallery、生产详情页和质量门禁；
- 每完成一组就从允许清单删除一项；
- 每批独立提交，确保中断可恢复。

**量化目标**：29 → 21 → 13 → 6 → 0。

#### P2-02 低风险颜色字面量语义化

**现状**

- high 0、medium 0，说明没有需要立即阻断发布的饱和 Material 漂移；
- 仍有 230 条 low 硬编码色，主要集中在战斗底栏、门派页、伤害反馈、章节/关卡和共享牌匾组件；
- 场景天空、山体、雾光等局部调色属于美术配方，不应被机械迁入全局 UI token。

**执行**

1. 先整理共享组件和高频 UI 状态色：文字、边框、选中、危险、成功、禁用；
2. 其次处理战斗 HUD 和章节/关卡的重复字面量；
3. 场景、特效、插画局部 palette 仅在跨文件重复且语义稳定时抽取；
4. 每批以截图像素差、双视口目检和色调审计共同验收。

**量化目标**

- 下一阶段把 low 230 降至 **150 以下**；
- high、medium 持续保持 0；
- 不以“数字下降”为由改变已经确认的画面色温。

#### P2-03 题字、印章与伪文字边界

**阻塞点**

- AI 图中的不可读题字、印章是作为氛围纹理保留，还是一律清除，尚需产品侧统一规则。

**拍板后执行**

- 定义允许的纹理字、必须可读的玩家信息和禁止出现的伪文字；
- 对场景、装备详情、角色肖像做分类审计；
- 玩家信息继续只由真实 UI 文本承载，不把生成图中文字当作功能信息。

#### P2-04 敌我与流派的非颜色单一辨识

**执行边界**

- 只使用现有边框纹样、指针形状、墨温和小型印记；
- 不移动人物、血条、状态牌和技能栏；
- 不增加新的教程弹窗或说明层。

**验收**

- 灰度和低饱和条件下仍能辨认敌我与首领；
- 小尺寸状态牌不依赖红/绿单一编码；
- 塔层、首领战、三人混战各选一条生产 route 验收。

### P3：完成 P1/P2 后再处理的细节抛光

- 动态字幕、伤害数字与角色脸部的短时遮挡采样；
- Windows 鼠标 hover、键盘 focus 与 disabled 状态的细微一致性；
- 低频页面剩余 token 漂移；
- 新增素材的透明边、压缩伪影和极暗背景可见性抽查。

这些任务不应提前挤占正式字体、站姿、Windows 实机和 29 组详情图的优先级。

## 5. 明确不进入后续任务的事项

- 不扩宽或改造用户已确认的固定窄宽页面；
- 不把仓库、档案或设置改成新的侧栏/页签信息架构；
- 不重排战斗 HUD、阵位、技能槽、底栏和状态牌；
- 不为了“更现代”替换水墨宣纸、沉郁墨色和克制绛红；
- 不在字体方案未确认前临时引入来源不明的 CJK 字体；
- 不把视觉收口扩张为玩法、经济、数值、存档或剧情改造。
