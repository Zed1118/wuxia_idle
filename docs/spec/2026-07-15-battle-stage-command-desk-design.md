# 战斗界面重构 · 水墨人物舞台与武学案台（设计初稿）

> 日期：2026-07-15  
> 阶段：1.0 长线打磨期  
> 状态：方向及 V2 概念稿已获用户认可；2026-07-15 实机对照后确认首轮实现仅达到功能灰盒，视觉还原未达标，现按概念稿重新收口
> 用户拍板：采用“透明全身战斗立绘 + 水墨人物舞台 + 武学案台”，不做实时 3D / 复杂骨骼模型；技能释放继续使用现有两段点选，不改为拖放；招式采用“人物动作 + 远程特效”的混合表现，不把全部技能统一做成原地弹道。

V2 概念稿（2026-07-15 用户认可）：[`docs/spec/battle_ui_stage_command_desk_v2_2026-07-15.png`](battle_ui_stage_command_desk_v2_2026-07-15.png)。

## 0. 一句话目标

把当前“左右头像列 + 底部文字按钮排”的战斗屏，重构为能看见人物交锋的水墨舞台：人物是第一视觉主体，招式案台是完整的操作系统，血条、战报和控制键退回辅助层。

玩家不看战斗日志，也应能立即判断：谁在场、谁在出手、谁可被选中、哪一招可用、真气是否足够、敌人是否正在蓄力，以及 Boss 与普通敌人的视觉区别。

## 1. 现状问题与成因

### 1.1 战场人物过小

- 双方各占一列 168px 宽区域，主体是 92px 圆头像。
- 中央场景留白很大，但人物没有进入场景，只在边缘横移、闪白和飘字。
- 角色名、境界、两条资源条、状态标签围绕头像堆叠，信息完整但人物感薄弱。
- Boss 虽有金色头像框，仍是小头像，无法形成压迫感。

### 1.2 底部技能栏像功能占位

- 固定 124px 深色矩形将水墨战场硬切断。
- 三名角色选择器、技能、冷却、真气、目标类型和快进控制处于同一视觉层级。
- 技能全部呈现为相同规格的文字按钮，招式性格只能依赖小标签和颜色。
- 横向滚动意味着玩家不能稳定建立招式位置记忆。
- 自动战斗时仍显示近似“不可用按钮”的形态，容易产生未完成感。

### 1.3 交互口径漂移

- GDD §5.7 锁定：点击技能查看简介；拖到目标并松手立即出招。
- 当前生产 UI 采用：单体技能两段点选、群攻点击即放、长按查看简介。
- **2026-07-15 用户重新拍板**：新方案继续采用当前生产交互，不恢复拖放。实施本方案时须同步修订 GDD §5.7，消除文档与生产行为漂移。

## 2. 已拍板的设计方向

### 2.1 采用二维透明战斗立绘

“全人物模型”在本项目中定义为**透明背景的二维全身或近全身战斗立绘**，不采用：

- 实时 3D 模型；
- Flame 等新游戏引擎；
- 需要大量逐帧资源的传统序列帧动画；
- 复杂 Spine 骨骼与换装系统。

表现由纯 Flutter Widget + 现有 AnimationController 完成：位移、缩放、轻旋转、闪色、残影、裁切、墨化和分层特效。

### 2.2 采用“水墨人物舞台”

- 双方不再竖排三个圆头像，而是按前、中、后景斜向错位站位。
- 我方整体朝右，敌方整体朝左；1v1/2v2 可镜像排布，标准 3v3 采用概念稿的非对称纵深——我方祖师压低外侧前景、两名弟子向中场抬高，敌方主位前压、随从向右后方退开。允许对原图做水平镜像，但人物题字、武器方向异常的资产须提供专用版本。
- 交锋区位于画面中央，行动者临时前冲进入交锋区，动作结束回位。
- 头像仍保留在角色切换、目标快捷选择、日志与缺图降级中，不再承担主战场人物表现。

### 2.3 采用“武学案台”

底部不再是一排通用按钮，而是一张悬浮于战场下缘的水墨案台，分为：

1. **执招者**：当前角色、队员切换、真气状态；
2. **招式谱**：固定位置的招式签；
3. **战备行囊预留位**：未来战斗消耗品快捷槽与行囊入口。

自动/允许点选、速度、暂停属于整场战斗控制，移入顶栏，不与技能或道具争夺案台宽度。

## 3. 总体布局

### 3.1 垂直信息层级

```text
┌────────────────── 战况、节拍、暂停、撤退 ──────────────────┐
│                  蓄力危险提示（按需出现）                    │
│                                                             │
│    我方后景                               敌方后景            │
│        我方中景                       敌方中景                │
│            我方前景     中央交锋区     敌方前景               │
│                                                             │
│              招式题字、墨痕、弹道、伤害反馈                  │
│                 最近战报（单行、弱化、可展开）                │
├────────────── 悬浮武学案台，不做整块硬切背景 ────────────────┤
│  执招者与真气        7 枚固定招式签         战备行囊预留位      │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 视口策略

- **1280×720 为硬验收底线**：不溢出、不遮挡人物关键部位、不依赖横向滚动完成核心操作。
- 1440×900 与 1920×1080 增加的是人物尺度、舞台留白和特效活动空间，不额外堆信息。
- 布局使用断点与设计 token，不在各 Widget 散写尺寸。
- 战场优先保证人物高度；空间不足时先收窄战报、状态文字和案台装饰，再等比缩人物。
- 1280×720 的案台宽度预算以执招者约 18%、招式谱约 58%–62%、战备行囊约 20%–24% 为灰盒起点；最终值以真机文字和点击热区验收为准。

## 4. 水墨人物舞台

### 4.1 标准 3v3 阵列

- slot 0（前景/前排）：最靠中央、尺度最大、垂直位置略低。
- slot 1（中景）：向外、向上退半步，尺度约为前景的 90%。
- slot 2（后景）：继续向外、向上退，尺度约为前景的 80%。
- 阵列只表达空间纵深，不新增前后排数值、减伤或站位玩法。
- 人物互相允许少量轮廓重叠，但脸、武器和资源条不得被遮挡。

### 4.2 人物信息板

每名人物只保留贴身的战斗必要信息：

- 姓名；
- 短血条；
- 短真气条或真气刻度；
- 最多 2 个常驻状态标签，其余合并为状态入口；
- 蓄力、破绽、护法结界等关键机制使用轮廓环、地面墨圈或人物侧题签。

境界不再常驻占据人物下方一行；可移入 hover/详情或战斗开场亮相。最近战报降为单行，点击后仍打开完整日志抽屉。

### 4.3 动作表现

不为每个招式制作独立动作动画，先建立可复用的动作语法。技能按表现性质选择五类模板：

| 表现模板 | 适用招式 | 人物位移 | 主要特效 |
|---|---|---|---|
| `melee` | 掌法、刀剑近击、近身破招 | 起势后快速前冲至中央交锋锚点，命中后回位 | 近身墨痕、hit-stop、受击后仰 |
| `projectile` | 暗器、剑气、掌风等远程招式 | 原地起势或只前踏半步 | 从手部/武器锚点发出弹道 |
| `area` | 群攻、横扫、震荡 | 短暂前移并放大，不逐个冲向目标 | 横扫墨痕、地面墨圈或全场气浪 |
| `control` | 内伤、阴柔控制、缠制 | 基本保持原位，以起势动作表达 | 墨气、扩散波、目标侧状态反馈 |
| `cinematic` | 大招、共鸣技 | 人物短暂升为主视觉，按招式需要决定是否前冲 | 背景压暗、招名题字、贯穿或全屏命中效果 |

近身人物只移动到中央交锋锚点，不直接进入敌方原站位，避免 3v3 立绘叠成一团。命中关系由墨痕、弹道或冲击波从交锋锚点继续连接到真实目标。

每次行动遵循统一四段节奏：**起势 → 出手/位移 → 命中 → 收势回位**。不同模板只调整各段幅度和表现，不改变战斗 tick 与结算时机。

通用战斗状态继续使用下列表现：

| 行为 | 人物动作 | 场景反馈 |
|---|---|---|
| 普攻 | 短前冲 + 轻微放大 | 细墨痕、轻 hit-stop |
| 强力招 | 更深前冲 + 起势回弹 | 流派色墨痕、屏幕轻震 |
| 大招/共鸣 | 人物短暂升为主视觉 | 背景压暗、招名题字、强命中反馈 |
| 受击 | 短后移 + 闪色 | 伤害字、墨点飞散 |
| 闪避 | 侧移残影 | 原位置留淡墨虚影 |
| 蓄力 | 呼吸缩放或衣摆墨气 | 轮廓环与剩余拍数 |
| 破绽 | 人物失衡、绛红墨圈 | “破/断”等既有题字反馈 |
| 阵亡 | 下沉、褪色、墨化 | 资源条同步消隐，不留灰色头像柱 |

动作仍是纯表现层，不改变 tick、命中、伤害、AI 或胜负计算。

### 4.4 Boss 与特殊战斗

- Boss 占敌方主位，默认比普通角色大 25%–45%；随从退到中后景。
- 单 Boss 战不保留三槽等分空位，双方人物自动放大并靠近交锋区。
- 2v2 自动采用前/后双点阵列。
- 群战不渲染 5–7 个同等大小的完整人物：主将保留完整立绘，其余单位缩为有区分度的墨影队列。
- 轻功对决可将阵列改为上下错层和更大的水平位移，但复用同一人物资产与信息板。
- 心魔镜像使用人物立绘的反相墨色/边缘晕染，不复制新的角色美术。

## 5. 武学案台

### 5.1 案台外形

- 使用底部渐暗墨层和局部纸签，不使用贯穿全宽的实心深色矩形。
- 中央招式谱最突出；执招者次之；战备行囊以器物格形态收束在右侧。
- 保持水墨克制：大面积青黑/纸灰为基底，铜金只表示高价值或关键时机，绛红只表示危险与破招。
- 自动/允许点选、速度、暂停、日志和撤退统一归入顶栏；底部右侧不再放战斗节奏控制，完整保留给战备行囊。

### 5.2 执招者区域

- 三名队员表现为固定位置的人物名签，可附小头像，但不再使用三张高瘦调试 chip。
- 当前执招者名签展开，显示姓名、主修流派与真气气脉。
- 真气是角色与招式之间的公共资源，应在招式谱之前被看见，而不是重复埋入每个按钮状态文案。
- 敌人蓄力时，可破招的角色名签出现一次明确但克制的金色墨光；若当前角色不可破招，可自动将视觉焦点引向可破招者，但不替玩家直接出手。

### 5.3 招式签

每个非普攻技能占据一个稳定槽位，按现有装配结构为 **7 槽固定可见**：主修×2、辅修、共鸣、大招、奇遇、破招。空装配槽保留稳定位置，不使用横向滚动：

- 招式名是最大文字；
- “破 / 绝 / 合”等性质用小印章表达；
- 单体与群体通过签形、墨痕展开方向及目标提示区分，不依赖孤立的“单/群”小角标；
- 真气消耗显示在签底，与左侧气脉同色；
- 冷却以墨色覆盖/褪去表现，同时保留剩余拍数，避免只靠颜色；
- 真气不足时降低墨色并显示气脉缺口，不将整张招式签处理成普通 disabled 灰按钮；
- 可破招时招式签轻微抬起并出现短促呼吸光，不持续闪烁。

装备专属技能等战斗中临时并入的额外招式不直接挤出第 8 张常驻大签；实施计划前须核实其触发方式，优先作为对应装备/技能签的临时附印或自动触发提示。不得用横向滚动隐藏基础 7 槽。

### 5.4 桌面主交互

- **单体招式（多个存活敌人）**：点击招式签进入待发态，战斗软暂停；所有合法目标获得克制的墨光轮廓，再点敌方人物或快捷目标签立即出招。
- **单体招式（仅一个存活敌人）**：点击后直接对唯一目标出招，不增加多余确认。
- **群体招式**：点击后立即对全体存活敌人出招，不进入选目标状态。
- **查看简介**：长按招式签；冷却或真气不足时仍可查看。
- **取消待发**：再点同一招式、点击战场空白或按 ESC；不消费真气、不进入冷却。
- 不实现拖放释放，也不在案台与目标之间绘制跟随指针的拖招路径。

### 5.5 自动与允许点选两种形态

#### 自动战斗

- 案台收窄为“招式轮转谱”，仍展示当前角色、真气、冷却与将要发动的技能。
- 不将技能渲染成一排灰掉的可点击按钮。
- 允许玩家观察 build 运转，但不误导为当前可操作。

#### 允许点选

- 案台完整展开，招式签获得点击命中区；单体技待发后，敌方人物与快捷目标签进入可选状态。
- 战场人物获得目标轮廓反馈。
- 敌方蓄力时，破招角色与破招技能形成一条连续视觉引导，而不是在多个区域分别亮灯。

模式切换只改变表现与输入门控，不改变自动战斗基础规则；首通强制允许点选的既有规则继续保留。

### 5.6 战备行囊预留位

战备行囊属于全队共享战备，不属于当前执招者的技能槽。当前版本只锁定布局契约，不在本方案中实现或拍板战斗药品规则。

#### 布局

- 案台最右侧固定预留 **3 个消耗品快捷槽 + 1 个“行囊”展开入口**。
- 快捷槽显示器物图、剩余数量和不可用原因；不使用与招式相同的纸签形状，避免把道具误认成第五类武学。
- 空槽保持淡墨轮廓，不自动从背包补入。`rejected_task_registry.md` 已明确排除“药品行囊自动补位”。
- 行囊展开层向上覆盖战场下缘，不横向挤压七个招式槽；展开时战斗软暂停。
- 自动/允许点选、速度、暂停移到顶栏，避免右侧道具区与战斗控制混杂。

#### 未来交互契约

- 无目标或全队生效道具：点击后按未来规则直接使用或确认使用。
- 单体友方道具：第一次点道具进入待发，第二次点我方人物或快捷目标签使用，与现有单体技能的两段点选语法一致。
- 再点同一道具、点击空白或按 ESC 取消待发；不使用拖放。
- 成长型经验丹、秘籍、强化材料不进入战备行囊；只有未来明确标记为“战斗内可用”的消耗品可装入。
- 自动战斗是否消耗、每场次数、冷却、目标规则和离线结算一致性均属于独立玩法 spec，未拍板前 UI 只保留空态/禁用态，不先写隐含规则。

#### 红线提醒

战斗消耗品会同时触及资源消耗、自动战斗和“在线 = 离线”。后续设计必须在以下方向中另行拍板：显式挑战战专用，或自动/离线遵循完全一致的消耗规则。不得出现在线手动可喝药、离线同类战斗却无法获得等价结果的隐性增益。

## 6. 战斗立绘资产规范

### 6.1 新资产与现有资产的关系

现有玩家立绘多为 896×1344 纵向纸面构图，敌人图多为 1024×1024 方形纸面构图，均带完整背景。它们适合角色页、叙事和头像裁切，但不适合六张同时进入战场。

战斗舞台应建立独立资产口径，不能简单把现有方图缩小排列。

### 6.2 推荐交付格式

- WebP 或 PNG 内容，必须带真实 alpha 透明通道；扩展名策略沿用项目现有资产约定。
- 推荐母版比例约 2:3，人物头顶、兵器、衣摆、双脚完整。
- 不含场景背景、边框、文字、印章和地面投影。
- 人物周围保留适量透明安全区，避免攻击位移时裁切兵器。
- 统一脚底基线和头部安全线，便于不同身高角色在同一阵列中稳定缩放。
- 默认姿势为可读的战斗起势，不要求夸张动作；武器与流派必须一眼可辨。
- 需要镜像的资产必须检查服饰文字、伤疤、单侧武器与手势是否允许水平翻转。

### 6.3 资产降级链

1. 专用透明战斗立绘；
2. 现有立绘经不规则墨晕遮罩形成临时人物卡；
3. 现有头像裁切；
4. 首字水墨占位。

降级只保证不崩和信息可读，不作为最终美术验收通过条件。

### 6.4 首批样板

不直接全量重制，先用一场标准 3v3 和一场 Boss 战验证资产规范：

- 玩家：祖师、大弟子、二弟子；
- 普通敌人：覆盖三种明显不同体型/兵器；
- Boss：选择已有多阶段或护法机制的代表 Boss；
- 共 7 张左右透明战斗立绘即可完成第一轮布局与动作验证。

样板验收通过后再批量生产，避免全量资产在尺寸、朝向或透明边缘上系统性返工。

## 7. 技术边界与数据影响

- 不改战斗数值、AI、伤害公式、tick、胜负条件和掉落。
- 不新增站位数值；前中后景仅是视觉映射，继续使用既有 slotIndex。
- 不引入 Flame、3D 引擎或大体量运行时依赖。
- 中文文案统一进入 `UiStrings`；枚举显示继续走 `EnumL10n`。
- 视觉尺寸、阵列位置、人物缩放和动作时序进入集中配置/token，不在多个 Widget 中散写。
- 技能表现类型由数据显式声明，不仅凭流派或技能类别猜测；`data/skills.yaml` 新字段沿用该文件 camelCase 历史规则。五类模板的位移距离、时序和特效强度集中配置，避免为每个招式复制动画代码。
- 本方案只预留战备行囊 UI，不把现有经验丹、秘籍或战后疗伤丹改成战斗内道具；未来功能必须新增明确的战斗可用声明与消费服务，不能直接复用背包“使用”按钮绕过战斗状态。
- 建议将战斗资产路径与通用 `portraitPath/iconPath` 语义分开；最终字段落点须在实施计划前核实存档/schema 影响，优先采用 def 层可选路径并保持旧档无需迁移。
- 现有弹道、命中特效、题字、屏震和音效尽量复用；人物坐标需要从头像槽坐标迁移为舞台角色锚点。

## 8. 实施切片（已执行）

1. 静态灰盒：新战场阵列 + 新案台布局（含 7 技能槽与 3 个行囊预留槽），使用占位人物剪影验证 1280×720。
2. 资产样板：7 张透明战斗立绘，验证脚底基线、镜像、透明边缘和 Boss 尺度。
3. 人物舞台组件：1v1 / 2v2 / 3v3 / Boss 阵列与信息板。
4. 既有表现迁移：攻击位移、受击闪、飘字、蓄力、破绽、护法、阵亡。
5. 武学案台静态状态：角色切换、真气、冷却、单群、破招、大招。
6. 交互收口：单体两段点选、群体点击即放、长按简介、目标反馈与取消待发。
7. 自动/允许点选双形态与特殊战斗适配。
8. 双分辨率视觉验收、widget 测试、analyze 与相关战斗回归。

每个切片都必须保持可运行、可截图和可回退；这是战斗核心屏大改，实施时应另写 plan，不在本设计文档中展开到逐文件任务。

## 9. 验收标准

### 9.1 五秒识别

新玩家观看静态截图五秒，应能指出：

- 哪边是我方、哪边是敌方；
- 场上各有几人；
- 谁是 Boss；
- 当前控制的是谁；
- 哪些招式可用、哪一招可破招；
- 当前是真气不足还是技能冷却。

### 9.2 动态可读

- 不看日志也能判断当前行动者、受击者与伤害落点。
- 大招、强力招、普攻的视觉层级明确，但不靠满屏高饱和特效区分。
- 单体技进入待发后，技能、合法目标和快捷目标签形成连续视觉关系；第二次点选后反馈立即出现。
- 3v3 人物轮廓、姓名和血量不互相遮挡。

### 9.3 视口与性能

- 1280×720、1440×900、1920×1080 均无 overflow。
- 低配/减少闪烁设置下仍能读懂行动和目标。
- 6 名透明立绘同时在场不造成持续掉帧；静态人物层使用 RepaintBoundary，动画只重绘必要子树。

### 9.4 风格

- 战斗截图看起来是写实水墨武侠，不像卡牌头像对撞，也不像通用手游技能栏。
- 底部案台与场景相融，但信息对比度足够。
- 铜金、绛红和三流派色只用于明确语义，不形成彩色按钮阵列。

## 10. 尚待共同拍板

以下内容不阻碍方向成立，但应在静态灰盒前逐项拍板：

1. 招式签采用横向短签还是略带竖意的窄长签；
2. 人物信息板放在脚下，还是贴近人物外侧；
3. 自动模式的轮转谱保留多少技能信息；
4. 战备行囊空态采用三个常驻淡墨槽，还是收成一个“尚未备药”的窄题签；
5. 首批样板 Boss 的具体对象；
6. 群战中的“主将完整立绘 + 士卒墨影队列”是否接受。

## 11. 明确不做

- 实时 3D、自由镜头、角色骨骼换装；
- 每个技能独立逐帧动画；
- 因视觉前后排新增战斗数值；
- 借 UI 重构改战斗公式或技能平衡；
- 为追求“华丽”加入高饱和稀有度框、SSR 式光柱或持续闪屏；
- 一次性重制全部敌人资产后才开始验证布局。
