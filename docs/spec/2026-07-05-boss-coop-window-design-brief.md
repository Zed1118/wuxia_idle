# Boss 协同窗口(敌方协同) · design brief(2026-07-05 夜间批 I · 待拍板)

> backlog 四·P2③ 遗留:「Boss 协同窗口(『敌方协同』新概念·先讨论范围再动)」。
> 本 brief 给现场事实 + 3 候选形态 + 红线边界 + 推荐,不动代码。

## 现状(现查)

- **玩家侧协同已闭环**(第六阶段):敌 `staggerTicksRemaining>0` 破绽窗口 → 全队优先集火
  (battle_ai.dart:209-224 `_pickFocusTargetId`);junior 控场盯蓄力敌(battle_ai.dart:76)。
- **敌方侧无 team 级协调**:`BattleAI.decide`(battle_ai.dart:28)每敌每拍独立决策;
  `BattleState` 无跨敌协同状态字段可挂——做敌方协同需要新状态面(这是成本主项)。
- 既有敌方「准协同」原语(全部可复用):蓄力 `chargingSkill`/破招踉跄、护法结界
  (guardianWard taunt+减伤,battle_ai.dart:163-180 isGuardedBoss)、bossPhases 3 aiMode、
  心魔镜像 vulnerability 注入(inner_demon_service.dart:116-146)。

## 3 候选形态

| 形态 | 机制 | 复用面/新面 | 玩家反制(爽感闭环) | 成本 |
|---|---|---|---|---|
| **A 合击蓄力** | 双敌同步进蓄力,同拍引爆合击(伤害/效果强化);**打断任一 → 两个都踉跄**(合击破功,双倍破绽窗口) | 复用 charge/stagger/危险条渲染;新面=同步启动+引爆判定(需轻量跨敌状态) | 强:破招一个赚两个,读秒环天然可视 | 中(xhigh 设计+实装一批) |
| B 护法赋能 | 护法存活时 Boss 蓄力周期缩短/相位提前(结界之外再加「催功」语义) | 几乎全复用 guardianWard plumbing | 弱:数值型,玩家感知差(先杀护法本就是既有解法) | 低 |
| C 链式驰援 | Boss 血阈相位触发时,存活小怪切 aggressive/focus aiMode 集火玩家最低血 | 复用 bossPhases aiMode 思路,扩到非 Boss 敌 | 中:压力型非窗口型,反制=奶/换目标,挂机下反制面窄 | 低-中 |

## 红线边界(三案共同)

全部走机制/AI/目标选择层,**不膨胀伤害数字**,与 v1.30「机制型 Boss 例外=减伤方向」同精神
(A 的合击强化若做伤害端,需守敌方伤害不制造玩家闪 death——建议做成「效果强化」如内伤/踉跄
而非纯大数字);不新增胜负条件;不触三系锁死/在线=离线;投放面限定终局(爬塔高层/心魔/周目),
主线不投(守早期爽感基本盘)。

## 推荐

**A 合击蓄力**,理由一句话:唯一「窗口型」方案——敌方协同制造的威胁本身就是玩家的机会窗口
(破招一个双倍回报),与战斗爽感主旋律(参与感+打击感)和既有读秒环/破招投资全线复利;
B/C 是数值/压力型,感知弱。可后续把 B 作为 A 在塔更高层的叠加变体。
