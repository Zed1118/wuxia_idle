## 2. 机制规格

### 2.1 掩护相位(核心循环)

触发:协同型 Boss 进入蓄力(`chargingSkill != null`)且存在存活护法 → 护法进入「掩护」。

**破招重定向链**(回应 `battle_ai.dart:65` 留白的正式拍板:破招**不穿透**掩护,但不白费):

1. 我方破招技命中被掩护 Boss → **重定向到掩护护法**:护法代吃打断 → 护法踉跄(`staggerTicksRemaining`,复用 phase6 破绽窗口),Boss 蓄力**不断**。
2. 护法踉跄 → 我方 `_pickFocusTargetId` 自动集火(零新代码)→ 击破护法 → 掩护解除。
3. 掩护解除后 Boss 仍在蓄 → 第二发破招才真打断(走既有破招路径)。

决策张力:抢时间链条(破招→集火→再破招)vs 硬吃大招保破招 CD——两条路都通,梯度由蓄力 tick 数配置控制。若破招直接穿透掩护,掩护无意义(玩家无脑破招);若护法纯挡下无代价,破招白费挫败——「代吃+踉跄」让每一步都有收益。

### 2.2 护法合击(压迫可见性)

- 触发:掩护相位中双护法均存活 → 护法行动替换为「合击」(每相位一次):两护法伤害各按 `damage_calculator` 公式计算后**合并一次结算**,目标=我方当前血最低(复用 `_pickTargetId` 语义),配重表现(hit-stop/双人题字/战报专句)。
- 击破任一护法 → 合击不可用(单护法仍掩护,无合击)——「拆散一个就废」的目标优先级爽点:先打踉跄的还是血低的,决策留给编成/介入。
- Boss 蓄力倒计时 + 合击即时伤害双重压力 → `interveneNow` 拖招/手动锁定的价值时刻。

### 2.3 配置层(全部 opt-in,不配=零行为变化)

敌配置新增(snake_case,towers/stages/gauntlets 通用):

- Boss 侧:`coop_charge_skill_id`(协同蓄招技,CD 型)、`guard_intercepts_interrupt: true`(掩护重定向开关)。
- 护法侧沿用 `guardianDefIds` 注册;合击**不引入独立倍率字段**(合并结算=两份公式伤害求和,零新数值面)。
- schema 校验:蓄力 tick 有界;`guard_intercepts_interrupt` 仅可配于已有 `guardianDefIds` 的 Boss(联结校验 fail-fast,沿 §8.1 体例)。
