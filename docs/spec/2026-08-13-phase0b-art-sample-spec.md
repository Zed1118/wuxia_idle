## 1. 本阶段要回答的问题

Phase 0B 不是“批量出漂亮图”，只回答五件事：

1. 现有写实水墨角色身份能否迁移为横向浅纵深实时动作，而不变成另一个游戏；
2. `20+1` 中主角、精英和危险方向是否仍能在 1 秒内读懂；
3. 聚怪、清场和破招能否共用一套克制的水墨反馈语法；
4. 主角、普通敌人和精英各需要多少拆件、骨骼、动作与人工清理成本；
5. 正式动画资产能否同时服务实时模式，并以关键帧/演出层反哺挂机战斗，而不把反哺设为前置依赖。

## 3. 冻结视觉语言

### 3.1 层级

1. 主角：稳定青绿色主块、最高局部明度、始终露脚和躯干中心；
2. 精英：约 `1.25×` 普通敌人体量、直立重心、粗墨外缘；
3. 危险/破招：朱砂只在判定方向和窗口出现；
4. 普通敌人：灰褐同族群，以姿态和深度区分，不用高饱和换色；
5. 场景：宣纸黄和灰墨，战斗带细节低于人物轮廓。

### 3.2 动作反馈

- 普攻：一条短促白墨锋线；
- 身法：一段横向残墨，不留长时间分身；
- 聚怪：贴地向内墨流，不伤害、不爆炸；
- 清场：唯一主墨环 + 错峰击退，不为每个目标叠一套特效；
- 破招：短白墨命中 + 约 80ms hit-stop；
- 精英重击：动作轮廓优先，朱砂只是辅助，禁止全屏红罩。

## 4. 生产拆件建议

### 4.1 主角样片

建议 `22–28` 个核心绘制/绑定部件：头、面部、前后发、长须 3–4 段、躯干、骨盆、双上臂/前臂/手、双大腿/小腿/脚、内袍、外袍左右大片、双袖外摆、腰绳、前后衣摆。长袖、长袍、须发至少使用独立二级链，否则移动与身法会像整张纸片旋转。

首批动作：idle、run、basic、dash、gather、clear、break、hurt、defeat，共 9 个；普攻需要可循环且支持后半段身法取消。

### 4.2 普通刀客模板

建议 `14–18` 个部件；短衣和单腰带尾，避免长披风。首批 7 动作：idle、run、telegraph、strike、pulled、knockback、defeat。以同一骨架换头部、袖片、腰片和刀型，可制作 3 个低成本变体；20 人同屏不等于 20 套骨架。

### 4.3 精英

建议 `18–24` 个部件；沿普通人类骨架扩体量，但须发、长袍和武器独立。首批 8 动作：approach、circle、telegraph、break-window、commit、stagger、recover、defeat。

## 5. 资产管线路线对照

| 路线 | 优点 | 风险 | Phase 0B 用法 |
|---|---|---|---|
| 分层 2D 骨骼 | 动作复用高、换片便宜、适合多敌同屏 | 长袍穿插需网格/约束；运行时和工具选型成本 | **主验证路线** |
| 逐帧序列 | 关键动作质量稳定，运行时简单 | 文件大、动作与方向扩展昂贵 | 仅为 R/破招高潮做 6–10 帧对照片 |
| 整张立绘变形 | 最快 | 纸片感强，不能支撑 ARPG 手感 | 不通过，不进入正式样片 |

Phase 0B 不直接拍板 Spine、Rive 或自研运行时。透明姿态图集已完成第一个引擎接线对照：`1 主角 + 6 刀客 + 1 精英`按 `approach → gather → clear → elite telegraph → break success → settle` 自动循环。它是离散姿态切换，不是骨骼或连续逐帧动画。

本轮又完成了一个 Flame 原生层级关节木偶对照。代码能够播放 `idle → basic → dash` 的父子层级、旋转和位移，但 AI 自动拆出的 16 个部件没有绘制关节背后的隐藏延伸区，产生明显断袖、断手和袍片接缝。结论是：**零依赖层级木偶技术可用，自动拆件资产不可用**。后续只有人工补画重叠区、关节盖片与衣摆层次后，才有资格与逐帧路线做画质/工时对照；当前结果按失败证据冻结。

## 7. 美术 ROI

- 实时战斗资产的第一收益来自反复刷的主角、普通敌人和通用技能反馈，不来自只打几次的 30 个独立 Boss；
- 主角骨架应跨流派复用基础移动/受击/身法，武学只替换手臂层、武器层和特效层；
- 普通敌人优先“一骨架多换片”，精英优先“普通骨架扩展 + 独立关键态”，Boss 才允许完全独立；
- 挂机模式可选择复用 idle、普攻、受击、R 关键帧和题字，但不将“挂机战斗全面换骨骼”设为 Phase 0B 前置；
- 若最终手操只占总时长约 10%，则共享到挂机表现层的资产比例应至少达到 50%，或美术预算必须相应收缩。

## 9. `20+1` 美术负载与镜头修正

新增独立模式 `phase0b_art_load`，始终绘制 `1 主角 + 20 普通刀客 + 1 精英 + 1 背景`，与 Phase 0−、Phase 0A 的 Gate writer 和结果目录物理隔离。它只观察姿态图集在真实密度下的绘制负载，字段固定 `gate_eligible=false`，不得替代玩法、真人或 Windows Gate。

**产品边界：该模式不是最终战斗界面。** 固定 1280×720 镜头只用于把最坏同屏美术负载稳定复现；不得据此把普通关卡做成一张固定竞技场。固定场地只允许用于有明确空间理由的 Boss 房、守点或特殊挑战。

第一版负载阵列暴露了真实美术问题：主角高度约为普通敌人 `1.8×`、20 人同姿态围成完整椭圆、背景自带动作剪影，人物像贴纸而非站在山道上。根据实机审片，Camera V2 做出以下修正：

- 主角基础高度 `168px`、普通敌人 `132px`、精英 `184px`，再按脚底 `y` 做 `0.78–1.06×` 纵深缩放；
- 战斗带中心从画面中部下移到山道路面，人物统一按脚底 `y` 排序；
- 清场由同时腾空改为五组错峰，受力距离加入固定差异，不再形成完整花环；
- 主角周围强制保留约 `210×152px` 的可读性口袋，运动插值也不得穿入；
- 背景换为无人物的 1280×720 山道底板；1440×900 使用等比 1440×810 内容区并上下留黑边，不做非等比拉伸。

当前四张解码纹理理论 RGBA 占用为 `22,563,280 bytes`（约 `21.52 MiB`）；20 名刀客共享同一图集，不能错误乘以 20。每帧逻辑 `drawImageRect` 为 23 次；它不是 GPU draw-call 结论。首轮 `0.05×` Profile smoke 得到 435 帧、`totalSpan p99=1.596ms`，只证明采集链与模式可运行，**不构成 60 秒正式观察矩阵**。正式矩阵固定两视口各 3 次、每次 `12s warmup + 60s sample + 30s cooldown`。

## 10. 连续地图与镜头方向

用户审片后明确否决“整场战斗框在一个页面”的舞台感。产品主结构冻结为：**独行穿关，敌群沿路围来；局部聚成怪海，高手清出一条路。**

新增隔离模式 `phase0b_scroll_review`，技术样片使用 `3600×720` 世界（约 2.8 个 1280px 视口）、WASD 横向与浅纵深移动、横向 dead zone 和 delta-time 平滑镜头。三段局部遭遇按 `6 → 10 → 20+1` 递进；敌人从视口外分两批进入，20+1 只在末段关隘形成局部峰值，不铺满整张地图。地图改为一张 3600×720 连续长卷：山口、林道、关隘在同一母图、同一地平线和道路透视中一次生成。运行时按原生比例绘制，不横向拉伸，也没有跨图拼缝；三张独立背景加雾幕的尝试因仍有拼接痕迹而被否决。现有 Phase 0A 白盒本来已经使用 `2400×720` 世界和跟随镜头，本模式负责把美术资产接回这一产品结构。

最终地图规则：

- 普通主线/险境是连续行进空间，不以每屏空气墙或固定矩形竞技场为默认；
- 镜头主要跟随 X，浅纵深移动不得造成大幅上下摇镜；朝移动方向保留前瞻空间；
- 怪从视口外、后方和纵深入口分批涌入，不在玩家眼前原地生成；
- 地图通过山口、林道、桥、关门等地标表达推进，遭遇结束后继续行进；
- 只在局部遭遇中达到 20+1，高密度是高潮而非常态；
- 当前地表是一张连续扁平长卷，并已叠加独立远景雾（0.18）、贴地雾（0.72）、脚底 Y 排序和前景遮挡（1.04）作为层次验证；仍明确标记 `NOT FINAL MAP ART`。正式场景至少提供可独立调整的 sky/far/mid/ground/foreground 美术层。

吸收《暗黑》的连续推进、视口外涌怪、普通群/精英层级、局部密度高潮与清场后继续前进；不吸收等距视角、常态满屏怪、彩色词条光污染和每屏硬锁门。吸收《鬼谷八荒》的地域空间叙事、技能形状语言和危险窗口；不吸收固定竞技场作为主结构、俯视弹幕海和仙侠漂浮轰炸。

连续地图观察链新增 `phase0b_scroll_profile`，与 0−、0A 和固定镜头 art-load 的结果目录及结论完全隔离。2026-08-13 23:36 起在 LG 60Hz / DPR 1 的本机 Profile 模式完成 `1.0×` 签名矩阵：1280×720 与 1440×900 各 3 次，每次 `12s` 预热、`60s` 采样、`30s` 冷却。六次均按 `6 → 10 → 21` 覆盖遭遇，20+1 累计全部可见 `15.50–15.56s`，镜头世界移动 `2316.49–2317.34px`；`totalSpan p99` 为 `2.257–2.442ms`，最大帧 `7.369ms`，六次 `16.6ms` 超预算帧均为 0，严重连续帧均为 0，RSS 峰值 `193.45–199.08MB`。所有结果绑定 Git commit `948094694a8d9afe11ba248653593603953d0831` 与长卷 SHA256 `7991d755676a11e66b94018e5dc5ffbef8c5b9f891640a287393b0f485e9ee6d`。该矩阵只证明连续长卷、跟随镜头、程序层次与局部 20+1 负载在这台 Mac 可稳定观察，字段固定为 `gate_eligible=false`，不得替代 Phase 0− 性能 Gate、最低档 Windows Gate 或 Phase 0A 玩法 Gate。
