## 0. 文档用途与决策效力

本文档把本次会话中已经得到“认可、加入、继续”的内容，转换为能够直接拆分、开发、测试、合并和验收的实施方案。它同时回答五个问题：

1. 最终要把游戏改成什么样；
2. 现有系统哪些保留、哪些改造、哪些退役；
3. 底层规则、数据结构、界面和内容如何分层落地；
4. Codex、Claude Code、Qoder、DeepSeek 等工具如何大规模并行而不互相覆盖；
5. 每个阶段怎样证明“已经完成”，而不是只完成了孤立代码或配置。

本方案服从项目既有永久红线：买断制、无抽卡、无传统体力、无每日/每周任务、无登录奖励、无战令、无留存焦虑；在线与离线遵循同一战斗规则和收益口径；境界、装备阶、心法阶一一对应；数值与中文文案不得散写进 Dart；不引入第三方游戏引擎；保持克制水墨风格。

本次方案对旧协作口径有一项明确覆盖：项目文档曾记载 DeepSeek/Windows AI 工作流退役；本次用户明确要求 Qoder、DeepSeek 等外部工具重新加入。因此允许它们作为受控执行端重新参与，但不恢复“跨端各写各的”模式，不允许直接写主分支，不允许绕过主审与质量 Gate。Windows 仍主要承担发布兼容验证；外部工具输出一律视为待审补丁。

### 0.1 决策状态

- **FROZEN**：已由会话明确确认且可直接作为合同的规则。包括单角色 ARPG、主线首次推进固定掌门、支线可选符合条件的掌门/门人、亲战/差遣分离、取消强制关间剧情、五武器、三主修特性、六类几何、防御/姿态/状态方向、六类特殊模式、奖励三层、六生态包、七遭遇模板、21 章矩阵和受控并行。
- **PROPOSED**：方向或执行翻译尚未获得明确签字。当前包括：主线重打/前台 bot/headless 重刷/扫荡的参与者；连续关卡间换装与伤势中断；“随行听剑”的占用方式；七类心魔的具体 AI 行为映射；渐进解锁的精确章点和部分章节生态分配。听剑成长比例与每关上限归 `TUNING`，不与占用决策混用状态。
- **TUNING**：不改变已冻结方向的参数候选，包括秒数、倍率、数量预算、上限和性能目标。必须通过模拟、测试和真人试玩定标。
- **IMPLEMENTATION-GAP**：目标规则已确认，但当前代码/配置/长寿文档与之不一致。必须有明确任务和专项回归，不得仅改文字。

G0 不使用“未提异议即冻结”。完成条件是：每个 `PROPOSED` 由用户明确改写、保留或暂缓；每个 `IMPLEMENTATION-GAP` 有 owner、生产路径、针对性测试和验收证据；registry 记录决策 ID、原会话依据、当前状态、实现证据、处置和批准日期。

## 1. 最终产品形态

### 1.1 战斗核心

- 产品战斗统一为单角色、实时、横版、水墨 ARPG。
- 旧 3v3 不再作为可选模式、兼容回退或特殊玩法；只允许旧存档/历史枚举的最低兼容残留。
- 场上不设置可控或常驻 AI 队友。门人价值通过差遣、个人成长、活动占用、师承和宗门调度体现。
- 玩家在一场战斗中只控制一名角色；除主线这一身份例外外，这名角色可以是主角掌门，也可以是任意满足条件且空闲的门人。
- 手动亲战、自动战斗、差遣结算、扫荡与离线挂机共享同一套角色快照、技能规则、敌人规则、胜负、受伤与奖励结算；不同模式只改变输入来源和时间推进方式。

### 1.2 掌门与门人的选择

- 主线首次推进固定使用当前掌门，以保证叙事身份与成长记录稳定。重打、自动重刷和扫荡是否也必须掌门参与保持 `PROPOSED`，G0 前不得写死在公共参与合同中。
- 副本、塔、轻功、群战、断魂庄、远征等支线活动均可选择掌门或门人。
- “亲战”表示玩家实时控制本次选中的角色，不等同于“只能掌门亲战”。
- “差遣”表示角色被派往活动，由 bot/headless 运行或按统一规则结算，不等同于“只能派门人”。
- 掌门空闲时，可以亲自参加支线战斗或被差遣；掌门闭关、远征、重伤疗养或处于其他互斥状态时不可出战。
- 门人同样受闭关、远征、疗伤、当值历练等状态约束。
- 每次进入活动单独选择参与者，不设置会让旧 3v3 复活的全局“出战阵容”。旧编成界面改造为“门人调度”。
- 实际参与者获得经验、武学熟练度、伤势和个人记录；物品、银两、材料、唯一解锁归宗门共享口径。
- 主线首次通关允许设置“随行听剑”：选择 0 或 1 名符合条件的门人；门人不进战场、不提供属性/战斗帮助、无战斗装备快照、不受伤、不计通关纪录、不分掉落；只在该关首次通关时获得小额个人经验或主修熟练，重打、自动重刷和扫荡不重复发放；更换无费用、无冷却。是否锁定整段 `MainlineRun` 及如何与其他活动互斥遵循 `MENTOR-INSIGHT-OCCUPANCY-01 / PROPOSED`；具体比例和每关上限遵循 `MENTOR-INSIGHT-RATE-01 / TUNING`，两类状态不得合并审批。

### 1.3 主线节奏

- 删除主线每个小关卡之间的强制过场动画、开场文字、胜利文字与关间剧情页。
- 一关胜利后先完成必要结算，再在结果界面提供醒目的“进入下一关”按钮；点击后直接进入下一小关，不必退回章节或关卡列表。
- 所有主线小关（含第 4 关小 Boss 和第 5 关章末 Boss）都不再自动弹 opening/victory/defeat 剧情阅读器；关卡失败也不插入强制剧情。Boss 可以保留战内不夺控制权的台词/题字，章节收束只在结果页提供可选阅读入口。
- 章节结尾可以保留可选择阅读的章节收束，但不得阻断继续游玩；玩家可直接继续，也可稍后在江湖纪事阅读。
- 原关间内容迁移到：章节卷轴、江湖纪事、人物传记、装备典故、物品说明、地点志、敌人图鉴与待处理江湖事。
- 招募、奇遇、收降等需要玩家选择的事件进入非阻塞队列“待处理江湖事”，不在连关过程中强制弹出。
- “继续江湖”从主菜单直接定位并进入当前下一关；若玩家有未处理事件，只做轻量提示，不抢占进入战斗。
- 每章第 1–4 关的主按钮为“进入下一关”；第 5 关完成后为“进入下一章”，旁边提供“阅读本章卷轴”。下一章尚未满足硬解锁条件时，不自动绕过条件，结果页说明缺口并返回江湖地图。
- 第 105 关完成后不再显示不存在的下一关，改为“终章归档 / 返回江湖纪事”；此后“继续江湖”显示主线已尽并引导到可继续的宗门或支线内容。
- 结果按钮在结算事务成功前禁用；重复点击、应用中断和重进由 `battleSessionId + stageId + rewardGrantId` 做幂等，禁止重复发首通或把进度卡在已胜未结算状态。

叙事搬迁必须逐 ID 建 manifest，不直接删除旧资产：

| 旧载体 | 新载体 | 规则 |
|---|---|---|
| 普通关 opening | 地点志/章节卷轴“行前”段 | 玩家主动阅读，不进战斗栈 |
| 普通关 victory | 章节卷轴“此役”段/江湖纪事 | 首通后解锁，结果页不强播 |
| 普通关 defeat | 敌人图鉴提示或纪事“败闻” | 只保留有设定价值内容，不强播 |
| 章中人物独白 | 人物传记/关系条目 | 随相遇解锁 |
| 装备/物品来历 | 对应典故页 | 由获得物品解锁 |
| 章末 prologue/epilogue | 可选章节总结 | 结果页提供入口，永不阻塞 |
| 招募/收降/奇遇选择 | 待处理江湖事 | 入队并持久化，稍后集中处理 |

manifest 为每个旧 narrative ID 标记 `targetType/targetId/unlockTrigger/disposition`；`disposition` 只能是 `migrate`、`merge` 或经内容 owner 说明理由的 `archive`。完整性测试要求所有现有 opening/victory/defeat ID 恰好有一个去向，避免“取消强播”变成误删剧情。

## 2. 战斗操作、资源与技能体系

### 2.1 固定输入布局

| 输入 | 功能 | 设计定位 |
|---|---|---|
| 鼠标左键 | 普通攻击 | 武器形态驱动；可持续按住；不占技能槽 |
| `1–4` | 常用招式 | 伤害、控制、机动、防御均可装配 |
| `Q` | 战术技 | 以冷却为主，承担聚怪、破阵、防御或位移 |
| `R` | 绝技/共鸣 | 以真气为主，承担爆发、清场或关键反制 |
| `Space` | 确定性闪避 | 免费、主动、可靠；由身法改变轨迹和附加效果 |
| `WASD` | 持续移动 | 固定逻辑步采样，不依赖系统按键重复 |

`Q`、`R` 必须是完整 `SkillDef`，通过数据定义行为、冷却、真气与表现；禁止在 UI/controller 中为某一招硬编码特殊效果。

### 2.2 唯一主动资源：真气

- 战斗中只保留真气作为主动资源，不新增体力条、怒气条、弹药条、耐力条或武器耐久。
- 普攻稳定产气；多段普攻一次动作只结算一次产气，避免多段武器天然垄断资源。
- `1–4` 可以是产气、耗气或中性技能，由技能数据定义。
- `Q` 以冷却约束为主，通常低耗或不耗气。
- `R` 以真气约束为主，可叠加较长冷却但不得只靠冷却释放。
- `Space` 不消耗真气。
- 杂兵击杀可以返还少量真气，但必须设置单次动作/短时间窗口上限，防止海量杂兵让绝技无限循环。
- 所有实时冷却统一使用秒或固定 tick 对应的秒值，不再从旧 `cooldownTurns` 做模糊换算。
- YAML 和存档接口只表达秒；装配战斗快照时统一量化为 `max(1, ceil(seconds / fixedDeltaSeconds))` 个 tick，保证实际冷却不短于配置。tick rate 由同一配置注入，禁止各 adapter 自行四舍五入。
- 同一关卡内换波不重置技能冷却；短间歇仅按 fixed tick 自然推进剩余冷却。进入新关卡时按该模式的入场合同重置。当前 `preserve_cooldowns: false` 为已知 `IMPLEMENTATION-GAP`，必须修正并以跨波剩余 tick 精确断言。
- 耗气动作在起手时锁定足额真气，在首个生效帧/效果 tick 才正式扣除。生效前被打断或玩家主动取消时解锁/退还真气，但进入短暂失败冷却，禁止无代价反复试探。

### 2.3 六类首批空间/作用域合同

技能作用域扩为六类通用合同：前五类为会产生空间命中集的碰撞几何，第六类为只作用于施法者的自身状态作用域。不做“点一下伤害全屏所有敌人”的旧 AOE。六类名称已由完整会话复核，不再作为推测恢复项：

1. **前向扇形**：剑扫、刀劈、掌风等，受朝向、距离和半角约束；
2. **自身圆形**：以施法者为中心的震荡、护体、清场；
3. **目标点圆形**：在合法鼠标落点或 AI 选点处产生范围，用于聚怪、毒阵、落击；
4. **直线/胶囊形**：穿刺、剑气、飞针、冲锋判定；用长度与宽度表达，不用无限直线；
5. **位移轨迹**：突进、追步、穿身斩；沿起点到终点的路径判定并处理终点安全；
6. **自身状态**：不以敌方命中集为前提，以施法者自身为目标施加护体、格挡窗口、化解窗口、蓄势或移动修饰等状态。

前五类碰撞几何都必须定义：锚点、朝向/落点、最大距离、边界是否闭区间、最多目标、命中排序、墙体/场地边界处理、AI 选点规则和预警形状；自身状态合同则必须定义持续时间、刷新/叠加、取消窗口和效果列表。“环形”由自身圆形或目标点圆形的内/外半径参数表达，不单独占一类。首批先做通用模板，少数名招只组合参数与效果，不新增一招一套代码。

### 2.4 技能效果原语

通用效果至少包括：伤害、治疗/护盾、位移、牵引、击退、姿态伤害、踉跄、减速、定身、内伤、毒、格挡窗口、化解窗口、蓄力反击、有限反伤。复合招式由“一个几何 + 有序效果列表 + 触发条件”组成。

效果执行必须确定性排序：合法性与资源检查 → 起手 → 位移/选点 → 命中集合冻结 → 防御响应 → 伤害/姿态 → 状态 → 击杀与资源 → 表现事件。表现层不得反写领域结果。

## 3. 武器普攻与主修特性

### 3.1 总原则

- 普攻主要由“武器形态”决定，主修心法/武学流派提供修饰，不把角色永久锁成一种战斗风格。
- 旧 `normalAttack` 类型退为技能/心法修饰来源；生产普攻由装备武器形态与角色快照装配。
- 武器专属技可占用 `4` 号槽，与其他常用招式竞争，不额外增加无限技能栏。
- 战斗中不切换武器，不做弹药、耐久、耐力或连招输入表。
- 五种武器都必须既能有效清杂，也能处理单体 Boss；差异来自范围、节奏、姿态、位移和命中方式，不来自“某武器只能打杂兵”。

### 3.2 五类武器形态

#### 剑

- 普攻链：直刺 → 横扫 → 进步斩。
- 特征：范围、速度、位移和姿态伤害均衡；适合作为教学与基准武器。
- 清杂依靠横扫和进步斩的小范围串联；Boss 依靠直刺与稳定收招。

#### 重兵器（重刀、斧、锤）

- 普攻链：宽幅横扫 → 回身扫 → 下砸。
- 特征：较慢、范围大、击退和姿态伤害高。
- 下砸可制造小范围震荡，但不做全屏清场。
- 对 Boss 的优势是破姿态与打断，不是无条件高伤碾压。

#### 软兵器（鞭、链、索）

- 普攻链：长弧抽击 → 回拉 → 绕身扫。
- 特征：攻击半径大、聚拢与牵引强、近身盲区更明显。
- 对精英/Boss 的强牵引折算为较小位移或姿态伤害，避免控制失效或无限拉扯两极化。

#### 双持/奇门成对兵器

- 普攻链：快速连击 → 交叉斩 → 追步收尾。
- 每套普攻链最多触发一次追步，不能每一段自动黏敌。
- 特征：高频、短距离修位、单动作产气仍只结算一次。

#### 暗器

- 普攻链：直投 → 穿透投掷 → 扇射或一次有限弹射。
- 不消耗弹药；约束来自射程、攻击节奏、穿透/弹射目标上限。
- 需要保留近身自救方式，不能让被贴身后完全失去操作。

### 3.3 三种主修特性

- **刚猛**：增强击退、姿态伤害、破阵能力；不得单纯叠乘成最高通用伤害。
- **灵巧**：改变追步、闪避轨迹与收招恢复；不能通过无限无敌帧替代防御判断。
- **阴柔**：增强牵引、减速、内伤扩散与节奏控制；对 Boss 主要转为姿态/弱化效果。

特性只修饰合法参数和触发器，不复制五套武器代码。武器形态 × 三特性应形成十五种可感知组合，但实现上由共享普攻链与 modifier 组合完成。

## 4. 闪避、防御、反击与伤害反弹

### 4.1 主动闪避

- `Space` 是确定性、可依赖的主动闪避，不再由概率决定“按了是否躲开”。
- 旧被动闪避率改为“擦伤/偏斩”：命中时按规则减伤或降为较轻伤害，不制造攻击完全消失的随机反馈。
- 速度属性只缩短部分恢复或改善手感，不直接无限缩短无敌窗口。
- 轻功决定闪避轨迹、距离、翻越地形或特殊触发，而不是堆一个更高的闪避概率。
- 完美闪避可触发灵巧流派钩子；表现使用短促墨停、残影和音效，不做全局模拟减速，避免海量单位一起慢放。

### 4.2 三类防御技能

#### 护盾/格挡

- 为自己添加吸收量或正面减伤层。
- 群战中默认只保护正面扇区，不做无条件 360° 全防。
- 护盾值、持续时间、可挡攻击类型和破盾反馈由数据定义。

#### 化解/弹反

- 在短窗口内化解可弹反攻击，并对攻击者造成姿态伤害、击退或有限反击。
- 成功化解群体近战时可产生小范围震退，解决被围时单点反馈不足。
- 不允许反弹原始 Boss 伤害；反击伤害读取标准化攻击力/技能倍率并受上限保护。

#### 蓄势反击

- 进入短暂守势，记录合法命中或吸收量，窗口结束后释放前向或环形反击。
- 面对群怪时反击可以是范围伤害；面对 Boss 时以姿态伤害和创造输出窗口为主。
- 存储量、最大层数、触发条件和释放失败处理必须数据化。

### 4.3 反伤规则

- 可以存在“反弹伤害或技能”的招式，但只反弹被标记为可反弹的投射物/轻重攻击。
- 原始伤害反射改为标准化结果：`反击基础值 + 角色属性系数 + 技能倍率`，并受单次上限、每秒上限和 Boss 系数限制。
- 不反弹抓取、地面持续区、剧情必杀、不可阻挡攻击和环境伤害。
- Boss 高伤不能因为数值大而反杀 Boss；玩家成功防御的价值体现为无伤、姿态压制、打断或输出窗口。
- `counterDamage`、`projectileRedirect` 和其他反伤结果必须带 `nonRecursive=true`，不得再次触发反伤/弹反，防止双方无限循环。
- 标准化反击伤害默认不暴击、不吸血、不触发“受击后反伤”和附带反伤；若个别技能需要例外，必须在 typed behavior 中显式列入 allowlist 并通过上限测试。

术语分开：`projectileRedirect` 只处理带 `reflectable` 的投射物，改变阵营/所有权、重新选择合法目标并保持配置化速度衰减；`counterDamage` 是格挡/化解/蓄势后产生的标准化反击伤害，永远不复制入站原伤害。二者分别测试，UI 可以统一显示为“借力反制”但领域不能混用。

### 4.4 攻击防御标签

攻击能力不是互斥三选一，而是一组正交 flags：`blockable`、`parryable`、`reflectable`、`dodgeable`、`interruptible`。轻击可同时 `blockable + parryable + dodgeable`；可重定向投射物额外 `reflectable`；“不可阻挡”是 `blockable=false && parryable=false` 的派生预警类别，仍可按招式定义是否能闪避/打断。非法组合由 schema 拒绝。

标签通过预警形状、纹理与音效表达，不能只靠颜色。不可阻挡攻击使用破碎朱砂印/断裂边框；可化解瞬间用克制金属亮点或笔锋闪光。

### 4.5 确定性防御结算顺序

每个入站攻击必须且只能按以下顺序解析：

1. `Space` 主动闪避无敌帧/合法脱离；
2. 化解、弹反、投射物重定向；
3. 护盾、格挡和正面减伤层；
4. 基础防御、流派减伤与擦伤/偏斩；
5. HP 和姿态伤害落账；
6. 合法反击、被动触发、击杀和资源事件。

同一攻击不得因 UI、VFX 或多个 adapter 重复进入结算。结果事件必须记录命中 ID、防御分支、最终伤害、姿态伤害和反击源，用于重放与破坏证红。

## 5. 敌人语法、姿态与状态体系

### 5.1 五类攻击语法

1. **轻击**：短前摇、低压力、可格挡/化解；承担节奏填充；
2. **重击**：明显前摇、较高姿态与伤害；鼓励闪避或化解；
3. **投射物**：有飞行轨迹、错峰齐射和屏外提示；
4. **地面技/抓取**：依赖落点或近身条件，通常不可简单格挡；
5. **冲锋**：有路径预警、起点来源与终点恢复，可被正确手段打断或侧闪。

### 5.2 四种基础战术角色

- **近战杂兵**：建立包围和压迫，单体招式简单；
- **远程杂兵**：迫使玩家移动，齐射必须错峰；
- **冲锋/侧袭者**：从可读入口切入，改变站位；
- **支援/阵型单位**：号令、治疗、护盾、旗阵或增援锚点，是 AI 高优先目标。

精英不重新造一整套 AI，而是“基础角色 + 一项机制”，例如重甲、毒阵、蓄力、护卫、召援、反击。Boss 按“常规动作 → 标志招 → 玩家回应 → 破绽窗口”循环，不靠无预警秒杀或控制免疫堆难度。

### 5.3 姿态统一

把旧硬直、踉跄、破招、打断施法、霸体等零散概念统一为姿态体系：

- 领域值统一为“已累计姿态伤害”从 0 向破势阈值增加；UI 可以反向显示“剩余架势”，但不得维护第二份数值；
- 攻击同时可造成生命伤害和姿态伤害；
- `postureDamageAccumulated >= postureCapacity` 时进入短暂破绽，并按配置在破绽结束后重置/恢复；
- 霸体表示某阶段不被轻击打断，但仍可累计姿态伤害；
- Boss 所有强控制效果转为姿态伤害或阶段性交互，不允许永久免疫导致控制流派失效；
- 破招技能对蓄力窗口有额外姿态/打断效力。

### 5.4 保留与删除的状态

按运行语义拆分：

- `instantEffect`：牵引、击退、位移，不进入持续状态列表；
- `postureReaction`：踉跄、破势、倒地，由姿态累计触发；
- `timedStatus`：减速、定身、内伤、毒，定义持续、刷新、叠层、免疫与固定 tick。

删除或不再新增：沉默、缴械、致盲、混乱。旧“刚猛震慑”不做独立眩晕，改为姿态伤害。毒与内伤按固定实时 tick 结算，在线/headless 频率完全一致。

首批运行合同进一步冻结：

- 减速只修改移动速度，不改攻击、输入、防御窗口或 fixed tick；
- 定身禁止常规移动，但仍可攻击和使用防御动作；允许消耗一次合法 `Space` 脱困；
- 同来源重复施加默认刷新持续时间，不无限叠加；可叠层状态必须显式配置上限；
- Boss 面对强控时转换为姿态伤害/打断窗口，不直接吃长时间定身；
- 敌人的连续控制有递减或短免疫窗口，避免玩家无法重新获得输入权；
- 换波时清除上一波敌人来源的远程预警、投射物、地面持续区和不应跨波保留的控制；玩家 HP、真气和技能冷却依据换波合同保留。

## 6. AI、手动与离线同核

### 6.1 玩家自动战术

提供三种战术预设：

- **寻隙**：重视走位、Boss 破绽、化解和资源保留；
- **强攻**：优先聚怪、爆发和追击，承受更高风险；
- **稳守**：优先护盾、脱离危险、保持生命和打断关键招。

自动 AI 的基础优先级：生存必需动作 → 不可阻挡区脱离 → Boss 关键窗口 → 远程/支援高威胁目标 → 聚怪阈值技能 → 常规输出 → 追击残敌。AI 不读表现层，不使用玩家不可见信息。

### 6.2 同核要求

- 手动控制：键鼠转为领域 intent；
- 自动战斗：player bot 产生同样 intent；
- 差遣/扫荡/离线：headless 以更快速度推进相同 fixed tick；
- 相同角色快照、内容 seed、战术和输入序列必须得到相同领域事件与结算 hash；
- 不允许为离线另写一套“战力比较公式”绕开技能、姿态、受伤与敌人机制；
- 允许表现层不渲染、时间批量推进，但不能改变规则。

## 7. 失败、受伤与连续挑战

### 7.1 通用受伤

- 受伤依据战斗表现和风险产生，不是每次失败必伤。
- 受伤影响出战资格、恢复时间或战斗属性，但不降低输入响应速度，不把角色做得“按键迟钝”。
- 普通 Boss 战失败不扣修为，不掉装备，不回退境界。
- 同一挑战会话内多次重试只在退出/结算时计算一次伤势，防止“练习 Boss 越练越残”。
- 实际参战者承担伤势；随行听剑者、未上场角色不受伤。
- 手动和差遣使用相同伤势规则，差遣不能无风险白嫖，也不能被额外惩罚。

### 7.2 特殊模式失败

- **心魔**：失败不产生物理伤势、装备损失、境界回退或永久内力扣减，并施加有上限的内息紊乱。当前生产路径仍扣主修修炼度；其去留为 G0 `PROPOSED`，签字前不得宣称“只有紊乱”，也不得擅自修改代码。
- **断魂庄**：失败保留已击败 Boss/精英对应的部分经验或阶段收益，不给最终通关奖励。
- **远征**：保留已经完成节点的暂存奖励；未带回部分按撤退/失败规则处理，不清空整趟成果。
- **塔与普通副本**：依通用伤势结算；不使用每日次数惩罚。

## 8. 角色装配、活动占用与离线时间线

### 8.1 个人装配

- 每个角色独立保存装备、主修、`1–4/Q/R` 行为技能、自动战术与亲战/差遣方案。
- 普攻和 `Space` 不占装配槽。
- 允许为同一角色保存“亲战方案”和“差遣方案”两套技能/战术配置；二者仍需遵守已拥有技能与装备。
- 角色进入活动后锁定本次角色快照；活动中不能换装备、主修或把同一装备移给别人。

### 8.2 占用规则

- 每个角色同一时间只能参加一项主要活动。
- 即时战斗在结算后释放角色；远征、闭关、疗伤、项目等持续活动占用角色。
- 宗门共享挂机材料不能随门人数线性倍增；门人只获得小额个人成长，宗门产出由岗位/设施/路线决定。
- 宗门只有一个“当值历练”槽，用于自动刷已经手动首通的内容。
- 宗门同一时间只允许一名角色深度闭关。
- 首版远征在整个存档范围内同时最多一条 active run，与当前生产实现一致。“每路线一趟”或更高并发会改变角色占用和资源吞吐，不在本轮冻结范围内；未来如重新提案，必须先做经济模拟和存档互斥设计。

### 8.3 离线时间线

离线结算以时间片统一处理：读取离线区间 → 按活动开始/结束、伤势恢复、节点完成、资源上限等边界切片 → 各活动用同核规则推进 → 汇总宗门资源、个人成长、伤势和待处理事件 → 生成一份统一归来报告。

归来报告必须区分：谁做了什么、完成到哪、获得什么、是否受伤、为何停止、哪些事件待玩家处理。禁止给每名门人弹一个阻塞对话框。

已完成的持续项目在时间线中自动结束并释放角色回到空闲状态；结算资源和物品在幂等事务中直接入宗门账本/背包。“归来报告”只是结果摘要和待处理事件入口，不是必须点击的奖励领取按钮；应用中断或未打开报告不影响入账。

超长离线不一次构造全部 tick/event：`maxOfflineDuration`、`simulationChunkTicks`、`checkpointInterval`、`maxReportEntries` 全走配置；每个 chunk 写恢复游标和累计摘要，取消/崩溃后从最后 checkpoint 幂等续跑。相同初态和 seed 下，“连续一次推进”与“分 chunk 推进”的领域末态/hash 必须一致；报告事件超过上限只聚合展示，不丢结算账目。

## 9. 各玩法模式的最终规则

### 9.1 主线

- 21 章、105 个小关保持现有总量。
- 主线首次推进绑定当前掌门；掌门处于明确不可战状态时，首次推进暂不可进入。手动重打、自动重刷和扫荡的参与者保持 `PROPOSED`；对应记录、伤势和成长归属随 G0 决策同步冻结。
- 普通关改为连续区域或有限增援，不再用“2/3/4 个旧怪复制三波”作为最终内容。
- 胜利结果直接“下一关”；普通关不强制剧情。
- 首通给予固定解锁、真解、招募/事件推进或目标装备，不把关键唯一奖励放低概率池。

### 9.2 问鼎九霄（塔）

- 保留 49 层，层 `N` 与绝对境界层 `N` 一一对应。
- 每层独立进入、满状态开始；不做 49 层连续血量继承。
- “满状态”只重置战内生命、真气、冷却和临时状态；存档中的伤势/疗养状态不被塔入口清除，受伤角色若允许挑战也继续承受伤势修正。
- 普通层简洁、Boss 层突出机制；不是每层都塞海量杂兵。
- 七层循环模板：清剿 → 组合战 → 伏击/据点 → 小头目 → 群涌 → 生存 → Boss。
- 每层首次必须手动通过；之后允许自动、headless、当值历练。
- 无每日重置，无赛季过期。
- 任意空闲角色可挑战；个人最好记录归角色，首通唯一奖励按存档/宗门共享，不能多角色重复领取。

### 9.3 轻功试炼

- 定位为移动和场地试炼，不是“堆闪避率”。
- 目标模板包括：穿过检查点、限时存活、触碰标记、追击/拦截和抵达终点。
- 沿用同一 ARPG 移动/闪避/技能内核；轻功改变闪避轨迹、越障和场地互动。
- 首批场景语法显式包括水面、屋脊和竹林：踏水、借墙/越脊、竹林障碍只修饰合法移动与闪避，不另建一套战斗引擎。
- 杂兵只承担路线压力，数量控制在较低水平；不能把轻功关重新做成普通清场关。
- 首次手动通过，之后可自动；奖励偏向身法、闪避形态、熟练/领悟和无属性记录外观。

### 9.4 群战守城

- 仍然是一名英雄面对大规模敌群。
- 友军只作为背景战线、远景剪影和目标状态，不生成需要玩家指挥的 AI 队伍。
- 阵型改变敌人入口、包围方式、通道与推进线，不直接给玩家加百分比属性。
- 目标包括守阵、拦截、斩将；固定防御目标必须耐打并有清晰状态，不能是容易误死的护送 NPC。
- 这是范围攻击、防御技、聚怪和蓄势反击最充分的展示场。

### 9.5 心魔

- 仅本人挑战，不可替代、不可差遣、不可扫荡。
- 镜像使用本人剪影、武器形态、主修特性与代表行为，不复制玩家精确数值造成镜像失控。
- 保留现有七类心魔名称与叙事：贪（求胜心）、嗔（回望仇）、痴（执着之过）、慢（自满之态）、疑（对师父之疑）、空（无物之惧）、真（自己对自己）。不改名，不重写已有 narrative canon。
- 会话确认七关应体现七类机制考验：贪攻、愤怒/反击冲动、误判、依赖霸体/护体、犹豫、生存压力、最终自省。G0 必须建立“现有名称与叙事 → 机制考验 → 当前关卡实现 → 待开发差异”矩阵。
- 不掉普通装备/材料，奖励只服务个人突破。
- 失败不扣永久内力，不产生物理伤势，并施加内息紊乱；当前主修修炼度扣减是 G0 单独未决项。

旧稿中“贪偏强攻、嗔受击反击、痴重复追击、慢进入护体、疑使用虚招、空偏生存、真分阶段综合”仅作为 `PROPOSED` 候选，不是已冻结 AI 合同。映射必须先对照现有关卡/narrative，再逐项签字。

### 9.6 断魂庄（Boss 连战）

- 三名 Boss 连续战斗，可选择掌门或任意空闲门人。
- 生命、真气、冷却和有限补给跨场继承。
- 场间允许使用补给和切换已保存的战术方案；不能换人、换装备、换主修。
- 入场凭证不是每日票，不自然日重置、不设过期。
- 首次完整通关必须手动；通关后可 headless 重刷。
- 中途失败给已击败 Boss 对应的部分经验/阶段收益；最终奖励提供选择，不以纯随机决定核心收获。
- 不禁止祖师/掌门参与。

### 9.7 远征

- 是长时项目，可派任意空闲角色，包括掌门。
- 普通节点按时间/headless 推进；路线政策只改变路线、事件和资源权重，不直接给角色加战斗属性。
- 可随时召回；召回结算已完成节点。
- 里程碑/精英节点首次要求手动挑战，成功后未来同节点类型可自动。
- 离线遇到尚未解锁的手动里程碑时，角色自动返程并生成报告，不替玩家暗中过关。
- 不做每分钟手动点击；玩家的主要决策是人选、路线、政策、补给、召回。
- 首版全局只允许一条 active 远征，不按路线并发，不随门人数增长。

### 9.8 各模式参与与自动化真值表

“前台 bot”是可见战斗中的自动操作；“快速 headless”是不渲染战场、按同核确定性模拟后结算；“差遣”表示角色被活动占用并随时间/headless 推进；“扫荡”表示消耗扫荡战备后立即跑完一次不可见 headless 模拟并结算。四者必须分别表达，不能用一个“自动重刷”开关代替。首通门槛均按存档/内容记录，不因换角色重复领取唯一奖励。

| 内容 | 角色选择 | 首次手动门槛 | 前台 bot | 快速 headless | 差遣/离线 | 即时扫荡 | 伤势 |
|---|---|---:|---:|---:|---:|---:|---|
| 主线 | 首推固定当前掌门；其余参与者待 G0 | 是 | 已通关后可；参与者 `PROPOSED` | 已通关后可；参与者 `PROPOSED` | 当值历练参与者 `PROPOSED`；不开放普通差遣 | readiness 和参与者待 G0 | 同核；实际参与者承担 |
| 塔 | 任意空闲角色 | 每层是 | 该层首通后可 | 该层首通后可 | 首通后可当值/差遣 | 否 | 同核；实际角色承担 |
| 轻功 | 任意空闲角色 | 每路线/关是 | 首通后可 | 首通后可 | 首通后可差遣 | 否 | 通用伤势；失败重点为路线结果 |
| 群战 | 任意空闲角色 | 每关是 | 首通后可 | 首通后可 | 首通后可差遣 | 否 | 通用伤势 |
| 心魔 | 仅本人 | 永远是 | 否 | 否 | 否 | 否 | 内息紊乱；主修修炼度惩罚待 G0 |
| 断魂庄 | 任意空闲角色 | 首次完整通关是 | 模式 policy 待 G0 | 完整首通后可 | 完整首通后可差遣 | 否 | 会话末一次；部分收益 |
| 远征 | 任意空闲角色 | 仅首次关键节点 | 不适用 | 普通节点可 | 核心形态，支持离线 | 否 | 实际角色；保留完成节点 |

表中“首次手动”是自动化解锁门槛，不代表之后禁止手动重打；心魔的“永远是”表示每次挑战都必须本人手动完成。远征普通节点是时间/headless 项目流；关键里程碑首次必须手动，已通过的里程碑如在后续路线中重现，可依规则手动或自动处理，但不重复发放唯一奖励。

“差遣/离线”在此表中只为节省宽度的展示分组，不是同一个字段。typed `AutomationPolicy` 必须分开 `dispatchAllowed`、`offlineAdvanceAllowed`、`realtimeBotAllowed`、`headlessReplayAllowed` 和 `sweepAllowed`；某模式支持离线推进不自动意味它允许普通差遣。

主线扫荡以下语义已冻结：消耗既有扫荡战备；不占用真实世界时长，但在事务内使用实际参与者快照运行确定性 headless；伤势、掉落和个人成长仍走同一结算；结果以简报展示；扫荡不能推进未通关内容。扫荡是否固定掌门、掌门占用/readiness 及个人记录归属保持 `PROPOSED`。

自动化解锁 key 明确为：主线 `stageId`（存档级；首推为掌门身份，重打/自动/扫荡的个人纪录归属待 G0）；塔 `floorIndex`（存档级解锁，个人纪录另存）；轻功 `lightFootStageId`；群战 `massBattleStageId`；心魔无自动 key；断魂庄 `gauntletId + rulesVersion`；远征 `routeId + milestoneId`（存档/宗门级，实际参与者个人纪录另存）。规则版本发生实质机制变化时由 migration 明确保留或要求重新首通，不能静默清空。

### 9.9 特殊模式策略数据合同

每种模式不写进一个巨型 `switch StageType`，而是组合以下策略字段：

| 模式 | ObjectivePolicy 必填 | AutomationPolicy 必填 | Failure/RewardPolicy 必填 |
|---|---|---|---|
| 塔 | floor、七层模板位、Boss/生存阈值 | `manualFirstPerFloor`、auto/当值解锁 | 个人纪录 key、宗门首通 claim key、重复表 |
| 轻功 | checkpoints、timeLimit/surviveTicks、terrainRules、终点 | `manualFirstPerRoute`、auto route | 失败原因、路线成长、无属性记录 |
| 群战 | defend/intercept/commander、目标耐久、入口阵型 | `manualFirstPerStage`、dispatchAllowed | 固定目标失败、批量材料、阵令解锁 |
| 心魔 | themeId、mirrorBehavior、phase、个人门槛 | manual only | disorder、个人突破 claim key、noLoot |
| 断魂庄 | bossSequence、carryFields、intermissionActions、supplyLimit | manual first full clear、headless after | defeatedBossCount、partialExp、finalChoice |
| 远征 | routeId、nodeGraph、policyWeights、milestoneIds | timed/headless、manual milestone gate | stagedRewards、recall、injury、returnReason |

断魂庄场间补给只允许配置中列出的有限补给，动作顺序为“查看下一敌情 → 选择一次补给/方案 → 确认进入”；奖励选择事务用 `runId + rewardChoiceId` 防重复。远征每节点将奖励写入 run 内暂存账本，只有节点完成才入账；召回/失败/自动返程都从同一暂存账本结算。

## 10. 奖励与经济统一

### 10.1 三层奖励

1. **首通解锁**：固定、唯一、可预期；
2. **重复产出**：材料、银两、经验等可循环资源；
3. **个人成长**：实际参与者的经验、熟练、记录和伤势。

关键唯一奖励不得用低概率随机掉落。除心魔个人突破外，唯一奖励按存档/宗门共享；个人通关记录可以每角色保存。

### 10.2 手动与差遣公平

- 同一活动的手动、自动和差遣使用同一重复掉落表，不设置“手动收益 +50%”。
- 差遣的成本是占用角色和真实时间；手动的价值是推进首次门槛、直接操作与更快解决内容，而不是额外资源倍率。
- 当值历练、扫荡、离线不能突破活动本身的首通/凭证/唯一奖励边界。

### 10.3 各玩法奖励定位

| 玩法 | 首通/核心 | 重复产出 | 个人成长 |
|---|---|---|---|
| 主线 | 真解、系统解锁、招募推进、目标敌人装备 | 银两、常规材料、装备 | 经验、熟练 |
| 塔 | 固定层奖励、里程碑、凭证来源 | 残页、磨刀/晶石类材料 | 楼层记录、经验 |
| 轻功 | 身法形态/移动能力解锁 | 领悟、熟练相关资源 | 轻功记录；外观不加属性 |
| 群战 | 阵令/内容解锁 | 大宗普通材料、银两、声望 | 群战记录、熟练 |
| 心魔 | 本人突破 | 无普通刷取 | 个人心境进度 |
| 断魂庄 | 专属招式优先、命名装备选择 | 稀有强化材料 | 连战记录、经验 |
| 远征 | 路线/节点解锁 | 草药、泉水、银两、补给、凭证 | 参与者经验、远征记录 |

各玩法的已确认细则：

- **主线**：重打的定向掉落优先来自实际敌人使用的装备，守“所见即所得”；不把心血结晶、残页等高价资源全部压到主线。
- **问鼎九霄**：首领残页集齐后，同类重复掉落自动转换为领悟点或已有强化材料，不堆积无用残页；不用最低层无限刷取取代正常成长。
- **群战**：评价可记录城门耐久、漏敌和完成时间，但不乘算基础资源，防止极速清场流获得数倍经济优势。
- **断魂庄**：存档首次完整通关必得专属招式；每次完整通关在三件命名装备中选一件；三件全收集后可继续选重复装备，或改选稀有强化材料包。
- **百草岭远征**：三种路线政策保持不同身份——采药偏药草/灵泉/疗伤补给，寻迹偏遗迹/银两/特殊事件，以战养行偏经验/领悟/断魂帖；每十层等关键深度给一次固定里程碑奖励。

### 10.4 节奏资源边界

- 不为每个模式创建新货币。
- 不设置每日/每周次数、自然日刷新或过期倒计时。
- 不按通关速度、连击数、无伤等级给资源倍率，避免操作压力变成收益义务。
- 主线扫荡战备只限制已通关关卡的一键扫荡，不影响首次推进。
- 高价值内容可使用世界观凭证，但凭证来自长期玩法与掉落，不是每日领取。

## 11. 导航、解锁与信息架构

### 11.1 四个一级入口

1. **继续江湖**：直接进入当前下一主线关；
2. **宗门**：角色、调度、闭关、疗伤、远征、生产；
3. **武学与行囊**：技能、主修、装备、物品；
4. **江湖纪事**：章节卷轴、人物、地点、敌人、装备典故、待处理江湖事。

设置、退出、资源总览放在角落工具区，不挤占一级玩法入口。

### 11.2 江湖地图

- 所有野外内容以世界地点出现，不做抽象“副本大厅”。
- 地点面板统一显示：进度、推荐境界、敌人生态、核心奖励、参与者、亲战/差遣选择、预计占用。
- 心魔不出现在主菜单或地图，入口放到角色突破页面。
- 顶部“宗门行止”摘要显示掌门状态、门人占用、远征/断魂庄进度和已完成报告。

### 11.3 渐进解锁（首版建议）

- 开局：继续江湖、角色、行囊；
- 第 1 章：听闻九霄塔；
- 第 2 章：开放轻功试炼；
- 获得首名门人：开放差遣与门人调度；
- 约第 4 章：开放群战；
- 第 6 章且已有门人：开放远征；
- 获得第一张断魂庄凭证：开放连战；
- 角色达到个人突破门槛：开放该角色心魔。

未听闻内容完全隐藏；已听闻未开放显示传闻剪影；开放时只出现一次蜡封/题签，不保留永久红点。

## 12. 杂兵生态与刷怪爽感

### 12.1 当前问题

现状主要把旧关卡敌人复制为低血低攻的 2/3/4 人三波，能够证明 Phase 0A 生产流程，但不能形成海量杂兵生态：敌人角色同质、同时在场少、波次切割明显、没有目标优先级、没有阵型与场景入口，也无法支撑群战清场的爽感。

最终目标不是让所有敌人同时堆在屏幕上，而是“总量大、同时活跃受控、进入方式可读、击杀连续、危险公平”。

### 12.2 四个敌人层级

- **杂兵**：低生命、简单动作、成组出现、快速死亡反馈；
- **专职兵**：远程、冲锋、支援等明确角色；
- **精英**：基础角色 + 一项机制，拥有名字/姿态；
- **Boss**：独立循环、阶段、破绽和顶部 HUD。

### 12.3 各模式数量预算

| 模式 | 单关总量 | 同时活跃目标 | 说明 |
|---|---:|---:|---|
| 主线普通关 | 25–50 | 8–16 | 连续区域/增援，不全在一屏 |
| Boss 前置 | 15–30 + Boss | 6–12 | Boss 出场前清理或压缩残兵 |
| 塔普通层 | 15–35 | 8–14 | 依七层模板变化 |
| 轻功 | 8–18 | 4–8 | 敌人服务路线压力 |
| 群战 | 60–150 | 18–24 | 前景实体 + 背景剪影 |
| 远征里程碑 | 20–40 | 8–14 | 首次手动节点 |
| 断魂庄 | Boss + 0–4 | 1–5 | 只在 Boss 机制需要时带随从 |
| 心魔 | 1 | 1 | 纯个人镜像 |

下一批敌人通常在当前活跃组剩余约 20%–30% 时从场景入口补入，形成不断流的击杀节奏。具体阈值走配置，不在 Dart 写死。

### 12.4 攻击令牌与公平性

- “同时在场数量”和“同时攻击数量”分离。
- 近战同时获得攻击令牌的单位通常为 2–4 个，其余围堵、换位、蓄势或等待。
- 远程齐射错峰；支援技能错开；冲锋有独立入口和屏外预警。
- 敌人不在玩家脚下凭空生成；入口必须可见或有预警。
- 新敌人出生后有短暂可读的入场/攻击宽限，不得在首个可见帧就命中玩家。
- 屏幕外的敌人不得启动会直接造成重伤、抓取或大幅姿态伤害的攻击；已起手后离屏的攻击必须保留边缘方向、威胁类型与声音提示。
- 默认同时最多只允许一个不可阻挡的大范围攻击进入生效窗口；如需叠加，必须为 Boss 显式机制并通过人工可读性验收。
- Boss 追踪攻击必须在命中前的明确时点停止追踪，标志招后给出可识别的收招/破绽窗口。
- 单位需要最小间距、软推挤和玩家可读口袋，避免模型完全重叠。
- 背景剪影只制造战争规模，不参与真实碰撞、伤害、掉落和 AI。

### 12.5 掉落和击杀反馈

- 杂兵不逐只掉落物和弹窗；按遭遇/区域统一结算。
- 连续击杀可显示“连斩/清剿进度”，只作为视觉与记录，不给资源倍率。
- 杂兵死亡快速散墨并允许同一攻击合并墨浪；专职兵有武器/旗帜破碎；精英更重；非致死叙事敌人用撤退替代尸体。
- 不保留大量尸体物理对象。

## 14. 七类关卡遭遇模板

七模板是内容组合，不是领域层仅有的七个硬编码枚举。底层目标原语为：`defeatTargets`、`destroyAnchors`、`defendEntity`、`surviveDuration`、`reachCheckpoint`、`touchMarkers`、`pursueTarget`、`defeatCommander`。主线七模板、塔七层循环、轻功检查点和群战拦截都由这些原语组合，特殊模式不需要再造第二套胜负系统。

| 模板 | 必填字段 | 胜利 | 失败/超时 | 残敌处理 |
|---|---|---|---|---|
| 破路 | zones、requiredTargetsPerZone、exitCheckpoint | 完成区域并到达出口 | 玩家失败 | 非必要残敌撤退/不追入下区 |
| 伏击 | triggerVolume、entrances、warningTicks、groups | 击败伏击主力/头目 | 玩家失败 | 清理仍持攻击令牌者后终局 |
| 据点 | anchorIds、spawnCaps、commanderId? | 锚点全毁或头目被斩 | 玩家失败；无无限超时 | 锚点停刷，余敌撤退或限量清理 |
| 追击 | checkpoints、targetRoute、delayGuardGroups | 抵达终点并处理目标 | 玩家失败；慢不直接判负 | 延误只增加有限护卫 |
| 守阵 | entityId、durability、duration/attackers | 时限到或敌主力败 | 目标耐久归零/玩家失败 | 时限到停止生成并撤离残敌 |
| 生存 | duration、pressureProfile | 时间到立即成功 | 玩家失败 | 立刻停止生成，残敌退场 |
| 斩将 | commanderId、requiredAdds? | 头目败且必要机制随从处理 | 玩家失败 | 非必要随从随头目败退 |

### 14.1 破路

- 连续经过 2–3 个区域，清出道路；不弹传统波次横幅。
- 区域剩少量敌人时下一入口开始补兵，保持连续推进。

### 14.2 伏击

- 敌人从前后或上下层入口出现，但必须有环境、脚步、尘土或朱砂预警。
- 不允许首次游玩无提示贴脸包围。

### 14.3 据点

- 摧毁/压制有限的增援锚点；锚点数量和刷新上限固定。
- 玩家可以直接斩首支援单位缩短战斗；不做无限刷怪。

### 14.4 追击

- 追赶目标、穿越检查点；未在最短时间追上不直接判失败，而是让目标获得额外护卫或更有利位置。
- 避免硬计时导致剧情关卡卡死。

### 14.5 守阵

- 保护固定阵眼、城门、火盆等耐久目标。
- 目标足够稳健，失败来自长期失守而不是一只杂兵瞬间误触。

### 14.6 生存

- 在规定时间内承受压力；时间到立即进入胜利/撤离流程，不强迫清理最后几只残兵。
- 奖励不按击杀数线性增长，避免刷无限增援。

### 14.7 斩将

- 围绕精英/Boss 的干净战斗；必要随从数量有限。
- 重要决斗保持稀疏，不为了“海量”破坏武侠对决气质。

## 16. 战斗表现、HUD 与可读性

### 16.1 信息优先级

玩家本体、危险区、不可阻挡提示 > Boss、精英、支援单位 > 普通杂兵和技能特效 > 背景剪影。

### 16.2 头顶信息

- 杂兵：默认无名字、无常驻血条；
- 专职兵：角色图标，受击时出现细血条；
- 精英：名字、生命、姿态；
- Boss：顶部 Boss 条，不在头顶重复一套完整 HUD。

### 16.3 镜头

- 普通横版战斗使用水平安全区/死区跟随。
- 群战镜头稍宽，Boss 战稍近；不播放强制入场镜头打断操作。
- 不为每只杂兵受击震屏；同帧/短窗口震动合并，重击、破势、Boss 警告拥有更高优先级。

### 16.4 伤害数字

- 普通群怪按一次攻击聚合显示“总伤害 + 命中目标数”；
- Boss/精英保留独立数字；玩家受到的伤害最高优先；
- 毒/内伤按短窗口聚合；
- 屏幕常驻伤害数字控制在约 6–8 组；
- 聚合不能掩盖“是否命中、是否格挡、是否破势”的语义。

### 16.5 屏外威胁

只为冲锋、远程蓄力、支援单位和 Boss 显示屏外提示；同时最多三个方向。提示包含方向、攻击类型和临近程度，不为普通追路杂兵制造满屏箭头。

### 16.6 HUD 布局

- 左下：角色头像、生命、真气、伤势/关键状态；
- 右下：普攻提示、`1–4/Q/R/Space` 状态；
- 顶部：Boss 信息；
- 左侧：本关目标；
- 右侧：清剿/生存/据点进度。

连续普通关取消大幅“第 N 波”横幅，用入口尘土、号角、旗影等环境信号表达增援。

### 16.7 角色辨识与遮挡

- 玩家使用克制青色脚环、白墨外轮廓和被遮挡时的剪影；
- 敌人与玩家重叠时适度降透明/压暗；
- 不依赖高饱和发光描边。

### 16.8 LOD 与无障碍

- 玩家、Boss、精英使用完整动画和特效；普通杂兵简化帧与粒子；远景只用剪影。
- 设置允许降低特效密度、背景人群、震屏和闪光，但不能减少真实敌人数、改变攻击令牌或降低难度。
- 音效按命中数量分组播放；Boss 警告优先级最高，避免 20 个命中音叠爆。

### 16.9 战后江湖纪事

单角色战斗不再输出旧队伍成员对比。战后摘要最少保留：击杀数、破势次数、破绽期伤害、最高单击、承受伤害、各技能使用次数、完美闪避/化解和越阶获胜记录。普通战斗默认显示精简版，详细纪事可主动展开；统计来自领域事件或结算快照，不从动画/VFX 反推。

### 17.3 需要新增或扩展的领域模块

建议在 Phase 0A 领域层形成以下稳定边界，实际文件可按现有命名细化：

1. `combat_geometry`：六种几何、选点、边界、命中排序；
2. `action_timeline`：起手、命中、收招、取消窗口；
3. `defense_resolution`：格挡、化解、不可阻挡、反击、反伤上限；
4. `posture`：姿态伤害、恢复、破势、霸体与 Boss 转换；
5. `status_effects`：保留状态的固定 tick 与叠加规则；
6. `spawn_director`：遭遇阶段、入口、活跃上限、补兵阈值；
7. `attack_token_director`：近战/远程/冲锋/支援并发动作预算；
8. `encounter_objective`：八个目标原语及破路、伏击、据点、追击、守阵、生存、斩将等组合模板；
9. `participant_snapshot`：掌门/门人装配、状态、实际参与者；
10. `activity_occupancy`：角色占用、锁装、互斥、完成/召回；
11. `battle_presentation_feed`：领域事件到 VFX/SFX/HUD 聚合的单向映射。

生成、目标与后备敌人不要继续塞进已经高耦合的单拍 reducer。建议结构为：

```text
Phase0aEncounterFlow
├── ObjectiveController
├── SpawnDirector
├── AttackTokenCoordinator
├── ActiveEnemySet
├── ReserveEnemyQueue
└── Phase0aCombatSession → reducePhase0aTick()
```

reducer 只处理一拍内的移动、动作、防御、伤害、姿态和状态；EncounterFlow 管理场外队列、进入点、目标状态与终局。现有 `Phase0aWaveBattleFlow` 只在迁移期服务 `legacy` allowlist；`legacyStageCount == 0` 后产品入口引用必须归零并删除。若个别测试仍需旧波次，只能留 test fixture adapter，不能作为存档兼容或生产回退。

参与者入口统一为显式请求，禁止 assembler 自行猜掌门：

```text
ActivityParticipationRequest
- contentId / contentKind / characterId / loadoutPlanId
- participation: direct | dispatch
- controller: human | playerBot
- clock: realtime | headless
- entryKind: firstClear | replay | sweep | offlineResume
```

所有入口通过唯一 `CharacterAvailabilityService` 检查存活、主修、伤势、闭关、远征、断魂庄、当值、本人专属、亲战/差遣允许矩阵。

### 17.4 数据层建议

不要把所有内容继续塞进 `stages.yaml` 和 `enemies` 数组，也不要让十几个外部执行端争抢巨型 `stages.yaml`、`towers.yaml`、`skills.yaml`。建议先新增覆盖层，通过稳定 ID 与原进度数据联结：

```text
data/combat/
├── enemy_archetypes/
│   ├── bandit.yaml
│   ├── army.yaml
│   ├── sect.yaml
│   ├── xiliang.yaml
│   ├── poison.yaml
│   └── temple.yaml
├── encounters/
│   ├── mainline/chapter_01.yaml ... chapter_21.yaml
│   ├── tower/group_01_07.yaml ... group_43_49.yaml
│   ├── light_foot.yaml
│   ├── mass_battle.yaml
│   ├── inner_demon.yaml
│   ├── gauntlet.yaml
│   └── expedition.yaml
├── action_behaviors/
│   ├── weapon_forms/sword.yaml
│   ├── weapon_forms/heavy.yaml
│   ├── weapon_forms/flexible.yaml
│   ├── weapon_forms/dual.yaml
│   ├── weapon_forms/hidden.yaml
│   ├── defensive_actions.yaml
│   └── skill_behaviors.yaml
├── activity_rules.yaml
├── reward_profiles.yaml
└── presentation/
    ├── telegraphs.yaml
    └── crowd_lod.yaml
```

`stages.yaml` 暂留关卡 ID、章节、推荐境界、场景、进度与历史叙事引用；新 encounter 覆盖层按 `stageId` 联结。每个生产战斗关必须恰好一个 encounter；未知 stage/floor、未知 archetype、目标参数不自洽、总量/活跃/攻击令牌越界均 fail-fast。

权威读取顺序不是永久双真相源：新 `data/combat/encounters/**` 是战斗编排唯一权威，`stages.yaml` 的旧 `enemyTeam` 只在迁移期 allowlist 中作为 fallback。版本化 resolver 为每关标记 `migrationState: legacy | migrated`：`migrated` 必须有且只有一个 encounter，`legacy` 必须在显式 allowlist 并走旧 adapter；两条路径同时有效或状态/内容不一致立即报错。每迁完一批从 allowlist 移除。M7 完成条件为 `legacyStageCount == 0`、生产不再消费旧复制扩波；历史字段何时物理删除另立兼容任务。

所有新 YAML 必须有 typed def、fail-fast schema、唯一 ID、引用完整性和红线测试。现有文件是否真的拆分，以减少冲突和加载成本为准；原则是“公共 schema 先冻结，内容分片后并行”。

### 17.5 技能槽、武器形态与冷却迁移

- `EquipmentDef` 增加数据层 `weaponForm`；装备实例不重复持久化可派生形制。
- 新战斗装配使用 `combatSkillId1..4`、`tacticalSkillId`、`ultimateActionSkillId`，旧七槽只在一个迁移周期内读取，不再作为新 UI 的命名基础。
- 旧 `ultimateSkillId` 优先迁入 R；合法 `keySkillId` 优先迁入 Q；其余主攻/辅助/奇遇/共鸣按确定顺序填 1–4并去重。
- 不符合新槽位 behavior 或缺失配置的技能进入“待整备”；自动补位必须同阶、同流派、合法并写迁移报告，不能静默丢招。
- `SkillDef` 增加并最终强制 `cooldownSeconds`。先冻结秒数映射规则，再允许外部工具机械补数据；UI、百科、AI、Q/R、1–4 全部改读秒。
- Phase 0A 禁止继续使用 `cooldownTurns × 攻击秒数`；旧字段在所有生产读方归零后才退役。

### 17.6 存档影响

优先把纯战斗配置留在 def 层，避免不必要存档迁移。确需持久化的新增状态包括：

- 每角色亲战/差遣装配方案；
- 角色当前主要活动与锁定快照引用；
- 每活动首次手动通关/自动解锁；
- 每角色个人记录；
- 宗门共享唯一奖励领取；
- 远征暂存节点、召回与离线停止原因；
- 待处理江湖事队列；
- 可选章节纪事已读状态。

迁移要求：旧档默认生成安全装配；旧全局阵容只用于推导门人调度初值，不恢复 3v3；未知/退役状态 fail closed 或按明确兼容策略忽略；每个迁移版本有低版本、边界版本、重复启动幂等和部分数据缺失 fixture。

迁移 fixture 还必须覆盖：活跃远征、活跃断魂庄、闭关人物、活动锁定装备/心法、重复技能、缺旧槽、境界不合法技能、旧塔 49 层进度、旧主线 105 关进度和旧心魔进度。旧状态沉默/缴械/致盲/混乱允许迁移层读取历史战报，但新 Phase 0A 不消费。

### 17.7 主线连续流程与失败策略

把当前长 `stage_entry_flow` 拆成清晰职责：

```text
MainlineRunCoordinator（外层循环，不递归堆 Navigator）
├── BattleLauncher
├── SettlementPipeline（进度、奖励、唯一领取、成长事务）
├── FailurePolicyResolver
├── PostBattleEventQueue（招募/奇遇/收降入队）
├── VictoryResult
└── ContinueDecision: nextStage | backToMap
```

“下一关”必须发生在结算事务成功以后；不能为追求快而丢掉奖励、首通和解锁。失败统一由 `FailurePolicyResolver(contentKind, participantId, sessionId, failureReason, performanceSnapshot)` 返回 injury/disorder/partialReward/noPenalty，移除主线 Boss 的旧式散功口径。挑战会话用 `sessionId` 保证多次重试只结一次伤势。

`sessionId` 从第一次进入挑战到玩家胜利、主动退出、返回地图或应用恢复后明确结算为止；崩溃恢复读取未完成 session，先重放/核对结算幂等键，再允许新 session。伤势输入至少记录剩余生命比例、承受重击/不可阻挡次数、倒地/被破势次数、主动退出与内容危险档；具体权重在 M0/M2 模拟中定标。

`MainlineRun` 必须保留幂等的 run/session 身份和每关结算快照，但“是否锁定 `leaderId + loadoutSnapshotId`”、“连续关卡间是否允许换装”、“伤势达到何种程度中断推进”均为 G0 `PROPOSED`。在拍板前，外层协调器只实现可替换的 policy 接口，不在存档或 UI 写死。结算、唯一奖励和待处理事件使用同一事务或 outbox：进度/奖励提交后 outbox 必可重放，事件消费幂等；测试在每个写入边界模拟崩溃。

## 19. 大规模并行开发组织

### 19.1 总体模型

采用“一个主调度窗口 + 一个集成主审 + 多个隔离执行端”的星型结构。并行不是同时改同一文件，而是在公共契约冻结后，把内容、测试、局部实现和资产拆到互不重叠的任务包。

本阶段不以 token/调用量为调度约束，不设置用量节省型暂停点；仍以 Git 冲突面、机器 CPU/内存、Isar 文件锁、视觉窗口锁和主审吞吐作为真实并发约束。未经 preflight 确认的外部工具只进入候选队列，不在方案里假设它已正确安装或已获得仓库权限。

角色建议：

- **Codex 主窗口**：维护总方案、依赖图、任务队列、状态总账、视觉验收和最终覆盖率；
- **Claude Code/Opus 主审**：核心架构、schema、数值/存档决策、跨切面实现、逐分支合并 Gate；
- **Qoder**：边界明确的纯 Dart 模块、机械迁移、局部 feature、性能 fixture、测试补齐；
- **DeepSeek**：冻结 schema 后的批量 YAML、章节/塔矩阵填充、文案分类搬迁、测试样例生成、静态审计；
- **其他外部工具**：资产提示词、视觉变体清单、独立审查或数据校验；默认只产补丁/报告。

任何工具都不能仅凭“它说完成了”进入主分支。主审必须看真实 diff、生产接线、测试证据和残留风险。

### 19.2 权限边界

外部执行端允许：

- 在独立 worktree/分支内编辑任务包允许的文件；
- 新增针对性测试、数据分片和计划文件；
- 运行本地 format/analyze/targeted tests；
- 生成待审资产或文案候选。

外部执行端禁止自行决定：

- 核心架构、公共 schema、存档版本与迁移策略；
- 数值硬红线、经济倍率、Boss 生命上限和伤害公式；
- 三系锁死、在线=离线、首次手动门槛等产品红线；
- 新货币、每日/每周/体力/抽卡等系统；
- 删除大量文件、重写历史、强推、直接合主分支；
- 在任务包之外顺手重构。

外部执行端还必须遵守：不把源码、存档、密钥或未公开资产上传到未经授权的网络服务；不自行升级依赖；不提交生成物、截图、日志和临时 capture；不修改 `GDD.md`、`CLAUDE.md`、`PROGRESS.md`，除非任务包明确指定它为该文档的唯一 owner。

### 19.3 分支与 worktree

- 每个任务一个独立分支和 worktree；统一使用 `codex/<phase>-<task-id>-<slug>` 前缀，执行工具写入任务元数据而不是改分支规范。
- 分支从主调度指定的冻结 commit 创建，不允许自行从过时基线开工。
- 依赖公共 API 的任务在 API 分支 `[READY]` 且主审冻结后再创建；不复制猜测中的接口。
- 每完成一个可独立验证的小切片提交一次；提交信息用中文动宾。
- 最终 tip 使用 `[READY] <摘要>`；需要用户决策用 `[BLOCKED] <问题>`；其他均视为 WIP。
- `[READY]` 后不得继续提交；如需返修，先回到 WIP，完成后重新打新的 `[READY]`。

### 19.4 标准任务包

每个任务必须有 `docs/superpowers/plans/<date>-<task-id>-<slug>.md`，至少包含：

```text
taskId / milestone / priority / owner / tool / model
goal / playerVisibleOutcome / nonGoals
baseCommit / branch / worktree
prerequisites / wakeCondition / downstreamTasks
readFirst（含 rejected_task_registry）
ownedFiles / fileWhitelist / forbiddenFiles
frozenContracts / schemaVersion / ID registry
inputs / expectedOutputs / productionWiring
implementationSlices / recoveryPoint
TDD red evidence / destructive mutation red evidence
targetedCommands / expected pass counts
determinismSeed / performanceBudget / visualViewports
redlineImpact / saveMigrationImpact / rejectedRegistryCheck
stopConditions / escalationQuestion
handoffEvidence / residualRisks
READY or BLOCKED tip format
```

推荐 tip：`[READY][QODER][M2-T04] 完成山匪冲锋职责`。计划文件自报“完成”不是就绪信号，只有 `[READY]` + worktree 干净才进入主审。

任务包分两档：核心/存档/数值/跨切面任务使用上面的完整模板并提供破坏证红；纯资产、单章节 YAML、文案搬迁等低风险内容包可用精简模板，只保留基线、owner、文件白名单、冻结 schema、validator/targeted 命令、恢复点、风险和 READY。不能为了流程完整让大量执行端都写无价值的长文档。

权威路径在 M0 建立并固定：已否/暂缓方向读取 `docs/spec/rejected_task_registry.md`；本轮决策与字段版本写入 `docs/dispatch/phase0a_overhaul/decision_registry.yaml`；任务 ID、owner、基线、依赖和状态写入同目录 `task_registry.yaml`。只有主调度可以改两个 registry；执行端通过任务计划引用，不自创 ID。

### 19.5 并发梯队

| 阶段 | 动态 WIP 原则 | 适合并行的工作 | 必须串行的瓶颈 |
|---|---|---|---|
| M0 | 以独立只读证据包和主审可处理量为上限 | 现状证据、基线、schema 草案、测试设计 | 用户决策与最终冻结 |
| M1 | 同一公共合同一个 owner，其他任务等待 READY | 几何、姿态、防御、状态、spawn、typed defs 的互斥分片 | reducer 事件序与公共模型合并 |
| M2 | 以黑风岭集成和真人验收吞吐为上限 | 山匪敌包、五关数据、HUD、VFX、测试 | 纵切总集成与试玩 |
| M3–M4 | 只开放已冻结 schema 且文件白名单互不重叠的任务 | 武器、特性、AI、生态包、模板、资产 | 公共 schema/数值审批 |
| M5–M6 | 每个模式一个 owner，公共占用/迁移单线 | 特殊模式、导航、叙事、调度的独立切面 | 存档迁移与活动占用核心 |
| M7 | 由实际工具可用性、owner 冲突和主审验收吞吐动态控制 | 章节、塔、数据、文案、资产、画像 | 每批集成与全内容验证 |
| M8–M9 | 以发布候选单一基线和验证机器资源为上限 | 平台、性能、视觉、迁移、审计 | 发布候选冻结 |

不在方案中承诺固定数量的执行端。主调度每批在开工前根据实际可用工具、文件 owner、CPU/内存/视觉窗口锁和尚未审核的 READY 积压计算 WIP 上限。只要两个任务需要修改同一公共文件，就不能同时写；应先把总文件拆成可组合分片，或由单一 owner 串行合并。

### 19.6 热点文件与资源锁

以下现有热点必须单一 owner，先提取接口再开放并行：

| 热点 | 原因 |
|---|---|
| `phase0a_combat_reducer.dart` | 单拍确定性与事件顺序核心 |
| `phase0a_combat_model.dart` | Actor/State 公共契约 |
| `phase0a_stage_content_mapper.dart` | 所有模式装配高耦合 |
| `phase0a_battle_screen.dart` | 输入、HUD、焦点、反馈混合 |
| `stage_entry_flow.dart` | 结算、剧情、奖励、招募钩子混合 |
| `main_menu.dart` / 入口路由 | 顶级导航与解锁 |
| `numbers.yaml` / schema / save migration | 数值与兼容 choke point |
| `UiStrings` / ID registry / `pubspec.yaml` | 全仓共享索引 |
| `GDD.md` / `CLAUDE.md` / `PROGRESS.md` | 设计、操作、进度真相源 |

机器资源也要加锁：同一台 Mac 同时最多一个全量 `flutter test`、一个 `build_runner` 集成任务、一个真窗口视觉抓图任务。其余执行端只跑 targeted；“不考虑用量”不等于可以让 CPU、Isar、端口和截图窗口互相污染。

### 19.7 合并列车

每个批次按固定顺序：

1. 公共契约/typed def；
2. 领域实现；
3. application adapter/生产接线；
4. 数据内容；
5. presentation/资产；
6. 迁移与文档；
7. 批末全量验证。

每合一个分支按以下列车运行：扫描 `[READY]` + clean → 校验 base/tip/白名单/恢复点 → 独立语义审 diff → 主审复跑 targeted → 至少一条破坏证红或反例 → 临时 integration worktree `--no-ff` 合入 → analyze → 批末全量 → 双视口/性能/存档 Gate → 文档同步 → integration `[READY]` → 合主线并清理。

外部端报告的测试数字必须在当前 integration 基线重跑。base commit 漂移或公共契约变化后，旧报告自动降级为 stale，不能拿旧绿结果给新基线签字。

### 19.8 外部输出安全

- Qoder/DeepSeek 生成的补丁按“不可信但可用的候选”处理。
- 先查看 diff 和文件范围，再运行 formatter、schema validator、targeted tests；不得先合后看。
- 外部审查报告先证伪，不能直接变成修复清单。
- 大批 YAML 先跑解析、ID 唯一、引用完整、红线、内容计数，再运行模拟画像。
- 文案候选检查是否改变 canon、是否把已搬走的关间文字重新强制弹出、是否在 Dart 硬编码。
- 资产检查透明边、尺寸、安全区、命名、无水印/乱码、色彩与低特效降级。

### 19.9 恢复与失败处理

- 每个任务计划实时维护“当前恢复点：状态、最后完成、下一步、验证、阻塞”。
- 测试失败、依赖变化、上下文即将中断或需要用户拍板时，先提交安全小片或记录恢复点再停。
- 公共 API 变更后，受影响分支全部标记 stale，由主调度决定 rebase/重派；不允许执行端各自猜修。
- 合并引发回归时优先 revert 单个可识别合并提交或暂停合并列车；禁止 `git reset --hard`、禁止覆盖用户未提交改动。
- 每个里程碑保留 tag/冻结 commit、测试报告和已知风险，可从最后一个绿色点续跑。
- 外部代理挂死或只交半成品时，将其分支冻结为 quarantine，主窗口决定续跑、缩小任务或 clean-room 重做，不在原 worktree destructive reset。
- integration 合并失败时废弃临时 integration worktree，从上一个绿色冻结点重建；不让 `main` 停在半合并态。
- flaky 与语义失败分账；只有隔离 flaky 时临时 `-j1`，不把串行全量当常态。

### 19.10 分层质量 Gate

- **G0 决策**：本方案覆盖完整、已否清单无冲突、未决参数已列入 M0；
- **G1 契约**：schema/API/ID/存档迁移冻结；
- **G2 纵切**：黑风岭从生产入口可玩，不是 debug/demo；
- **G3 同核**：manual/bot/headless/dispatch/offline 同规则、同 seed 可复现；
- **G4 密度与性能**：目标敌量、攻击令牌、Mac 正式画面过线；
- **G5 内容与经济**：引用、奖励、唯一领取、红线、21 章/49 塔计数；
- **G6 UX/视觉**：双视口、semantics、focus、鼠标、可访问性、信息优先级；
- **G7 发布**：全量、旧档、Windows 正式内容实机、双架构构建与文档收口。

## 21. 测试与验收体系

### 21.1 领域确定性

- 六几何边界、零向量、闭区间、命中上限、排序；
- 同 seed、同输入的 event 序列/hash 一致；
- 手动 adapter、bot、headless 使用同一 reducer；
- 多段动作只产一次真气；击杀返气上限；
- 格挡/化解/不可阻挡矩阵；闪避 → 化解/反射 → 护盾 → 基础减伤 → HP/姿态 → 反击的顺序精确断言；
- 反击/反射不递归，默认不暴击/吸血/触发附带反伤；Boss 反伤上限；
- 姿态、霸体、破势、打断的状态机；
- 减速只影响移动；定身保留攻击/防御并可消耗 `Space` 脱困；Boss 强控转姿态；同源刷新和控制递减；
- 毒/内伤固定 tick 在线离线一致；换波清理旧敌人场效，但保留玩家 HP/真气/冷却合同；
- 同关换波剩余冷却精确保留并在间歇递减；新关卡入场按 policy 重置；
- spawn 与攻击令牌不因渲染帧率改变。
- 自动模式比较采用同 seed、同角色快照、同 bot 版本/战术产生的 intent 序列；手动与 bot 结果不要求相同，但同一录制 intent 重放必须得到相同 event/hash。

### 21.2 内容与数据

- 105 主线、49 塔数量守卫；
- 21 章模板矩阵精确守卫；
- 每个关卡模板、生态包、奖励、场景引用存在；
- 24 逻辑角色和目标美术变体覆盖；
- 所有攻击拥有防御标签与预警；
- 新敌人入场宽限、屏外重击禁止、同时大范围不可阻挡上限和 Boss 追踪停止点均有生产画像；
- 所有首通唯一奖励只可领取一次；
- 无新日常货币、每日/每周/过期字段；
- 数值红线、三系锁死、技能倍率与 Boss 生命上限继续通过。
- 所有生产入口静态/运行守卫确认无 3v3 路由、runner 或队友 fallback；兼容枚举不得被生产消费。
- `cooldownTurns` 的 Phase 0A 生产读方计数归零；十五种武器形态 × 主修特性组合都有清杂/精英/Boss 合法画像。
- 105/105 主线 opening/victory/defeat 不再被普通战斗流强制 push；搬迁 manifest 无孤儿、无重复目标。

### 21.3 流程测试

- 主线胜利 → 结算 → 下一关，无剧情阻塞；
- 章节结束：继续与可选阅读均可达；
- 事件加入待处理队列，不抢占战斗；
- 掌门空闲/闭关/远征/重伤的参与资格；
- 门人亲战与差遣；同角色双重占用拒绝；
- 塔/轻功/群战/断魂庄/远征的首次手动与后续自动；
- 心魔不可替代/差遣；
- 心魔失败不扣永久内力，内息紊乱受上限；主修修炼度按 G0 签字结果精确断言；
- 断魂庄跨场状态与失败部分奖励；
- 远征遇未解锁里程碑自动返程；
- 无论路线和人选如何，第二条 active 远征一律拒绝；
- 离线归来报告合并多个活动。
- 同一挑战 session 多次重试只结算一次伤势；崩溃恢复和重复提交不重复奖励/伤势。
- 活动中换装被拒绝；同一件锁定装备不能被另一角色并发使用；离线切片跨活动边界幂等。
- 同内容亲战/自动/差遣引用相同 reward profile；同条件和同领域结果时奖励明细完全相等。
- hidden/heard/open、一次性蜡封、无常驻红点、入口直达和锁定回退全部可达。

### 21.4 UI 与视觉

- 1280×720、1440×900 两个常规桌面视口；
- 键盘 focus、`Space`、`1–4/Q/R`、鼠标持续普攻、语义与 cursor；
- 8、16、24 活跃单位下 HUD 不被遮挡；
- Boss 条不重复、杂兵无常驻血条；
- 屏外提示最多三个方向；
- 伤害聚合不遮蔽危险区；
- 低特效不改变真实单位与难度；
- 战后纪事能准确显示击杀、破势、破绽期伤害、最高单击、承伤、技能使用和越阶获胜；
- 无矩形高饱和默认 Material 感，无强制教程弹窗。

### 21.5 性能 Gate

先在 M0 记录当前硬件基线，再用相对回归与目标预算双守：

- 复用现有 `BattleFrameProfile` 指标：正式 profile 场景 `p99(totalSpan) < 16.6ms`，不得连续 2 帧 `totalSpan > 33.3ms`，build/raster 连续超预算均少于 3 帧；
- 普通主线分别测 8/12/16 活跃，塔测 14，群战测 18/24；另测总敌 50 与 150 的持续补兵；
- 每档在 1280×720、1440×900 运行真实 HUD、伤害聚合、死亡散墨、屏外警示与背景剪影；Profile 模式预热后至少 60 秒、3 次有效 run；
- 关闭背景人群和降低特效应显著降低渲染成本，但领域结果 hash 不变；
- headless 吞吐记录每秒模拟 tick/场次，并设置相对主线基线的回归阈值；
- 长时间群战检查 RSS 冷却后不单调增长，事件列表、反馈池、VFX、伤害数字、尸体和音频实例有界；
- Mac 双视口和 Windows 发布候选都跑生产内容，不以 debug fixture 代替。

以上绝对帧预算是目标线；若当前发布硬件基线无法达到，M0 必须记录真实数据并由用户决定最低配置/画质目标，不能通过减少真实敌人数偷偷改变玩法。

### 21.6 批末 Gate

每批执行：format → `flutter analyze` 0 issue → targeted tests → 批末一次 `flutter test --no-pub` → 常规视口 visual smoke → 存档迁移（如触及）→ 生产路线 smoke → 更新 PROGRESS 四态（已完成/已验证/已知风险/下批建议）。

## 22. 关键风险与控制

| 风险 | 后果 | 控制方式 |
|---|---|---|
| 公共 schema 未冻结就批量填内容 | 大量返工、冲突 | M0/M1 Gate 后才开放 M7 |
| 海量敌人等于海量同时 AI | 掉帧、不可读、不公平 | 总量与活跃分离、攻击令牌、背景剪影 |
| 自动/离线另写公式 | 在线离线漂移 | reducer/hash 契约测 |
| 防御与反伤克制 Boss | 数值崩坏 | 标准化反击、上限、Boss 系数 |
| 五武器各写一套系统 | 维护爆炸 | 普攻链 + modifier + 通用几何 |
| 主线去剧情导致世界感变薄 | 内容失去承载 | 章节卷轴、纪事、人物/地点/装备典故、事件队列 |
| 大规模并行多人改同一 YAML | 合并事故 | 先拆分片/索引，单文件 owner |
| 外部工具产生伪生产代码 | fixture 绿、真实路径断 | 生产接线证据 + 主审 diff + smoke |
| 角色活动状态互相覆盖 | 复制角色/装备、奖励重复 | 单一 occupancy、快照锁、事务与幂等测试 |
| 旧档恢复 3v3 概念 | 产品模式回退 | 迁移只推导调度，不恢复队伍战斗 |
| 所有关都塞杂兵 | 决斗气质消失 | 密度按场景，斩将/心魔/连战稀疏 |
| 奖励模式各自造货币 | 经济碎片化、日课化 | 三层奖励与既有资源复用 |

## 23. 开工顺序（第一批实际执行）

用户批准本方案后，第一批只开以下任务，不直接铺开 21 章。其中 A 轨的现版试玩与 B 轨的 G0 文档/合同修订并行：

1. **A 轨—现版试玩**：使用已完成的 2/3/4 波、420 普攻、固定拍移动和水墨反馈基线，记录密度、节奏、打击感、防御需求和操作问题；
2. **B 轨—确定性修订**：建立五列决策表，先修正六几何、换波冷却、远征全局一条和七心魔映射口径；
3. **B 轨—底账同步**：同步 `GDD.md` / `CLAUDE.md` / `PROGRESS.md`，只写已冻结事实、实现差异和待决索引；旧 3v3 只做生产路径防回流守卫检查，不再开大型清理工作流；
4. **G0 清账**：单独拍板主线重打/自动/扫荡参与者、连续关卡换装/伤势中断、随行听剑比例/占用/上限、心魔主修修炼度惩罚和七关 AI 映射；
5. 建立总任务板、决策 registry、任务包模板和动态 WIP 规则；记录普通关/群战 fixture 的性能与 headless 基线；
6. 冻结六几何、动作/防御顺序、姿态、状态、spawn、攻击令牌、遭遇目标和参与者合同，关闭 G0；
7. 在现有 reducer/typed binding/事件流上并行实现 M1 扩展和对应测试；M1 末验证通过后关闭 G1；
8. 在已验证过渡基线上建立黑风岭数据包、山匪生态、HUD/VFX/音频与结果“下一关”链路；
9. 完成黑风岭手动/自动/headless/扫荡/伤势/奖励全链和关间叙事搬迁；
10. 用户验收黑风岭 G2；通过后才开启五武器、其余生态包和 21 章批量扩面。

## 24. 完成定义

本阶段不能以“新 reducer 写完”“105 关 YAML 改完”或“画面能出现 20 个敌人”作为完成。只有同时满足以下条件才算完成：

- 本文所有已确认规则均已同步到 GDD，并能在生产路径找到对应实现或明确的“不适用”说明；
- 105 主线、49 塔和六类特殊模式都使用单角色 Phase 0A，且没有产品路径回退旧 3v3；
- 掌门/门人均可按规则亲战或差遣，活动占用、锁装、伤势、成长与奖励一致；
- 主线普通关可连续进入下一关，无强制关间过场，原内容在新的可选载体可阅读；
- 五武器、三特性、防御/反击、姿态、状态与 AI 三战术可用；
- 六生态包、七模板、21 章矩阵、塔七层循环和各模式密度达到设计；
- 在线、自动、差遣、离线同核契约通过；
- 唯一奖励、重复产出、个人成长和特殊失败规则无重复领取或模式倍率漂移；
- 标准视口、高密度性能、无障碍、双平台构建和旧档迁移过 Gate；
- 所有外部工具分支经过主审，主分支干净、文档和进度总账同步、已知风险明确。

## 附录 A：不可在实施中悄悄改变的决策

- 不恢复 3v3，不加场上队友；
- 不固定“副本只能门人打”或“只能掌门打”；
- 不给手动模式额外资源倍率；
- 不做全屏无落点 AOE；
- 不做概率化主动闪避，不做弹药/耐力/耐久；
- 不让反伤按 Boss 原始伤害无限反弹；
- 不保留沉默、缴械、致盲、混乱；
- 不让普通 Boss 失败扣修为；
- 不让心魔失败造成物理伤势；
- 不让心魔失败扣永久内力；主修修炼度惩罚在 G0 签字前不擅改；
- 不让断魂庄换人/换装备绕过连战；
- 不让远征自动越过首次手动里程碑；
- 首版远征全局同时最多一条 active run，不按路线或门人数扩并发；
- 不把塔做成每日重置；
- 不为各模式新增日课货币；
- 不按速度、连击、无伤给资源倍率；
- 不让所有关卡都变成海量杂兵；
- 不用降低真实敌人数作为画质选项；
- 不把关间剧情换成另一个强制弹窗；
- 不让 Qoder/DeepSeek 或任何外部工具直接决定架构、数值、存档或合并主分支。
