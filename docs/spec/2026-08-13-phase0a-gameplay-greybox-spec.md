## 0. 本阶段只回答什么

Phase 0A 只回答一个产品问题：

> **在没有正式美术、完整成长和掉落经济时，“单门人无 AI 队友”的横向浅纵深战斗，能否通过移动瞄准、身法、聚怪、破招和范围清场，在 `20 普通怪 + 1 精英`中形成可读、可重复的刷怪快感？**

它不回答：

- 正式 Flame 生产选型；
- 259 招的实时语义如何批量迁移；
- 122 关、塔 49 层与旧 3v3 的最终去留；
- 武学真意、掉落、自动攻克与离线经济；
- 正式角色美术、骨骼运行时与动作产能；
- 市场成功或最终玩家规模。

## 2. 冻结的玩法边界

### 2.1 角色与战场

| 维度 | Phase 0A 决定 |
|---|---|
| 出战角色 | 1 名白盒门人，整场不换人 |
| 队友 | 无 AI 队友、无援护实体 |
| 视角 | 横向卷轴 |
| 活动平面 | 横向主轴 + 浅纵深地带 |
| 瞄准 | 鼠标世界坐标决定攻击方向，不限于左/右 |
| 场地 | 参考逻辑视口 `1600×720` 等比缩放；世界 `2400×720`，战斗带 `y=150–570`（浅纵深 `420px`），能横向滚动 |
| 跳跃 | 不做 |
| 关卡成长/掉落 | 不做；进入后直接试玩固定战斗脚本 |

### 2.2 敌人档位与三批循环

单次正式试玩依次包含三批，不让测试者从菜单挑选最容易档：

| 批次 | 同屏活跃敌人 | 目的 |
|---|---:|---|
| A | 10 普通近战 | 学会移动、瞄准、身法与聚怪 |
| B | 20 普通近战 | 验证包围、聚怪与范围清场 |
| C | 20 普通近战 + 1 精英 | 验证怪海中的危险可读性与破招 |

每批的敌人位置、入场次序和精英攻击节奏由固定 seed 驱动。波间留 `3.0s` 换气，真气保留并恢复 25（气海的 25%），HP 不回满；整个三波循环目标 `90–130s`。测试版完成三波后显示“再打一轮”，用真实点击作为重复意愿证据，不自动进入第二轮。

固定波次脚本：

| 波次 | 出生 | 目标时长 | 必要观察 |
|---|---|---:|---|
| W1 | 5 杂兵 `t=0` + 5 杂兵 `t=0.8s`；出生后只移动 `1.2s` | 15–25s | 学移动普攻、身法和 Q→R |
| W2 | 8 杂兵 `t=0` + 6 `t=0.7s` + 6 `t=1.4s`，三方向 | 25–40s | 同屏峰值 ≥18；至少一次 Q→R 击溃 ≥8 |
| W3 | 8 杂兵 `t=0` + 6 杂兵与 1 精英 `t=0.7s` + 6 杂兵 `t=1.4s` | 45–60s | 精英最早 `t=4s` 蓄力；至少 2 次破招机会 |

## 3. 输入、招式与资源循环

### 3.1 固定键鼠映射

| 输入 | 行为 | 输入语义 |
|---|---|---|
| `WASD` | 横向 + 浅纵深移动 | 允许对角线；越界时沿边界滑动 |
| 鼠标移动 | 瞄准 | 屏幕坐标转世界坐标；角色面向与移动方向解耦 |
| 按住左键 | 连续普攻 | 按固定攻速重复释放；可移动中攻击 |
| `Space` | 身法 | 沿当前 `WASD` 方向移动；无移动输入时沿瞄准方向 |
| `Q` | 聚怪技 | 以鼠标世界落点为中心，对范围内敌人施加牵引 |
| `R` | 清场技 | 以主角为中心释放半径 `340px` 的圆形清场攻击；鼠标方向不改变作用域 |
| `Esc` | 暂停/继续 | 暂停时不记性能样本；试玩数据保留 |
| 暂停/结束层按钮 | 重开本轮 | 不占用战斗键，避免与 `R` 清场冲突 |

0A 只验键鼠。手柄映射、改键、键盘可达性和输入缓冲的正式规格不属于本阶段；但按键不得丢失、卡住或因窗口失焦持续释放。

### 3.2 可调整的首轮参数

下表是灰盒起点，不是生产数值。全部写入隔离探针的 YAML 配置域，调整时保留版本与 checksum，不在 Dart 散写；若与 0− 共用 `probe_scenarios.yaml`，只能新增独立 `gameplay` 域，不得改变原三档负载语义：

| 能力 | 首轮起点 | 战斗职责 |
|---|---|---|
| 普攻 | `300ms` 一轮（前摇 50 + 判定 60 + 后摇 190ms）；伤害 `34`；半径 `150px`、`75°` 扇形；最多轻硬直 3 人；移动保留 85%；后摇过 50% 可被 Space 取消 | 每个技能实例命中任意数量只产 `5` 真气 |
| 身法 | 位移 `200px` / `180ms`，CD `3.2s`，无敌 `30–150ms`，结束锁定 `80ms`；穿杂兵，不穿精英/边界 | 脱困和重新站位；无伤害/产气 |
| 聚怪 | 鼠标落点最远离角色 `360px`；半径 `300px`，单敌最大拉距 `220px`，拉拽 `300ms`；前摇 180 + 收招 120ms；CD `6.5s`，零耗气/零伤害 | 杂兵聚到约 `100px` 圈并失衡 `2.0s`；精英仅 35% 位移、不失衡 |
| 清场 | `R`；角色中心半径 `340px`；前摇 280 + 判定 120 + 后摇 360ms；耗气 `60`；无独立 CD，受动作锁定；前摇有轻击霸体，精英重击可打断 | 普通伤害 `65`；失衡×1.7=`110.5` 一击击溃；精英固定 `120`（10% HP） |
| 真气 | 气海 `100`，开场 `40`，无被动自然回复 | 要求先普攻/整理怪群，再兑现清场；禁止站等 CD |

统一资源规则：

1. 真气产出按“技能实例”结算，任一可命中技能在该 `castId` 首次合法命中时产 `5` 真气；同时命中 5 怪仍只产一次；
2. 聚怪在 CD 期、清场在真气不足或动作锁定期不扣资源，HUD 给短促负反馈；
3. 输入在有效前摇结束前可记录一个后续指令，不允许无限排队；
4. 普攻、聚怪、清场的命中组都有唯一 `castId`，同一目标在同一 `castId` 下不重复结算；
5. 死亡、暂停、失焦和重开必须清空按键持续态与缓冲指令；
6. 输入缓冲 `120ms`；输入到动作视觉反馈：普攻/Space `≤50ms`，Q/R `≤100ms`，伤害仍按前摇时点落地；Q/R 互斥且前摇不可被 Space 取消。

### 3.4 冻结状态机与优先级

- 玩家：`Locomotion ↔ BasicAttack → Dodge | Gather | Clear → Recovery`；任意非无敌态可进入 `HitStun/Knockback`，HP 为 0 进入 `Defeated`。
- 输入/打断优先级：`Defeated > 精英重击/击退 > Dodge > Q/R > BasicAttack > Locomotion`。Q/R 互斥且不能互相取消。
- 杂兵：`SpawnGrace → Approach → Encircle/RequestAttackSlot → Telegraph → Strike → Recover → Encircle`；受击进入 `HitReact/Knockback`，HP 为 0 后 `Defeated/Flee`。
- 精英：`Approach/Circle → Telegraph 350ms → BreakWindow 650ms → Commit 200ms → Recover`；破势满 2 点转入 `Staggered 1.8s`。

### 3.3 白盒生命与敌人参数

| 实体 | 冻结值 |
|---|---|
| 玩家 | HP 100；气海 100；开场气 40；横速 360px/s；纵速 260px/s；半径 22；受击后 180ms 伤害保护 |
| 杂兵 | HP 100；移速 250；半径 20；伤害 7；前摇 350 + 判定 80 + 后摇 900ms |
| 精英 | HP 1200；移速 280；半径 32；普通伤害 12；蓄力失败技伤害 25 |

这些数值只属于隔离灰盒，不写入 GDD 数值表，不代表正式伤害换算。

## 4. 敌人职责与攻击名额

### 4.1 普通近战杂兵

普通敌人不是静态血包，必须完成三个职责：

- **包围**：追击、分离、从浅纵深上下两侧取位；
- **施压**：只有 3 个近战攻击名额，获得名额者才能前压并攻击，外围敌人维持围势与威吓；
- **被整理**：可被牵引、击退、硬直和清场，死亡在 `120ms` 窗内错帧，不同帧同时退场。

杂兵攻击为前摇 `350ms`、判定 `80ms`、后摇 `900ms`；普通攻击名额最多 3，各攻击起手至少错开 `180ms`。危险提示优先级低于精英预警但高于普通粒子。

### 4.2 精英：破阵重手代理

精英负责把“无脑清杂兵”切成破招决策：

- 独占 1 个精英攻击名额，不挤占 3 个杂兵名额；
- 状态链是 `Approach/Circle → Telegraph 350ms → BreakWindow 650ms → Commit 200ms → Recover`；蓄力总可见时间 `1.2s`，重招循环建议 `5.0s`；
- 窗口有 `2` 点破势：普攻 1，Q/R 各 2；同 `castId` 不得因多目标/多碰撞重复扣减；身法不直接破招；
- 破招成功后踉跄 `1.8s`、承伤×1.5，并返气 15（每次蓄力最多一次）；
- 破招失败后释放高可读重击（预警几何须配合声音和朱砂形状），身法能逃出，不设为必吃伤害；
- 精英的预警、破招值、攻击范围与踉跄状态在 20 杂兵和清场特效中仍必须可见。

破势值按 `castId` 结算，同一普攻的多段/多碰撞不能重复削减。这是 0A 对“多目标不能放大资源/触发”的最小证明。

## 5. 反馈、相机与可读性

### 5.1 最小反馈套件

| 事件 | 必须有 | 禁止 |
|---|---|---|
| 普攻命中 | 短闪白/色值变化、轻微击退、一次主命中音效代理 | 每命中目标各停顿一次 |
| 聚怪 | 落点预览、牵引轨迹、敌人位移方向可见 | 用全屏高亮遮住敌人 |
| 清场 | 单次主 hit-stop，墨迹/残影、成片击退/死亡、一次轻镜震 | 按命中数累加 hit-stop/震屏 |
| 破招 | 精英轮廓中断、状态从蓄力转踉跄、独立声音/色值代理 | 只用小文字说明“已打断” |
| 主角受击 | 短闪、击退或硬直、HP 变化 | 无反馈扣血 |
| 死亡 | 错帧退场、剩余敌数可见 | 同帧全部消失 |

主 hit-stop 只暂停战斗世界很短的固定时长，HUD、输入释放与数据采集不得被停顿成卡死。一次技能实例最多一次主停顿：普攻 `18–25ms`、R 约 `65ms`、破招约 `80ms`；R 镜震 `2–3px / 100ms`。退场在 `0–180ms` 错帧；R 伤害数字最多显示 8 个，其余合并。Q 只保留一股内收墨线，R 只保留一圈主墨爆。数值由 YAML 调整，性能报告必须记录特效预算与反馈版本。

### 5.2 可读性优先级

从高到低：

1. 主角轮廓、HP 危险与当前瞄准方向；
2. 精英蓄力范围、破招进度与重击落点；
3. 杂兵即将命中的短预警；
4. 技能范围与敌人被牵引/击退的方向；
5. 伤害数字、墨迹、残影和氛围粒子。

主角与精英优先级不得被主角自己的清场特效覆盖。性能允许粒子更多不等于可读性允许更多。

敌人使用灰阶；主角以留白和稳定轮廓区分；精英用体量与粗墨边区分。朱砂只给危险与破招，并同时使用形状和声音。按 y 坐标排序；主角轮廓、危险预警、精英动作始终高于粒子。同刻普通危险提示最多 3 个、单方向最多 2 个。

### 5.3 镜头

- 默认跟随主角横向位置，纵深只小幅度跟随；
- 主角与瞄准点之间提供有界 look-ahead，不让鼠标把镜头拉走；
- 怪群密度升高时只允许小幅拉远，并保证主角屏幕轮廓不低于起始尺寸的 80%；
- 震屏不改变逻辑 hitbox，不使鼠标落点和视觉落点偏移。

## 8. 性能回归

### 8.1 两种模式，不混签

1. **人工试玩模式**：用于主观 Gate 和操作数据，记录帧时但不作为稳态性能签字；
2. **确定性回放模式**：使用固定输入事件、seed、敌人脚本和三批流程，用于 Profile 回归与跨版本比较。

人工操作结果不能与确定性 run 混池计算 p99。

### 8.2 Mac 本地必跑

在与 0− 相同的 Profile、视口、刷新率、DPR 与采集口径下：

- `1280×720`、`1440×900`；
- 0A 三批确定性回放；
- 至少 12 秒预热 + 60 秒采样 + 30 秒冷却；
- 每视口 3 个有效 run；
- 采样期覆盖多次 `20+1` 与清场特效峰值；
- 每个 run `p99(totalSpan) < 16.6ms`；
- 连续 2 帧 `totalSpan > 33.3ms` 为 0；
- GC telemetry 可得，对象池复位，预热后新分配守 0− 口径；
- 相对同视口 0− `target_20_plus_1` 的最差 p99，0A 退化不得超过 25%；若 0− 基线过低导致相对值夸大，仍须满足绝对 `16.6ms` 并在报告中单列解释，不静默删除回归项。

性能报告须同时写出广相/narrow-phase、反馈实体峰值、HUD 更新频率、每批活跃敌人峰值与三批循环 checksum。

### 8.3 Windows 仍为硬阻塞

- 同 commit、同 `probe_scenarios.yaml` gameplay checksum、同确定性脚本；
- 目标最低档 Windows 两视口各 3 个有效 run；
- 帧时、GC、对象池和隔离 Gate 与 Mac 同标准；
- 没有该证据时最多只能签 `LOCAL_PASS_WINDOWS_PENDING`。

## 9. 6 人测试设计

### 9.1 招募是进入条件

正式主观 Gate 开始前须确认：

- 2 名偏挂机玩家；
- 2 名 ARPG 玩家；
- 2 名混合玩家；
- 至少 2 名候补；
- 作者、主要实现者不计入；
- 同一人不重复占类别名额。

测试者先只获得一张键位卡，不提前解释最优连招、聚怪或破招答案。操作员可在首轮 30 秒后回答“哪个键做什么”，不代打或提示时机。

### 9.2 对照与顺序

每人必须同时体验：

1. 当前生产版“点招立即出手”战斗的固定对照段；
2. Phase 0A 三批灰盒。

为减少顺序偏差：3 人先旧后新，3 人先新后旧；每个玩家类型尽量各有一人走反顺序。对照关卡、门人/build、操作说明和时长固定并写入测试记录。

### 9.3 必问与观察

5 分量表：

1. 聚怪后清场的释放感（爽感）；
2. 20 怪 + 1 精英时找到主角与危险的难易（可读性，高分=容易）；
3. 完成三批后愿意继续主动操作的程度（操作意愿）。

二元题：

- 是否愿意立即再打一轮；
- 新灰盒的主动体验是否明显优于当前点招战斗；
- 身法、聚怪、破招中哪些有不可替代用途；
- 你在哪一刻最开心，哪一刻看不清或觉得只需重复一个技能；
- 它更像武侠 ARPG，还是无差别割草演示；为什么。

观察员不引导，只记录：找不到主角/精英预警、危险来源判断、技能空放、原地站桩、死亡、主动聚怪、成功破招、只按单一技能和“再打一轮”点击。另冻结 5 段高密度画面/短视频，逐段要求测试者在 1 秒内指出主角及危险来源。

## 10. Gate 和否决项

### 10.1 所有条件同时成立

1. 爽感、可读性、操作意愿的 6 人中位数各自 `≥4/5`；
2. 至少 4/6 人口头表示愿意再打，且至少 4/6 人在应用内真实点击“再打一轮”；
3. 至少 4/6 认为明显优于当前“点招立即出手”；
4. 至少 4/6 能说出身法、聚怪、破招各自的一个不可替代用途；
5. 5 段冻结画面/短视频中至少 5/6 能在 1 秒内指出主角，危险来源判断正确率 `≥80%`；至少 5/6 能解释 Q 与 R 为什么不可互换；
6. 量化战斗 Gate 同时满足：峰值活跃 `20+1` 场景 `≥19`；普通攻击者 `≤3`；Q→R 击溃中位数 `8–14`；满血裸 R 击溃 `0`、平均清场率 `<50%`；精英破招成功率首轮 `40–70%`、理解后 `60–85%`；单波受击中位数 `2–5`；三波 `90–130s`；
7. 固定 10 seeds 下，“不移动 + 持续 LMB + Q/R 亮就放”脚本至少 `8/10` 死于 W3 或超时；会用身法、Q→R、破招的基准脚本至少 `8/10` 通过；
8. 不出现过半测试者（≥4/6）在 C 批频繁找不到主角、找不到精英危险，或将“只需重复一个技能”判为最优玩法；
9. 至少 5/6 有效样本在无实现者代打下完成三批；
10. Mac 确定性 Profile 回归满足 §8.2；
11. 存档/依赖隔离、对象池和采集契约通过；
12. 实际开发投入不超过 10 个工作日，未靠删除失败样本或改低 Gate 达成结论。

### 10.2 直接否决项

即使平均分达线，以下任一成立仍为 `LOCAL_FAIL`：

- 最优策略是站桩按住普攻或等 CD 只放清场技；
- 上述无脑脚本通过率超过 `2/10`，或基准脚本通过率低于 `8/10`；
- 聚怪、身法、破招中任两项没有可感知职责；
- 主角/危险可读性只能靠减到 10 怪才成立，20+1 目标档不成立；
- 爽感主要来自伤害数字或无区分全屏特效，不来自整理怪群和时机；
- 需要 AI 队友、战中换人、跳跃或第四个主动技能才能补救核心循环；
- 出现任何正式存档读写或生产奖励接线；
- Mac 性能或稳定性在时间盒内不能恢复。

### 10.3 裁决状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| `LOCAL_PASS_WINDOWS_PENDING` | 6 人主观 Gate + Mac 性能 + 隔离全通过，Windows 仍缺 | 冻结 0A 代码/参数，只准备 Windows 复跑；不进 0B/0C |
| `PASS` | 上述条件通过，且目标最低档 Windows 同版本回归通过 | 可申请进入 0B，仍需人类裁决 |
| `LOCAL_FAIL` | 核心玩法、可读性、Mac 性能或隔离失败 | 停止 ARPG 主路，回现有半手动战斗表现强化 |
| `INCONCLUSIVE` | 有效样本 <6、包/问卷不一致或外部事件污染数据 | 不降 Gate；补齐同版本样本，时间盒不重置 |

## 11. 失败回退与部分成功

| 结果 | 处置 |
|---|---|
| 爽感通过，可读性失败 | 在剩余时间盒内只调主角/预警层级、特效预算、镜头和攻击名额；不新增技能 |
| 可读性通过，爽感/重复意愿失败 | 只允许调整聚怪—资源—清场节奏和命中反馈；若第二轮仍失败则停线 |
| 玩法通过，性能失败 | 先恢复 0− 已验对象池/粒子/HUD 约束；时间盒内仍失败则 `LOCAL_FAIL` |
| 只有 10/20 怪可读，20+1 不可读 | 不自动改 Gate；记为目标密度失败，回项目主人决定降密度或停线 |
| 测试者只喜欢清场演出，不使用身法/聚怪/破招 | 判核心循环未成立，不靠加第四个技能补救 |
| 多数人认为“无双/割草演示”而非武侠 | 降低同屏密度、改退场表达为击溃/逃散并重测品类；不以性能通过为理由强行保留 |

0A 失败后保留代码与数据为隔离研究资产，关闭实验入口；不接生产、不为沉没成本扩大范围。

## 12. 时间盒与范围冻结

Phase 0A 最多 10 个实际工作日（等待测试者/Windows 设备的日历时间不计实现时间，但状态必须显示为阻塞）：

| 时间 | 交付 |
|---|---|
| Day 1–2 | 独立配置、输入、移动瞄准、移动普攻；首个可玩杀伤性版本 |
| Day 3–4 | 身法、聚怪、清场、真气/CD、三批流程 |
| Day 5 | 精英蓄力/破招，攻击名额，胜负/重开 |
| Day 6 | 命中反馈、镜头、HUD、可读性首轮 |
| Day 7 | 确定性回放、采集、targeted tests、Mac Profile 回归 |
| Day 8 | 内部走查与一轮有记录调整；冻结测试包 |
| Day 9 | 6 人测试与问卷（可按排期分散） |
| Day 10 | 聚合结果，裁决与恢复点；不新增功能 |

一旦预计超出 20%，冻结新技能/新敌人/新特效，只完成既定测试并输出继续/停止裁决。

## 13. Targeted tests 与破坏证红

至少覆盖：

1. WASD 对角线归一化、边界滑动、失焦清持续键；
2. 鼠标屏幕→世界坐标，镜头移动/震动后瞄准不偏；
3. 按住普攻节奏、移动速度保留、每 `castId` 只产一次真气；
4. 身法位移/CD/无敌窗、边界 clamp、无方向时使用瞄准；
5. 聚怪落点、精英 35% 位移、CD/真气失败不扣资源；
6. 清场圆形作用域、裸 R/失衡 R 伤害关系、杂兵成片击溃、精英不被一击秒杀；
7. 攻击名额不超 3+1，无名额敌人仍包围/动画；
8. 精英蓄力、破招值按 `castId` 去重、成功踉跄/失败重击；
9. 三批顺序、换气、死亡/重开/再打一轮与固定 seed checksum；
10. 同一技能实例只一次主 hit-stop/镜震，伤害标签聚合；
11. 帧时/RSS/GC/对象池报告字段、暂停样本 invalid、两视口；
12. 根依赖无 Flame 、探针无 Isar/正式 app data/生产 import；
13. 量表中位数、4/6 门槛、否决项与样本不足裁决函数。

破坏证红至少包含：

- 把真气产出从每 `castId` 改为每命中目标，20 怪测试必须红；
- 让 4 个杂兵同时获得攻击名额，名额上限测试必须红；
- 对同一 `castId` 重复削减精英破招值，去重测试必须红；
- 把清场主 hit-stop 改成按命中数触发，聚合契约测试必须红；
- 在 0A 源码 fixture 注入 `IsarSetup.init`，隔离契约必须红。

真实爽感、可读性与 Profile 帧时不能用 unit test 代签。

## 16. 与现行 GDD 的已知口径差异

以下差异不阻塞隔离 0A，但不得悄悄写回生产系统：

1. GDD 仍写“手动首通后自动刷”，v2 已拍板不强迫手操；本阶段不验证内容覆盖与解锁策略。
2. 旧 AOE 规则是对全存活目标完整结算，v2 实时战斗改为空间范围与总预算；0A 只验证后者。
3. 现行战斗是 3v3，0A 是单门人无 AI 队友；不删除多门人养成、阵容和传承结构。
4. “身法”在项目中已有属性语义，代码动作命名使用 `movementArtAction`/“身法技”，避免复用属性概念。
5. 白盒归一 HP/伤害只属于隔离探针，不进入正式数值表。

## 17. 剩余待决点

下列不阻塞首个可玩灰盒，但必须在对应测试轮前记录决定：

1. **对照生产片段**：在测试包冻结前，由主窗口选定同一关卡、门人/build 和播放时长；未冻结对照时不开始 6 人 Gate。
2. **测试者可用性**：6+2 人的名单、玩家类型、设备与排期属外部准备；未就绪时可继续实现与内部 smoke，但不能签主观 Gate。
