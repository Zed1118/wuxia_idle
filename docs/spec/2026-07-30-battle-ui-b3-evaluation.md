## 二、量测方法

15 关真机战斗屏截图（`visual_capture.sh --route battle_audit_stage_*`，1280×720 逻辑 = 2560×1440 物理），
取敌立绘躯干带与其紧邻的同高度背景带，比较：

- **暖度** `warmth = R - B`（正 = 偏暖褐，负 = 偏冷青）

以**截图**为准而非算原图——截图含 scrim、色彩矩阵、景深、暗角的最终合成结果。

## 四、真正的成因：两族素材的渲染语言不同

- **立绘**：派单书锁死「**厚涂写实**、低饱和土色系、柔和顶侧光」→ 实体感强、边缘锐、中低调。
- **场景背景**：水墨淡彩高调，大片近白宣纸底 → 平面、通透、高调。

两种画法拼在一起，人物就会读作「贴上去的」。**没有任何色彩矩阵能调和两种渲染语言**——
色温只是表象，真正的差异是「实体 vs 平面」「低调 vs 高调」。

## 五、现成杠杆（都在立绘侧，零触背景美术）

`character_avatar.dart` 已实装的大气融合三件：

| 常量 | 现值 | 作用 |
|---|---|---|
| `battleStandeeEdgeSofteningSigma` | 见源码 | 边缘柔化模糊，削锐边 |
| `battleStandeeFusionMatrix` | 对角 0.74/0.75/0.67 + 偏移 12/10/8 | **抬黑位、压高光**、降通道分离 |
| `battleStandeeFusionOpacity` | 0.96 | 整体透一点 |

代入验证该矩阵的实际行为（本会话手算）：暗部 `40 → 46`（抬黑位 ✓）、中调 `128 → 127`（几乎不动）、
亮部 `220 → 210`（压高光 ✓）。**方向完全正确，只是幅度偏轻**——正是「降低立绘自身对比、
让它更像背景那样通透」的那个杠杆，而 B3 却去改了背景侧的色温矩阵。

## 六、四个选项

| 选项 | 做法 | 波及面 | 风险 |
|---|---|---|---|
| **A · 不做** | 承认高反差是水墨风格的有意选择（人物可读性优先），B3 这 3 分永久不取 | 0 | 0 |
| **B · 按场景亮度自适应加强立绘融合**（**推荐**） | 读该关背景平均明度，明度越高 → `fusionOpacity` 越低 / 黑位抬得越多。**只动立绘侧** | 立绘渲染路径 1 处；**0 张背景美术** | 中：暗场景（塔/心魔）须确保不被洗淡，要加下限钳制 |
| C · 全局加强立绘融合（不分场景） | 直接调三个常量 | 全部战斗场景 | 高：暗底场景会把人物洗没 |
| D · 改 `_mainlineSceneColorGrade`（B3 原方案） | 调背景色温矩阵 | 全主线背景 | **不推荐**：实测证明色温不是主导轴，改了也解决不了明度差 |

**推荐 B**（2026-07-30 用户拍板采纳，已实装），理由三条：
1. 实测指出主导轴是明度、且**逐场景方差极大**（-121.5～+16.8）→ 天然该按场景自适应，而不是全局常量。
2. 杠杆已存在且方向已正确，只是幅度不足与不分场景 → 是**参数化**改造，不是新机制。
3. **零触 90 关背景美术**，把交接里那条否决理由整个消掉。

## 七、拍板前仍需你定的三件

1. **要不要做**（A vs B）—— 高反差也可以是有意的风格选择，人物在任何背景上都清晰可读本身是价值。
2. **若做 B，自适应强度上限**：融合太强 → 人物发灰、失去厚涂质感（等于牺牲美术投入）；太弱 → 等于没做。需要给一个可接受的「最淡到什么程度」。
3. **暗场景下限**：塔 / 心魔 / 断魂庄是暗底，融合必须钳到几乎不生效，否则人物被背景吞掉。

## 八、附:同批复核的 C5（行囊三格）—— 比「中性占位」更值得处置

阶段 5 把 C5 记作「行囊三格是硬编码占位 + Semantics 标『待装配』，属未实装功能预留位，改视觉无意义」，据此扣 2 分。**现读源码复核后，结论要加一句**。

`BattlePouchRail`（`battle_bottom_bar.dart`）实况：

```dart
for (var i = 0; i < 3; i++) ...[
  Semantics(
    label: '${UiStrings.battlePouch} ${i + 1}',
    value: UiStrings.battlePouchReserved,   // 「待装配」
    child: Container(
      ...
      child: i < 2
          ? Image.asset(i == 0
              ? 'assets/equipment/accessory_baowu_zi_jin_hu_lu.png'   // 紫金葫芦
              : 'assets/equipment/accessory_xunchang_yao_nang.png')   // 寻常药囊
          : ...
```

**slot 0 / slot 1 无条件、写死显示两个真实道具的图标**，与玩家实际背包**毫无关系**；
slot 2 空。也就是说：**每个玩家、每一场战斗，行囊里都「有」一个紫金葫芦和一个寻常药囊。**

这不是中性占位——它在展示**假的游戏状态**。旁边的「待装配」小字确实给了提示，
但字号 9、颜色 `textMuted`，而两个道具图标是 42px 的实心彩图，**视觉权重完全相反**。

### 三个选项

| 选项 | 做法 | 成本 |
|---|---|---|
| **A · 换中性占位（推荐）** | 三格统一用空槽纹样（沿技能案台空签体例），不显任何具体道具 | 小，presentation 单点 |
| B · 整条隐藏 | 未实装就不显（守 §5.7「未解锁系统的菜单按钮直接灰掉或隐藏」） | 小，但战斗屏右下会空一块，需重排 |

**推荐 A**：既保住「这里将来是行囊」的信息，又不谎报玩家拥有的道具；
且 §5.7 原文是「未解锁系统的菜单按钮直接灰掉或隐藏」，现状（显具体道具）离这条更远。
