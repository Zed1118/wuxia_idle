### 1.3 境界差是阶梯函数(**复核新增 · 决定方案取舍**)

`derived_stats.dart:40` 取 `|attackerTier.index - defenderTier.index|` 查表。对武圣玩家:

| 敌 tier | \|差\| | 档 | 玩家打敌 | 敌打玩家 | 相对现状威胁 |
|---|---|---|---|---|---|
| xueTu / sanLiu / erLiu / yiLiu | 6/5/4/3 | diff_3_or_more | 1.0 | **0.05** | **1.0x** |
| jueDing | 2 | diff_2_tier | 2.5 | 0.3 | 6.0x |
| zongShi | 1 | diff_1_tier | 1.4 | 0.7 | 14.0x |
| wuSheng | 0 | same_tier | 1.0 | 1.0 | 20.0x |

**敌人境界从学徒抬到一流,威胁零变化**。两条推论:
① 任何「每周目抬 1 阶」的配法,前几周目完全空转 → **每周目至少抬 3 阶**;
② `diff_3_or_more.attacker` 是 `null` 兜底 1.0(`numbers_config.dart:1776-1798`),
**比 diff_2 的 2.5 还低,曲线非单调** → 抬到差 2 阶时敌人输出 ×6 的同时玩家输出也 ×2.5,
净威胁增益约 2.4× 而非 6×(解析推算,实装时须 `balance_simulator` 实测)。

### 1.4 断档成因(**复核订正起草版**)

起草版记「floor 15(abs 3)→16(abs 8) 断档是 Lv100 时代压缩曲线的遗留」。实测证伪:
成因是**每 tier 只取前 3 个 layer(qiMeng/ruMen/shuLian)× 5 楼/层**的系统性取法,
xueTu 与 sanLiu 两段跳过的 layer 完全一样(jingTong/yuanShu/huaJing/dengFeng)。
→ **按「每 tier 取 N 层」的思路扩塔,会在每个 tier 边界再生一个断档**。

## 2. 问题定义 · 既有周目机制为何不够

**除主线与心魔外,全部支线内容对终局玩家近免疫。** 通关到武圣(abs 49)的玩家回到这 5 个入口,
面对 abs 10-17 的敌人、境界差 4-5 阶 → `defender 0.05`,只剩扫荡刷资源的功能;
塔的「问鼎九霄」叙事定位与断魂庄的 Boss 车轮压迫感均落空。

塔虽已有周目(`scale_per_cycle: 0.10` / `max_cycle_tower: 2`),但**只缩放属性不动境界**:
`stage_battle_setup.dart:455` 的 `scale = 1.0 + scalePerCycle × (cycle-1)` 只乘 hp/attack/IF
(`:465/:471/:476`),境界取 `enemy.realmTier` yaml 原值(`:448/:543`),全仓无按周目抬境界的路径。
而**境界差是乘在最外层的独立轴**,+10% 属性被 `0.05` 整个吞掉。

> 措辞订正:`0.05` 是 `level_diff_modifier.diff_3_or_more.defender` = **低境界打高境界的输出乘子**
> (`numbers.yaml:230`),起草版写作「承伤乘子」,方向等价但语义不同。

## 4. 方案取舍(拍板依据)

**塔走扩层不走境界周目**:塔是**顺序爬**的,扩层天然自动分层(爬到第 40 层时玩家境界也到那一段);
境界周目是**整体抬**,同一份配置对刚通关的三流玩家是差 3 阶硬墙(自己输出 ×0.05 打不动)、
对武圣玩家又不够,在塔上机制不自洽。**其余 4 入口(固定关数、非渐进)反之**——扩关数不适合其
玩法形态(轻功对决 / 群战守城波次 / 断魂庄 Boss 车轮 / 远征 headless 结算),周目语义修正才对症。

**形状取 1:1 锚死**(见 §7):非因最便宜,而因 `floor N ↔ abs N` 是唯一自解释的映射且断档结构上
不可能存在;起草版「70 层」经复核否决——内容量翻倍且保留 6 个断档。

| 形状 | 总层 | 新增层 | 新敌条目 | 结构性断档 |
|---|---|---|---|---|
| **1:1 锚死(采纳)** | **49** | **19** | **~38** | **0** |
| 起草版 70 层 | 70 | 40 | ~80 | 6 |
| 2:1 | 98 | 68 | ~136 | 0 |

## 5. 红线影响

- **§5.2 七阶锚死**:塔层境界落在既有 7 阶 49 层内,1:1 映射天然满足,不新造「塔专属阶」。
- **§5.4 Boss 血量 ≤60000**:扩到武圣段若线性外推必破线,**走机制门槛(vulnerability / ward)
  而非堆血**,复用 floor25/30 既有体例,贴 §5.4 机制型 Boss 例外条款。
- **§5.3 三系锁死**:新层 `requiredRealm` = 该层敌人境界,掉落阶随之(该字段经
  `tower_entry_flow.dart:235` → `equipmentTierCapOf` 决定稀有彩头装备阶);加守卫测钉死
  `requiredRealm ≤ 该层敌人境界`,防配错造成 `GDD.md:593` 的「提前发放」。
- **§5.1 反主流**:不得借扩塔引入体力/每日/登录奖励类闸门。
- **周目上限**:`max_cycle_tower` 调整须同步 `cycle_evolution.assignment` 词条表(现只配到 cycle 2/3)。

  yiLiu 22-28 / jueDing 29-35 / zongShi 36-42 / wuSheng 43-49。

  门槛靠 vulnerability 承伤窗 + ward 结界。敌队维持 3 人上限(`stage_battle_setup.dart:124`)。

  曲线整体重校,**不是纯追加**。
