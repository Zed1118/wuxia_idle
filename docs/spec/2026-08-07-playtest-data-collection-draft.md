# 真人试玩数据采集 spec【草案待拍板】(2026-08-06 夜批块3 产出)

> 解锁对象:BACKLOG 一区 #4(丹房 2B)/#5(残页数量)/#6(高熟练度微调)+§十二「仍需实玩校值」(战斗节奏/音频听感)+checklist D 段(30-35 关终调、closed beta 前置)。
> 上游拍板:§十三#5 已拍「做 3-5 人试玩」,本 spec 只收「怎么采」。

## 拍板点 1:采集口径(三选,推荐 b 为主 + c 抽 1 人)

| 口径 | 开发成本 | 数据质量 | 回收摩擦 |
|---|---|---|---|
| a. 存档文件回收 | 零(写个找文件指引) | 只有终态,无过程(不知哪关卡了多久/重试几次) | 中(玩家找 Isar 文件) |
| **b. 游戏内导出(推荐)** | 1-2 专注会话 | 过程+终态最全(首通尝试次数/败因/时长/配置) | 最低(一键出 JSON) |
| c. 旁观记录 | 零 | 定性最丰(卡点/困惑点),不结构化 | 人力最高(1-2h/人陪玩) |

推荐组合理由:#4/#5/#6 要的是**分布数据**,只有 b 给得出结构化分布;c 补「玩家在哪皱眉」的定性观察,抽 1 人即可。

## 拍板点 2:采集范围

- 最小集(推荐):**首通 Ch1-Ch5 + 塔 1-10**,约 2-4h/人——正覆盖 readable_first_clear 争议区、丹房 2B、残页节奏、早期难度曲线
- 全程到 Ch21 不现实(数十小时,先导批不必)

## 拍板点 3:招募(用户侧)

3-5 人;来源用户定(朋友/社群)。机器要求 macOS(当前唯一可跑端)。

## 导出设计草案(口径 b)

**铁律:不加运行时遥测、不联网上传、不加新追踪字段**(§2.1 反主流/买断制红线)——只读**现有** Isar collection 一次性导出,玩家主动点击。

- 数据源(本会话 Phase 0 已确认存在,字段细盘留实装):`battle_record`(战绩册/boss_memory)、`tower_progress`、`encounter_progress`、主线 stage 进度、角色境界/装备档位
- 导出内容(仅游戏数据,零系统信息):每关首通尝试次数/战斗时长 tick/败因(BattleDiagnosis 既有五规则)/首通时队伍快照(境界/心法阶/装备强化档)/境界时间曲线/残页与真解获取节点
- 出口:设置页「导出试玩数据」→ JSON 落桌面(或显示可复制文本);saveVer 零改动(纯读)
- 配套:回收分析脚本(3-5 份 JSON → 分布汇总报告,#4/#5/#6 直接可读)

## 实装切片(拍板后)

1. Phase 0 字段细盘(现有 collection 可导字段矩阵,补「想要但没存」缺口清单——缺口只报告,不为试玩加追踪)
2. 导出 service + JSON schema + 设置页入口(1 专注会话)
3. 回收分析脚本 + 试玩指引一页纸(0.5 会话)
4. 3-5 人发包(用户)→ 回收 → 分布报告 → #4/#5/#6 携数据拍板

## 与 D 段 closed beta 关系

本批=先导(工具+口径验证);M15-16 closed beta ~10 人**复用同一工具**,Google 表单(checklist D 段既列)只补主观项(难度评分/卡点描述),客观分布走导出文件,表单负担减半。
