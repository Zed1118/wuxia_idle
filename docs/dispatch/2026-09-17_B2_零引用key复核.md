## 2. 目标 B2-2 · 零引用 key 逐条四层复核（主体）

对 B2-1 重跑后仍判「零引用」的每个**归一路径**（数组元素合并到同一路径行，叶子数另列），逐条做四层复核，每层写命令原文 + 命中数：

| 层 | 复核内容 | 最低要求的命令 |
|---|---|---|
| ① 字面量 | 末段名与完整路径片段在 `lib/ test/ tool/ tools/` 全部 Dart/Python/Shell 文本中的命中（含注释） | `rg -n --no-heading '<末段名>' lib test tool tools` |
| ② 动态构造 | 是否存在字符串拼接/插值构造出该 key 的路径（`'$prefix.<末段>'`、`'${a}_${b}'`、`join('.')`、`yaml[section][name]` 变量取值），以及 `NumbersConfig.raw` / 原始 `Map` 被整表遍历的入口 | `rg -n "raw\[|\.raw\b|\.entries|\.keys|\.values|forEach\(" lib/data/numbers_config.dart lib/data/game_repository.dart` + 按所在段的父级 Map 变量名再搜一次 |
| ③ 跨文件配置引用 | 其他 yaml（`data/*.yaml`、`data/**/*.yaml`）、`data_schema.md`、`GDD.md`、`CLAUDE.md`、`docs/audit/**`、`docs/spec/**` 是否把该 key 当作**规则/合同**引用（例如 GDD §5.4 红线表、`data_schema.md` 字段说明、`validation_examples` 被测试文档引用） | `rg -n '<末段名>' data GDD.md CLAUDE.md data_schema.md docs --glob '!docs/audit/numbers_yaml_unused_keys*'` |
| ④ 历史与意图 | 该 key 何时加入、加入 commit 的意图（是否为「预留/待接线」）；是否曾被消费后又被删掉引用（`git log -S`） | `git log --oneline -S'<末段名>' -- lib data/numbers.yaml \| head` |

**每条给出四选一建议 + 一句话理由**：
- **删除候选**：四层全零、无设计文档合同、历史上从未被消费或消费已被后续实现替代 → 可进 `[schema]` 删除单（仍需用户拍板）。
- **头注 UNUSED**：暂不删但应在 yaml 段头加 `# UNUSED` 注释（例如作为公式/设计文档锚、`validation_examples` 手工战例）。
- **保留（有合同）**：③ 层命中——被 GDD/data_schema/其他 yaml 当作规则引用，或 ② 层发现动态消费（此时它**不是零引用**，标「误判：实际消费」并附 file:line，作为对 B-2 原表的更正）。
- **待拍板**：证据冲突或涉及数值/规则解释（如 `tower.*` 旧段是否等待 8–14 层迁移复用、`synergies` 旧段与 `synergies.yaml` 的主从关系）。

**期望终态**：`docs/audit/numbers_yaml_unused_keys_review_2026-09-17.md`：
