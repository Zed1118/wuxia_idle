## 〇、本包的核心判据(贯穿全部目标,先读懂再动手)

**假绿(false green)= 测试通过但它根本没在守护生产行为。**唯一判据一句话:

> **把被测的那行生产代码故意改坏,这条断言必然变红吗?** 若不必然红 → 假绿。

高发形态(本仓实证):
- 测试手设字段 / 手动改队列 / 手算几何 / 读残留状态 / **常量比自己**(断言两边都来自同一个字面量)
- 断言只锁「不抛异常」「非 null」「长度 > 0」这类恒真条件
- 用合成 fixture 而非真实生产配置(如自造 yaml 而不读 `data/` 真文件),生产配置改坏了测试照样绿
- 只测确定性(同 seed 两次跑结果一致)不测**正确性**(结果本身对不对)——同 seed 相等对一个恒返回空的实现也成立

**破坏证红的操作纪律(硬性,踩过坑)**:必须**先把新测试 commit**,再改坏生产代码看红,然后 `git checkout -- <生产文件>` 还原。**顺序反了会连未提交的测试一起抹掉**。还原后必须重跑一次确认复绿。

## 二、验收标准(可验证 · 每个目标都要满足)
