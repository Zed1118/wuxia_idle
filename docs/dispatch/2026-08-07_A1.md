- **执行端**:pi(DeepSeek V4 Flash) · **worktree**:`.claude/worktrees/pi-deadfield` · **分支**:`pi/dead-field-audit`
- **性质**:只读审计 + 写报告,**零代码改动**

## 〇、这单从哪来(真实案例,当判据锚点)

2026-08-07 本夜处置 numbers.yaml 时实锤了一个问题:

`Character.rarity`(`lib/core/domain/character.dart:64`,类型 `RarityTier`)是 Isar 实体字段,全 `lib/`(排除 `*.g.dart` 与 `lib/features/debug/`)**只有 7 处引用**:
- `lib/core/domain/enums.dart:150` 枚举定义
- `lib/core/domain/character.dart:64` 字段声明 / `:158` 构造参数 / `:207` 赋值
- 三处**写死** `RarityTier.biaoZhun` 的赋值点(recruitment / sect_recruit / master_builder)

**零读取点**——没有任何代码读 `character.rarity` 做任何事:不显示、不影响战斗、不派生属性。配置里 6 档稀有度概率(`data/numbers.yaml:942`)因此完全不生效。

这类字段的特征:**声明了、写了、存进数据库了,但没人读**。它同时是两件坏事的信号——(a) 死重量,(b) 某个设计只做了一半就停了。**本单任务:把这类字段全找出来。**

## 一、扫描范围

**实体侧**:`lib/core/domain/**/*.dart` + `lib/features/*/domain/**/*.dart` 下所有类的**实例字段**(`late X y;` / `X y = ...;` / `final X y;`)。重点是 Isar 实体(带 `@collection` / `@Collection()` 注解的类)与 `@embedded` 类,但普通领域类也一并扫。

**消费侧**:全 `lib/`,**排除** `*.g.dart`(codegen 产物,里面的读写是序列化不算真消费)。

**`lib/features/debug/` 的处理**:debug/种子/审计工具里的读写**单独标注**,不算"真消费"——只被 debug 读的字段等同于没被读(玩家侧无感)。

## 二、判定三档

| 判定 | 含义 | 举证 |
|---|---|---|
| **只写不读** | 有声明 + 有赋值,但生产代码零读取 | 字段 `file:line` + 全部赋值点 `file:line` + 一句话「为什么判定零读取」(你搜了哪些形态) |
| **仅 debug 读** | 只有 `lib/features/debug/` 或 test 读 | 同上,并列出那些读取点 |
| **正常** | 有生产读取点 | 不进主表 |

**搜索形态别只搜 `.fieldName`**,至少覆盖:
- `.fieldName` 直接访问
- `..fieldName =` cascade 赋值(这是写不是读)
- 解构 / 命名参数传递 `fieldName:`
- Isar query 里的 `.fieldNameEqualTo(` / `.sortByFieldName(` 等 codegen query 方法(**这些算真消费**)
- getter/computed 里间接引用

> ⚠ Isar 的 query 扩展方法名是字段名的驼峰变形(如 `rarity` → `rarityEqualTo`),别漏。
