# N7 · M0–M9 权威门事实底座(只读审计)

## 背景

`PROGRESS.md` 与 `CLAUDE.md` §8.4 长期把二阶段成熟度报成 `M0–M9 = 1/10`,但**这个分母从没有可核对的判据表**。
结果是没人能回答「二阶段做到哪了」——每次只能列 READY 分支数,而 §8.4 明确禁止用 READY/提交数/代码量冒充进度。

## 目标(只产事实,不产结论)

为 M0 到 M9 **每一门**产出四栏事实:

1. **判据出处** — 这门的权威 Gate 判据写在哪(`file:line` + 原文摘录)。找不到就如实写「无成文判据」,**不要自己发明一条**。
2. **已接线能力** — 当前生产路径上已经连通的能力,逐条带 `file:line`。
3. **未接线缺口** — 判据要求但代码里没有的,逐条带缺口位置。
4. **关闭还差什么** — 一句话,只描述缺口,**不估工时、不排优先级**。

## 范围围栏(机器可判)

- `git diff --name-only <base>..HEAD` 结果必须**恰好 1 个文件**:`docs/audit/phase2_milestone_fact_base_20260826.md`
- `lib/` / `test/` / `data/` 改动数必须为 **0**
- 报告 ≤120 行

## 禁止的修法

- ❌ **禁止定义权重**。M0–M9 各占多少分是 🔴 红级,归用户。你只产判据表,写权重即作废。
- ❌ 禁止把子门、局部绿测、READY 分支、文档数量算进「已接线能力」——§8.4 明令这些不进分母。
- ❌ 禁止「据我理解 M3 大概完成 60%」这类估算。没有判据就写「无成文判据」。

## [BLOCKED] 出口条件

- 找不到 M0–M9 的成文定义(即这十门本身就没有权威来源)→ 停 `[BLOCKED]`,报告你搜过哪些文件、用了什么关键词。
- 判据之间互相矛盾且无法从文档定序 → 停 `[BLOCKED]`,列出矛盾对。

## 验收方式(协调者会这么查)

1. `gate.sh <worktree> <base> HEAD --skip-full` 必须 PASS
2. 抽查报告里 5 条 `file:line`,现场 `sed -n` 核对原文是否真在那一行
3. `git diff --name-only` 必须只有 1 个文件

## 硬约束(全部照抄自协调者契约,违反即作废)

**执行端禁区文件**(一行都不许改):`data/numbers.yaml` / `GDD.md` / `PROGRESS.md` / `lib/shared/strings.dart` / `pubspec.yaml`

- **禁 push / 禁 merge / 禁碰 main / 禁 revert**
- commit message 用**中文动宾**,tip 打 `[READY]`(写完待评)或 `[BLOCKED]`(需拍板)
- 收工时工作树必须干净(`git status -sb` 无未提交实质改动、无未跟踪文件)
- 🔴 红级(玩家可见 UI / 数值与成长规则 / schema 迁移 / 删配置字段或功能 / GDD 解释)→ **停 `[BLOCKED]`,禁代拍**
- **数字必须实测**,禁转抄历史、禁凭记忆写 `file:line`;每条引用现 grep 定位
- 搜不到 ≠ 不存在:`git grep -E` 是 POSIX ERE **不认 `\s`**(静默永不匹配);先搜中文/领域词找代码真实命名
