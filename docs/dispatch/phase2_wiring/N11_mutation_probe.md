# N11 · 变异测试探针建设 + 首轮跑批(🟡 黄级 · 今晚不合并)

## 背景(协调者 2026-08-26 实测)

仓里**没有任何变异测试工具**(`find . -iname '*mutat*'` 零命中,`tools/` 下 11 项无一相关)。

而本项目最大的质量风险恰恰是**假绿**——今晚正在跑的 N4 就是「假绿审计」,
memory 里已沉淀的坑包括「测试绕开生产路径」「红线测按文件名挑导致读的是合成 fixture 不是生产 yaml」
「多路径批跑静默漏跑文件却仍报 All tests passed」。
这些都靠人工审计发现,**而人工审计只能抽查**。5620 条测试里到底有多少条是承重的、有多少条改了生产代码也不会红,现在**没人知道**。

变异测试是唯一能系统性回答这个问题的手段:自动改一处生产代码 → 跑相关测试 → 没红 = 这处没有测试守着。

## 目标

分两步,**两步都必须完成才算交付**:

### 第一步 · 建探针工具

在 `tools/mutation/` 下建一个 Dart/Python 均可的变异探针,至少支持:

- **变异算子**至少 4 类:比较符翻转(`>` ↔ `>=`、`==` ↔ `!=`)、布尔常量替换(`true` ↔ `false`)、
  数值常量替换(`n` → `0` 与 `n` → `n+1`)、条件短路(整个条件强制为 `true` / `false`)
- **逐个变异、跑完还原**,一次只活一个 mutant
- 每个 mutant 跑**定向测试子集**而非全量(全量 ~6 分钟,跑不完;定向子集由你从被变异文件推导并在报告里写明推导规则)
- 输出逐 mutant 结果:文件 / 行 / 算子 / 定向测试命令 / 失败数 / 判定

### 第二步 · 对二阶段战斗核心跑首轮

变异目标**限定**在这两个文件(今晚 P1/N1 刚动过,假绿风险最集中):

- `lib/features/battle/domain/phase0a/phase0a_combat_reducer.dart`
- `lib/features/battle/presentation/phase0a/phase0a_battle_screen.dart`

产出报告 `docs/audit/mutation_probe_round1_20260826.md`,含:存活 mutant 清单(= 无测试守护的代码位置,带 `file:line` + 算子)、
被杀 mutant 数、**以及下面「必须单列」的三类**。

## 必须单列的三类(不列即交付不合格)

memory 已实证变异跑批有五类失效模式,以下三类**必须在报告里单独成段**,不许混进「被杀」计数:

1. **编译失败 / 测试崩溃的 mutant** —— 这类**不算被杀**。「页面挂了」计入抓到会系统性虚高分数。单列并计数。
2. **被非目标测试杀掉的 mutant** —— 即杀它的不是你推导的定向子集,而是别的测试。单列,说明实际杀手是谁。
3. **跳过 / 未能生成 / 超时的 mutant** —— 单列并计数。**禁止静默丢弃**;静默截断会让报告读起来像「全覆盖」。

报告开头必须写明:总生成 mutant 数 = 被杀 + 存活 + 上述三类之和,**四项相加必须等于总数**,并把这个等式实算贴出来。

## 硬约束(本单特有,极重要)

- **独立 worktree,跑批期间不许 commit**。变异跑批期间工作树处于被改坏的状态,
  此窗口任何 `git commit -a` / `git add -A` 都会把 mutant 提进去。
  正确顺序:**先把工具代码 commit 完 → 再跑批 → 跑完确认 `git status` 干净 → 最后 commit 报告**。
- **跑批前后各跑一次 `git status -sb` 并把输出贴进交付说明**,证明还原干净。
- 若跑批中断,**必须先 `git checkout -- lib/` 还原再做任何事**。

## 范围围栏(机器可判)

- 允许改动:`tools/mutation/**` 新建 + `docs/audit/mutation_probe_round1_20260826.md` 新建
- `lib/` 最终改动数必须为 **0**(跑批是临时改,收工必须还原)
- `test/` 最终改动数必须为 **0**
- `data/` 改动数必须为 **0**

## 禁止的修法

- ❌ **禁止为了提高分数去改测试或改生产代码**。本单只测量,不修复。发现的存活 mutant 是**下一批的输入**,不是本单的活。
- ❌ 禁止把「这个 mutant 在语义上等价所以杀不掉」当成被杀。等价变异体归入**存活**,并在备注里标「疑似等价」。
- ❌ 禁止用 `| tail` 截断测试输出后判定 —— 会丢失失败详情。
- ❌ 禁止自行 `brew install` / `pub global activate` 任何东西。需要新依赖 → 停 `[BLOCKED]` 说明需要什么。

## [BLOCKED] 出口条件

- 需要安装本机没有的工具 → 停 `[BLOCKED]`。
- 定向测试子集的推导规则你无法给出可复现的算法(只能靠猜哪些测试相关)→ 停 `[BLOCKED]`,
  **宁可停也不要用「我觉得相关」跑一轮** —— 推导规则错了整份报告的存活率就是错的。
- 首轮跑批预计超过 5 小时 → 缩小变异算子或采样,**但必须在报告里 `log` 出被砍掉的部分**,禁止静默采样。

## 验收方式(协调者会这么查)

1. `gate.sh <worktree> <base> HEAD` 必须 PASS(本单含 `tools/` 代码,**跑全量**不跳)
2. `git diff --name-only <base>..HEAD | grep -c '^lib/'` 必须为 **0**
3. 抽取报告里 3 个「存活」mutant,协调者**手工复现**:照它说的改那一行,跑它说的定向命令,确认确实不红
4. 抽取 2 个「被杀」mutant 同样复现,确认确实红,且红的原因不是编译失败
5. 核对报告开头那条四项相加等式是否成立
