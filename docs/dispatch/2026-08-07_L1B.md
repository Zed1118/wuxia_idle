## 三、批量替换的避坑写法(重要)

1. **不要用 `sed -i`**。macOS 的 BSD sed 语义不同且 UTF-8 不稳。**统一 `perl -CSD -i -pe`**(`-CSD` 强制 UTF-8,不加会把中文变 `?`)。
2. **分隔符用 `{}`**:`s{旧}{新}g`。路径含 `/`、md 表格含 `|`,都不能当分隔符。
3. **pattern 用 `\Q...\E` 包住**,否则 `.` 匹配任意字符。
4. **长路径优先排序**:`lib/ui/` 是 `lib/ui/theme/` 的前缀,短规则会吃掉长规则该管的内容。
5. **所有规则一次性 apply,禁止多轮迭代跑**——多轮可能震荡(A→B 的规则和 B→A 的规则互相打架)。
6. **不要 `awk -F'|'` 解析表格列再拼回**,会吃掉行内合法的 `a|b`。对整行做替换。
7. **幂等**:替换类天然幂等(新路径不含旧模式);加标注类必须先 `grep -qF '(已移除)'` 判重,防止插两次。

## 四、验收标准

1. 三类分别给处置计数(A 修了几条 / B 替了几条 / C 标注几条 / D 记录几条不动)
2. **新路径存在性自检**:B 类替换出的每个新路径逐个 `ls` 验证,把命令输出贴进报告。**这是本单最关键的验收项**——替成一个同样不存在的路径比不替更糟
3. **越界自检**:`git diff --name-only` 必须全部落在 `docs/spec/` 下,贴进报告
4. **幂等自检**:标注类 grep 计数,确认没有任何文件被插两次
5. 报告落盘 `docs/dispatch/reports/2026-08-07_L1B_doc_links_s2.md`
6. 分支 tip commit message 以 `[READY]` 开头,工作区干净
