## 〇、这单在解决什么

本仓 2026-05 做过大重构(`lib/ui/` `lib/providers/` `lib/services/` 整目录搬迁)。历史交接文档里大量引用旧路径——**那些引用是对的**(记录的是当时的真实结构),不该改。但读者 grep 到这些文件时会困惑:"这文件为什么不存在?"

**处置 = 不改路径,只在文件头插一行档头**,告诉读者"这是历史快照,路径对照表在哪"。

> ⚠ **绝对不要做路径替换。**上一分片(L1-A)已经把该改的现役文档改完了。本单**一个字符的路径都不许改**,只插档头行。

## 三、三种档头(按文件类型选,别用错)

### 变体 B · 计划态文档(`docs/superpowers/**`,11 个文件)

## 四、插入位置与幂等

**位置**:插在文件的**一级标题(`# xxx`)之后**,空一行。如果文件没有一级标题,插在文件最开头。

插入后的样子:
```markdown
# 某某交接文档 2026-05-16

> 📌 历史快照 · 本文路径按撰写当时的目录结构保留未改;…

(原有正文…)
```

**幂等(硬要求)**:插入前必须先判重,已经有档头的跳过。判重锚点:文件内是否已含 `PATH_MIGRATION_MAP.md` 这个字符串。

```bash
grep -qF 'PATH_MIGRATION_MAP.md' "$f" && continue   # 已插过,跳过
```

**重复跑本单必须是安全的** —— 跑两遍不能出现两行档头。

## 五、技术避坑

1. **不要用 `sed -i`**。macOS BSD sed 语义不同且 UTF-8 不稳。用 `perl -CSD -i` 或 Python(`io.open(..., encoding='utf-8')`)。
2. 档头含中文、emoji、反引号、`·` 等多字节字符——**确保工具以 UTF-8 读写**,否则会写出乱码。写完随机抽 3 个文件 `head -5` 目检确认中文正常。
3. 档头里的 `` `docs/PATH_MIGRATION_MAP.md` `` 是**活链**(该文件真实存在),不要写错文件名。

## 六、验收标准

1. **覆盖率**:`grep -rlF 'PATH_MIGRATION_MAP.md' --include='*.md' docs/handoff docs/superpowers docs/sessions | wc -l` = 63(贴命令输出)
2. **幂等**:`grep -rcF 'PATH_MIGRATION_MAP.md' --include='*.md' docs/handoff docs/superpowers docs/sessions | grep -v ':0$' | grep -v ':1$'` 必须为**空**(没有任何文件被插 2 次)
3. **变体分配正确**:分别 grep 三种档头的首字符(`🔒` / `📋` / `📌`)计数,应为 10 / 11 / 42(合计 63);若与此不符,说明你的判定规则有偏,报告里说明
4. **零路径改动(最关键)**:
   ```bash
   git diff -U0 | grep '^[-+]' | grep -v '^[-+][-+]' | grep -v 'PATH_MIGRATION_MAP'
   ```
   期望**空**——除档头行外不应有任何增删行。贴输出进报告。
5. **越界自检**:`git diff --name-only` 必须全在 `docs/handoff/` `docs/superpowers/` `docs/sessions/` 下
6. **编码自检**:抽 3 个文件 `head -5`,确认中文与 emoji 正常显示,贴输出
7. 报告落盘 `docs/dispatch/reports/2026-08-07_L1C_doc_headers.md`
8. 分支 tip commit message 以 `[READY]` 开头,工作区干净

> **注意**:本单**不会降低死链计数**(档头不删除任何旧路径引用)。验收判据是覆盖率与幂等,**不要**用"死链数下降"当验收依据。
